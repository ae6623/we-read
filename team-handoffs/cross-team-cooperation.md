# 给另一支 Cue 团队协调者：新增协作约定

这是一份给未来接入者的规则补充，不是今日阅读日报，也不代表你已经接手任何书。两支团队可以同时保留，但必须共用一套书目事实，不能各读各的登记册。

## 先确认“你是哪一队”

请先与雨和另一队确认公开、稳定、唯一的团队别名。对外写 `团队别名/角色别名`，不靠显示名区分两个同名管理员或阅读员。此处尚未指定真实团队别名，不把示例当作已登记身份。

你所在账号的 canonical Agent UID 只在你自己的账号内部用于配置和联系；由你私下维护它与公开团队／角色别名的映射。另一队维护自己的 UID、工作区与权限。不要复制旧账号 UID、凭据或私人配置，也不要把它们上传仓库。

## 开始工作前，对同一本账

权威仓库是 [ae6623/we-read](https://github.com/ae6623/we-read)，每次都重新获取最新 `main`。先读 [最新决定](../skills/luoyu-reading/references/decisions.md)、[双团队协作规则](../skills/luoyu-reading/references/cross-team-coordination.md) 与 [状态协议](../skills/luoyu-reading/references/reading-state-protocol.md)，再核对该版本 registry、roster 和相关实际日期事件。

同一本书只有一个 owner；按稳定 `book_id` 去重，按 `book_id`、`environment_id`、`resource_ids` 核冲突。不同 Cue 账号不保证资源独立，实际共用的浏览器必须认同一资源键。原 owner、活动锁及暂停状态不因另一队接入而失效；不清楚就先协调，不抢锁、不代释放、不补跑。

两队工作区分开，共享 Git 写入串行。提交前重新读最新 main、revision 和其他团队增量；只有登记进入权威 main 才生效。冲突重新核查，不强推、不整表覆盖。现有 owner／agent_id 等字段不在本次改名；需要新身份键时先完成明确归属、安全交接、兼容检查和所需授权，不能用新别名冒充旧 owner。

## 公开只讲必要进展与计划

每日交接只写必要“今日进展／明日规划”：团队／角色别名、相关书目、已核状态、阻塞、下一安全动作与公开证据。把计划、登记、实际开始、完成、发布、在线核验和通知分开，不把日报当作实时锁或接管许可。

不要放私聊、原始 AI 答复、凭据、内部 UID、私人路径或原始私有记录。需要私人材料时另走已授权私下通道。管理员按团队别名＋角色别名核责任，不按显示名猜是谁。
