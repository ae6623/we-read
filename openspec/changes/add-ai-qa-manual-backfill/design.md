## Context

`weread_ai.py` 的问答能力已验证可用，本变更不改它的抓取与判定逻辑（`ask()` 内的 `has_more=0` 收尾判据是实测调出来的），只加"怎么用"和"怎么补历史"。以下决策均为防止后续实现走偏，逐条附理由。

## Decisions

### D1：入口挂 `weread_daily.py ai-qa` 子命令，不新建独立脚本

控制台现有 `/api/run` 的模式是 `subprocess.Popen([sys.executable, "weread_daily.py", "run"])`，配合 `run_subprocess()` 的超时与隔离。新增子命令可零成本复用这套：进程隔离、日志、`weread.lock` 互斥、`CREATE_NO_WINDOW`。

反例：在 `web_app.py` 进程内直接起 Playwright。浏览器卡住会拖垮整个控制台（`run_subprocess` 的注释已写明这个原则），这是既有教训。

### D2：回补必须按原日期落盘

`save_items(book, date_str, qa)` 的实现是**先删同日期所有条目再写入**（整桶覆盖）。回补 2026-10-19 那篇，必须传 `date="2026-10-19"`。

若图省事用今天日期：问答会塞进今天的页，历史篇仍为空，且同日的旧条目被清空——等于既没补上又制造了新问题。

### D3：同一本书多篇笔记共用一轮问答，不做逐篇提问

一问一答是**全书视角**（"这本书讲了什么""最反直觉的观点"），与具体读到哪一天无关。一本书若有 3 篇笔记，只问一轮，然后把同一组问答分别写入 3 个日期。

代价：`data/ai_qa/<书名>.json` 存储冗余（3 份相同内容）。收益：`items_for_date()` 与 `site_pub` 渲染零改动。

被否决的方案：加 `date="book"` 桶 + 渲染时回落查书级桶。更干净，但要同时改 `items_for_date()`、`save_items()`、`site_pub._publish_book` 三处，且旧数据需要迁移，风险不成比例。

### D4：事后补问必须显式标注

回补的问答是 2026-10-28 生成的，渲染进 2026-10-19 的页面。若不标注，读者会认为那是当天读出来的结论——这与 `overview_gen/README.md` 写明的「来源诚实」要求直接冲突（该文还要求任何 FAIL 都阻断发布）。

实现：`save_items()` 写入时带 `backfill: true` 与 `asked_at`（真实提问时间）；`_render_site_ai()` 在该 section 的 eyebrow 后追加一行：

> 以上问答为事后补问（YYYY-MM-DD），依据全书内容生成，不代表当日阅读进度。

正常场次产出的问答不带此字段，渲染结果与现在完全一致，不影响已有 3 篇。

### D5：关键词黑名单用"整名命中"而非"包含即删"

`NOISE_HEADINGS` 里的词（版权信息、引子、目录…）若按"章节名含该词就删"处理，会误杀正文章节：`版权制度的起源`、`序言的力量`、`插图史`。

判定规则：章节名去空白后，**等于**噪声词，或**以噪声词开头且总长度 ≤ 噪声词长度 + 2**，才算前置页。`版权制度的起源` 长度 7，`版权信息` 长度 4，超出阈值，保留。

再加一层兜底：`add()` 时若生成的问句含黑名单词，且还有通用候选（"最反直觉的观点""反驳论证的切入点"），则丢弃该问句。

### D6：不动 `ask()`

`ask()` 里的三个判据——网络帧 `has_more=0`、正文出现「书籍引源」提前收尾、正文长度连续 20s 不增长兜底——是 2026-10-25/26 反复实测调出来的。本变更只碰问题生成和落盘/渲染两端，中间这段保持零 diff，便于用 `git diff` 证明未回归。

### D7：历史页发布锁在本机

云端发布走 `gh_api.py` 的 Git Data API，策略是"只追加当天 `notes/<date>.html`"，因为云端 `sessions.jsonl` 只含自己跑过的场次，重建整书页面会缩水（实测 overview 42KB → 11.7KB）。

回补要改 19 篇历史页，必须由会话最全的本机发布：`we-read` 仓库在 `fix-publish` 分支，push 用 `git push origin fix-publish:main`；只把本次真正改动的页面加进提交，不整目录扫描 diff。

## Risks / Trade-offs

| 风险 | 缓解 |
|---|---|
| 回补过程消耗 AI 额度（39 问） | `--limit` 分批 + `--skip-existing` 幂等，中断可续 |
| 单本失败导致整批中断 | 单本失败记 `ai_qa_backfill_skip` 后继续 |
| 黑名单漏词（新书有奇怪前置页） | 日志里 `ai_qa_plan` 的 questions 可事后审计；发现新词补进 `NOISE_HEADINGS` |
| 回补把页面其它内容改坏 | 验收要求 `git diff --stat` 只出现增加行，不得有删正文/进度/时长的 `-` 行 |

## Migration

无数据迁移。`data/ai_qa/*.json` 旧条目缺 `backfill` 字段时按 `false` 处理；已有 3 篇笔记页渲染结果不变。
