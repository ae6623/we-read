## Context

三个生成器（`gen_mindmap.py`、`overview_gen/build_overview.py`、`overview_gen/auto.py`）分别在不同时机被调用：

- 云端 `weread_daily.py` 跑阅读场次 → 调 `gen_mindmap` 产精读页、调 `overview_gen.auto` 产通读页
- 本机 `gen_mindmap.py --render-only` / `--import-batch` 从已有 JSON 重渲精读页
- 沙箱 `produce_all.py` 直连网关产四件套

三者共享**同一份**源码（站点仓），但各自硬编码模板文本，导致「改一处漏两处」反复发生。

## Decisions

### D1 用独立模块做单一真源，而不是各文件内的常量

选 `reading_note_spec.py`（仓库根，与 `gen_mindmap.py` 同级）。理由：

- `gen_mindmap.py` 本身就在仓库根，`import reading_note_spec` 零路径配置
- `overview_gen/*` 作为包运行时 cwd 在仓库根，同样可直接 import
- 若放进 `overview_gen/`，`gen_mindmap.py` 反向依赖包里模块，耦合方向别扭

**不做 try/except 静默兜底**。import 失败就让它报错——一旦降级成"用内联默认值"，等于又在文件里存了一份模板，回到两处真源的起点，本次改造就白做。

### D2 章名派生优先级：章名 → 首小节名 → 首要点 → 锚点原句 → `第N章`

与用户口径一致（「可以获取章节下的第一个节点信息作为标题」）。逐级下降保证总有可读文本，最差也有「第N章」而不是裸数字。

### D3 「占位章名」的判定口径

满足任一即视为占位，需要派生：

- 空串 / 纯空白
- 纯序号：`一`、`二`、`第三章`、`第一部`、`12`、`第 3 节`（正则：数字或中文数字 + 可选章节量词）
- 渲染器自身的 fallback 文案：`本节要点`（`gen_mindmap.py:470` 在 `s["h"]` 为空时会输出它，绝不能拿来当章名）

判定 MUST 用**全串匹配**，不能用 `in` 或前缀匹配——否则「第一节 童年的记忆」这类有真实内容的章名会被误判成占位。

### D4 回填幂等：只增不改

回填脚本对每章：仅当 `is_placeholder_title(当前 mmx-name)` 为真才替换。已有人工/上游写入的真章名一律不动。重复执行结果一致，无副作用。

### D5 回填必须做「守恒校验」，否则拒绝上传

2026-11-01 的教训：上一版回填脚本用「按 `<details>` 配对切块 → 逐块 append 拼接」的写法，漏掉了**块与块之间的间隙文本**，`zhui-yi` 单本丢失 6167 字符、`<details>` 开闭失衡（428 open / 429 close），被迫 `revert`（commit `1dea65e4a5`）。

因此本次回填强制三道校验，任一不过即拒绝上传：

1. `<details>` 开标签数 == `</details>` 闭标签数（上传前后都要成立）
2. `<details class="mmx-cn">` 数量不变
3. 新文本长度 >= 原文本长度（派生只会让章名变长，缩短即说明文本被吞）

实现上改用**「按锚点定位、在原文上做等长位置替换」**，不做块切割再拼接——这样结构上不可能丢字符。

### D6 存量处理范围以「线上实际内容」为准，不以计划为准

上一轮曾用计划的章名数量（80 章）去做回填，实际线上基线只有 9 章是纯序号，多出的全是宽松正则的误报。本次一律：先拉线上最新内容 → 用严格判定重新统计 → 只改真正命中的。

## Risks / Trade-offs

| 风险 | 处理 |
|------|------|
| 新增模块导致云端 import 失败、整站生成中断 | 模块只依赖标准库 `re`；提交前在本机做 `python -c "import reading_note_spec"` + 三个生成器的 `py_compile` + 生成器真实 import 验证 |
| 派生出的标题过长撑破折叠行 | `chapter_title` 统一截断 40 字 |
| 回填写坏线上页 | D5 三道校验 + 逐本 sha 直传 + 失败即跳过该本，不影响其余 |
| 首小节名恰好也是占位（如「本节要点」） | 判定链里跳过占位名，继续向下一级下降 |

## Migration Plan

1. 先提交源码（新增模块 + 改三处生成器），云端下一次生成即生效——**这一步做完，问题就不再新增**
2. 再跑存量回填，把已发布页补到与流程一致——**这一步只是还历史欠账**
3. 最后跑新书，验证新流程端到端产物正确

顺序不可颠倒：先修流程再回填，避免回填过程中又有新页按旧模板生成。
