# 设计：私有全文存档放开

## 判据：按目标位置分流，不按可见性分流

旧规则的判断链是「是否把整篇原文复制到新页面 → 禁止」，因此加密码、缩小可见范围都无效。新判断链改为两问：

1. 材料是不是用户本人导出／上传的（本地 PDF、论坛帖等）？
2. 目标是不是用户本人私有笔记或私下归档？

两问都成立 → 允许全文转录与保存。任一不成立 → 沿用原有短引与发布限制。

可见性不再是判据的一部分。密码页既不增加也不减少权限，避免再出现「加密后能否贴全文」这类无效争论。

## 为什么保留公开边界

用户要的是把全文存进自己的笔记，不是对外转载。放开私有归档、保留公开页面限制，正好覆盖需求，且不引入对外发布风险。把整条边界删掉没有收益。

## 为什么三处都改，且各自写全

三份文档被不同流程分别读取：`SKILL.md` 是读书员主规则，`ai-ask-book.md` 是 AI 问书交付检查，`local-reading-guide.md` 是本地 PDF 阅读收尾规范。只改一处，另外两处仍会被 Agent 引用为拒绝依据。每处都独立写清「允许什么、禁止什么、依据日期」，不靠互相引用。

## 为什么不动安全项

`local-reading-guide.md` 原句把「全书文本」和「私有路径、凭据、登录态、私人运行日志」并列禁止。后者与版权无关，是仓库公开可见的硬约束，必须原样保留。改动时把两类拆成两句，只放开前者。

## 生效方式

规则以 `main` 为准。提交并推送后，运行中的 Agent 在下次读取最新 main 时采用；不声称已热更新当前会话，不回改既有内容。
