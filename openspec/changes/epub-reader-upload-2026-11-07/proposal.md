# EPUB 阅读器：Aa 入口归位、上传与异步补笔记（2026-11-07）

## 为什么

用户在同一轮里提了两类问题：一是 Aa 面板的入口形态不对（多了一个悬浮 Aa 方块，明明顶栏 `Aa` 按钮就在下载按钮左边）；二是阅读器只能读预置的 203 本 EPUB，用户自己上传的书进不来，也接不上已有的「上传 → 补笔记」Agent 流程。同时左侧 Tab 文案太长，挤掉了新增「上传」的空间，找书没有快捷搜索。

## 变更内容

- 删除悬浮 `#rdFab`，Aa 面板以顶栏 `#aaBtn` 为唯一入口，面板锚定顶栏下方右侧。
- 新增本机上传服务 `tools/epub-upload-server/`：接收 EPUB、落盘 `reading-notes/epub/uploads/`、维护 `uploads.json`、同源静态托管、按既有共享状态协议入队补笔记。
- 阅读器左侧 Tab 由「章节目录 / 全部书目」改为「目录 / 云端☁️ / 上传 / 🔍」，上传书目与云端书目分清单、互不污染。
- 书架页右上角与侧栏 Tab 行最右各增加一个图书搜索入口，即时过滤书名。
- 阅读器支持 `?src=upload&book=<id>` 读取上传书目。

## 不做的事

- 不改 `epubs.json` 的 203 本云端清单与 `books/*.epub`。
- 不在前端内置 GitHub token，不尝试让静态 Pages 直接写仓库。
- 不新造补书队列；复用 `book-registry.json` 的 `queued` 入队协议与当日交接文件。
- 不启动或冒充其他 Agent 的阅读进程，不宣称笔记已生成、不宣称用户亲读或完读。
- 不改 Aa 面板内部已有功能项、侧栏点击收起逻辑、用户亲读状态与完读计数。

## 影响

- 新增一个需要用户手动启动的本机进程；服务未启动时线上 Pages 仍可正常读云端书目，上传 Tab 明确显示离线与启动命令。
- 上传的 EPUB 会进公开仓库；页面 `noindex` 不构成私有，文档里已写明。
- 服务端默认只本地 commit，不自动 push，避免与多 Agent 串行写 main 冲突。
