# 阅读黑名单：先过滤，再选书与排班

## 唯一名单与优先级

每次从同一权威仓库最新 `main` 读取 [reading-blacklist.json](reading-blacklist.json)。它只管理“哪些书不再自动选读”，不取代 registry 的 owner、认领、活动锁、续读点或完读事实；不要在个人 Skill、排班镜像或记忆里维护另一份名单。

对所有团队、角色与阅读方式生效，包括AI读书、轻游记、独立时长阅读、本地 PDF、浏览器、代码及人工流程。管理员在推荐候选、选书、派活、安排书目之前过滤；阅读员在选取、认领、默认续读和实际开读前再次过滤。不得用换平台、文件名、版本、角色、书架重复加入或“当前书默认续读”绕过。仅允许在用户既有授权队列中选择。

命中后直接排除，转向下一本合格候选，**不再逐次询问是否读黑名单书**。用户指定优先、最近加入顺序、本人未完书优先和第一章阅读规则，都只对通过过滤的书适用；不为筛选或试读打开禁读书正文或书内 AI。旧指定、旧排班、旧认领不解除黑名单；只有用户明确解除／修改禁读决定或明确批准本书的一次例外才可另行处理，一次例外不自动删除长期规则。用户仅再次提及书名不视为解禁。

## 两层过滤，避免扩大禁读范围

1. **具体书目**：稳定 `book_id` 优先，再核对已登记的平台 ID、完整题名／别名和作者。同一本书换文件名、平台或重复入队仍排除。题名按 Unicode NFKC、大小写、空白和标点归一，不靠模糊相似度扩展书单；题名相同而作者不同先核实，不自行断定同书。
2. **主题规则**：按名单的 `scope`／`not_scope`，用题名、作者、官方简介、官方目录或已获授权的书目元数据判断主旨。职业选择、职业规划与发展、求职和职场策略等主题自动排除；不因一般金融、历史、旅行、文学中提及工作或城市就拉黑整书。题名关键词只是复核信号，不是无限扩大的永久书目名单。

分类由负责选书的 Agent 自主完成，不把每本候选再交给用户决定。元数据不足或存在歧义时，先用获准的非正文书目信息核实；仍不能确认就暂不自动选该候选，转下一本，不擅自加入永久黑名单。没有合格候选才简报原因，不因凑场次恢复暂停书或打开禁读书。

## 持久维护，不把跳过当永久不读

用户明确“这本以后不读／加入黑名单”时登记具体书目；明确“这类都不读”时登记受限主题规则。保存最少识别信息、简短理由及 `basis: user_explicit`，变更加 `revision`、更新日期，按共享 Git 规则检查后进入 main。只记决定，不复制私聊。自动分类命中既有主题规则无需逐书询问，也不必逐书追加永久条目。

单次跳过、候选未选中、暂停、受阻、暂时打不开、已完读，不自动等于永久黑名单。#76 与 #129 未获永久禁读决定，本次不加入名单，也不据此自动开读。只有用户明确改变偏好才改名单，不因重启、重排、换阅读员或解锁而清空。

本次登记职业主题禁读及具体书 `local-zhi-ye-gui-hua-niao-shu`。其现有 `paused`、owner／held、续读点及历史事实原样保留；黑名单生效不代表删除书、改成完读或回改阅读记录。已有活动场次命中新禁读决定时，不再继续正文；由原责任人按协议安全收尾，不由协调者抢锁或替人改记录。

## 可复用只读过滤器

从本 Skill 目录运行：

```bash
python3 scripts/filter-reading-candidates.py
python3 scripts/filter-reading-candidates.py --book-id local-zhi-ye-gui-hua-niao-shu
python3 scripts/filter-reading-candidates.py --candidates /absolute/path/candidates.json
python3 -m unittest discover -s scripts -p 'test_reading_blacklist.py'
```

候选输入可以是 JSON 数组，或带 `books` 数组的对象。工具不联网、不读正文、不改源文件；默认仅扫描 registry 书目，不修改其状态。批量输出 `excluded`、`needs_review`、`not_blacklisted` 三组，保留各组内原顺序及候选原信息，不重新排序书架。

具体 ID／已登记平台 ID／同书题名命中即 `excluded`；候选 `topics` 命中已批准主题，或有依据的主题判断为真，也排除。为避免用“没匹配关键词”冒充“确认不属禁读主题”，每个主题规则都须由选书 Agent 提供 `topic_assessments` 的布尔判断与非空 `evidence` 才可能进入 `not_blacklisted`。例如（仅为空白结构示例，依据须现场核实）：

```json
{
  "book_id": "<候选稳定ID>",
  "title": "<完整题名>",
  "topics": [],
  "topic_assessments": {
    "career-related": {
      "matches": false,
      "evidence": "<已核实的题名／官方简介／目录依据及简短判断；不放正文>"
    }
  }
}
```

判断为真则 `matches: true`。不伪造分类依据；临时候选分类保存在获授权的本地元数据中，不为接入工具改他人 registry／个人记录。默认 registry 未携带主题判断时，大部分书输出 `needs_review` 是预期行为，不是把它们永久拉黑。工具不自行理解题材，分类真实性仍由选书 Agent 负责；不得盲用旧分类或以脚本无异常替代语义核查。

`not_blacklisted` **只表示通过黑名单**，不表示可阅读、可续读、已获认领或已有排班；之后仍须检查暂停／受阻、完读、owner、活动资源、时窗和本场授权。批量返回码 0 只表示成功输出分组；不得把全部候选当放行。指定 `--book-id` 时，不可自动选返回 2；配置缺失／无效、输入无效、指定 ID 不存在／重复返回 1，均禁止默认放行。配置错误先报告并修复，不退回旧副本。

共享规则进入 main 后，下次获取最新 main 的各角色按此执行；这不证明正在运行的会话已热更新、独立实现已接入或其他团队已收到通知。本次不改实际定时任务、个人排班、registry、roster、owner、活动锁或旧笔记，不启动阅读。
