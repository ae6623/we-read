# 阅读归档 UI 规范

把阅读站点设计成「先看结构，再按需展开」的手机优先归档。本文是归档界面的唯一规范入口，约束文章呈现、页面布局和共享组件；不定义角色名称、权限、排班、任务分发或书目归属，不替代来源标注与阅读状态协议。

## 一、统一文章呈现

- 每篇只设一个 `h1`，写明书名与文章类型；日期笔记同时展示实际日期。按 `h2`、`h3` 组织内容，不跳级，不用加粗段落冒充标题。
- 文章开头依次呈现：返回与归档导航、标题、来源／阅读员／实际阅读范围、简短核心理解，再进入正文。用自然段和有意义的小标题拆分长文，避免一屏只有元数据或连续大段说明。
- 让「亲读」「公开资料」「综合推断」「部分阅读／未完读」等边界在折叠前就可见，不把关键限定仅藏在抽屉中。保留既有事实与历史口径，不为统一样式改写观点、实际时长、阅读进度或完读状态。
- 正文默认约 16px、行高 1.7–1.8，文章容器建议 760–900px；长题名、中文、英文和 URL 自然换行。不要固定正文高度、遮盖溢出或用省略号截掉关键限定。
- 把短来源说明贴近对应论点，完整来源集中在文末；正常保留来源链接、上下篇和返回入口，不把正文所有链接都收进抽屉。
- 章节导航沿用 [章节导读样式](chapter-guide-style.md) 的层级、导读与状态语义。入口编号只表示列表顺序，不能当作官方章节号、册序或阅读进度。

## 二、统一页面布局

首页负责发现与分类，按书归档负责回看，系列页负责主题与单书入口，文章页负责连续阅读。保留这几种页面的不同用途，但共用颜色、间距、按钮触点和入口组件。

1. 页面顺序采用「导航 → 标题与简短说明 → 分类／搜索（需要时） → 内容分组 → 返回入口」。首页分类页签保持原功能，不改造成编号抽屉。
2. 书目卡片依次显示状态、书名、必要归属与范围、简短简介、阅读入口。标题及关键状态始终可见；只折叠附属入口，不折叠整张卡片。
3. 手机默认单列；较宽屏允许多列，但必须使用 `minmax(0,1fr)` 或等效自适应布局。保持卡片内容自然撑高，不用固定高度迫使文字挤压。
4. 页面左右留白建议手机 18–24px，卡片内边距 16–22px；常用间距使用 8／12／16／24／32px，避免每页各写一套随机数值。
5. 沿用站点 `--paper`、`--card`、`--ink`、`--muted`、`--green`、`--gold`、`--line`、`--sage` 及字体变量。纸色背景、墨绿标题、浅绿辅助区域、赭金强调，不再添加独立风格。
6. 搜索、筛选、分类页签和抽屉互不替代：搜索应能找到折叠中的入口文字；打开页面不自动展开全部抽屉，也不为新增组件重置既有筛选行为。

## 三、统一编号阅读入口抽屉

### 适用范围

首页和按书归档的书目卡片、系列页的单书卡片，以及全书视角／旧书页中的「相关日期笔记」，统一使用同款抽屉。单入口也保持同款结构，后续增加子项不需要换布局。

主导航、系列主题索引、分类页签、来源链接、上一篇／下一篇、返回链接、既有章节目录不在此次入口迁移范围，不因含有多个链接就混为一类。

### 标题状态图标与空状态

- 书目标题前用 `.book-reading-state` 表示已确认的阅读状态：`data-reading-status="reading"` 用浅绿底开卷图标，表示「已开始／选读·未完读」；`unstarted` 用无底色、虚线边框的合卷图标，表示「未开始／正文未读」。形状与边框同时区分，不只靠颜色。
- 同组上方只放一次 `.reading-state-legend` 可见文字图例；图标自身带 `role="img"`、准确的 `aria-label` 与 `title`，内部 SVG 使用 `aria-hidden="true"` 和 `focusable="false"`。图标不是按钮，不占用 Tab 顺序；不能只靠悬停才知道状态。
- 状态仅来自已确认的卡片文字／阅读记录；「已开始」不代表当前正在运行，更不代表完整阅读或确认完读。暂停、未知或完读不得硬套成这两类；依据不足保留文字，待独立规范定义其他状态，不凭有链接就推断亲读。
- 无亲读内容的候选卡片保留标题、官方书目链接、简介与稳定 `id`，不再显示重复的无笔记说明，也不显示只有指向自身的「固定入口」的空壳抽屉。无内容的抽屉在呈现上不出现，不保留可点击的「0 项」或空白展开体。
- 已开始且有真实的全书视角／日期笔记等内容时显示编号抽屉；只有一项真实资源也可显示。未亲读却已有明确标注来源的公开导览资源，可按资源事实提供入口，但不能因此改成「已开始亲读」。状态与资源可用性分开判断。

### 结构与行为

引用仓库根目录的 [共享样式](../../../assets/css/book-link-drawer.css)，复用 [组件片段](../../../templates/book-link-drawer.html)。从实际页面计算相对路径；不要照搬模板路径或复制私有 CSS。

```html
<details class="book-link-drawer">
  <summary><span>阅读入口</span><span class="drawer-count">2 项</span></summary>
  <ol class="book-link-list">
    <li><div class="drawer-item"><a href="overview.html">全书视角初版</a></div></li>
    <li><div class="drawer-item"><a href="notes/实际日期.html">实际日期 日期笔记</a><span class="drawer-note">未完读</span></div></li>
  </ol>
</details>
```

以上是结构示例，不直接发布示例目标。只接入真实、已存在且获准展示的文件。

- 用原生 `details / summary`，默认不带 `open`，无需 JavaScript。summary 只负责展开／收起，不放跳转链接；子项才负责导航。
- summary 显示「阅读入口 + N 项 + 状态箭头」；相关日期笔记可用「日期笔记」。N 必须等于直接 `ol > li` 数量。箭头随展开状态变化。
- 展开体用 `ol.book-link-list`，每项一个 `li > .drawer-item`，一个真实链接。用顺序计数生成 1、2、3……；新增项目自动延续编号，不手工写死序号。
- 保留既有链接、锚点、`download` 属性及未完读限定；必要说明置于 `.drawer-note`。迁移不改变原有顺序。新增列表建议「固定导览 → 全书视角 → 日期笔记 → 完读汇编／下载」，日期项保持稳定的时间顺序。
- 只有本卡自锚而没有真实附属资源时，不生成抽屉；卡片 `id` 继续支持外部深链接。删除冗余自链接不等于删除固定锚点，不得连同书目外链或实际笔记链接一起移除。
- 不预建未来日期笔记、完读页或 EPUB，不用占位链接伪装已有内容。不设固定展开高度，不横向平铺，不在抽屉内另加滚动盒；子项增加时随文档自然延展。

### 视觉尺寸

抽屉边框用 `--line`，圆角 12px；summary 高度至少 48px，内边距约 12px 14px。编号列宽 26px，间距 10px，正文列 `minmax(0,1fr)`；窄于 380px 时内边距降为 12px。每个子项链接点击高度至少 44px，长标题自然换行。

## 四、手机优先与可访问性

- 先验证 320px，再验证 390px 与 1280px。抽屉、长题名和元数据不得撑出视口；网页文字放大后仍应自然流动。不要用整页 `overflow-x:hidden` 掩盖组件错误。
- 使用原生语义、有效标题层级、具名导航和有意义的链接文字；避免整页重复的「点击这里」。不为原生 details 手动维护另一套可能失真的 `aria-expanded`。
- 支持 Tab 到 summary，Enter／空格展开和收起，再 Tab 到子项；收起的子项不得仍可聚焦。不要把卡片整体做成可点击父链接再嵌套子链接。
- 给交互元素清晰的 `:focus-visible` 描边，至少 3px，不禁用浏览器焦点。焦点提示不能只在悬停出现，不能被祖先的裁切遮住。
- 用文字同时表达来源、未完读和选中状态，不只依赖颜色。正文、弱化文字和控件以 WCAG AA 对比度为验收目标，不把浅色装饰直接当正文色。
- 保持无 JavaScript 时入口仍可访问。组件不依赖悬停，不强制动画；需要动效的其他组件遵循 `prefers-reduced-motion`。

## 五、验收与维护

在仓库根目录运行：

```text
python3 scripts/check-book-link-drawers.py
git diff --check
```

检查图标与已确认状态一致、可见图例与读屏标签齐全、无内容卡片不生成空抽屉、重复的无笔记说明已去除；保留书目锚点、官方外链及实际资源。检查默认收起、真实项目计数、下载属性、相对路径和锚点；手机／桌面展开后无组件溢出，键盘操作可完成。至少用 50 个子项做一次只在测试页面中的增长验证，不把测试条目提交到站点。

新增同类区块复用组件；新增笔记更新实际列表与真实计数，不再另建 UI 规范副本。文章内容、章节状态、角色权限或排班发生争议时交由各自权威记录处理，不能靠样式推断事实。

本次规范首先随设计分支供审查；本地文件或 Git 提交不表示已安装到所有 Agent，也不表示线上已发布。Skill 的入口链接与权限说明由协调者另行审查接入，不在此文件中重复治理规则。
