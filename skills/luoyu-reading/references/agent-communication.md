# 阅读 Agent 沟通索引

这里是跨 Agent 的持久交接入口，不是实时聊天；事件正文已按年/月/日拆分，**不要再向本索引追加运行或交接记录**。

## 每场先读什么

1. 先获取权威仓库最新 `main`，阅读本索引、最新 `book-registry.json` 与 `agent-roster.json`。
2. 按 **Asia/Shanghai** 的今天日期，仅读取 `agent-communication/YYYY/MM/YYYY-MM-DD.md`；当天文件尚不存在时视为暂无记录，首次写入时创建，不能把缺文件当成任务失败。
3. 只在续接跨日任务、核对未解决交接或追溯证据时，再读相关日期文件；跨午夜先查上一日尚未结束的同一 run。不要例行加载全部历史，也不要根据旧的“进行中”条目推断当前仍运行；活动锁、责任归属及续读点按最新 registry 核对。
4. 详细选书、认领和冲突处理见 [共享状态协议](reading-state-protocol.md)，Git 串行写入和发布边界见 [协作规则](coordination.md)。读书管理员只读汇报，不改记录、不派活；实际阅读 Agent 只维护自己的记录和状态。

## 新记录写到哪里

- 开始、交接、完成、受阻、失败或未能开始时，按事件**实际发生日期**追加到对应日文件文末；跨日的结束事件写结束当天，沿用同一 run ID 并注明开始记录所在日期。补记写事件发生日并明确标明补记时间，不伪造当时已同步。
- 新建日文件时使用 `# YYYY-MM-DD · Agent 沟通记录`，并加入 `[沟通索引](../../../agent-communication.md)` 与 `[本月目录](index.md)`。条目标题沿用 `### [YYYY-MM-DD HH:MM] <Agent> / <run-id>`；记录实际起止、书目、准确状态、必要输出与下一步。完整旧模板按需查 [未注明日期原文](agent-communication/legacy.md#记录格式)。
- 新日期只在当月 `agent-communication/YYYY/MM/index.md` 添加一个相对链接；新月份再更新当年 `YYYY/index.md`，新年份才更新下方年度入口。各层目录只列导航，不复制事件正文；日期倒序排列，不将固定日期冒称“今天”。
- 只追加本人事件，不覆盖、改写或删除其他 Agent 的历史记录；共享写入前后检查 `git status`、`git diff --check`、`git diff --stat`。推送被并发更新拒绝时，先获取最新 main 并核对新增记录，再合并本次增量、重新校验后正常推送；禁止强推。
- 只写适合公开的最少协作元数据，不写凭据、私人聊天、私有原始运行记录、跨书综合或长篇书籍摘录。旧记录仅做位置迁移，不扩展新的公开授权。
- 实际阅读的开始前、结束后仍须在当前 Cue 私聊通知用户；失败/受阻立即直报。Git 记录、提交或监听命中不等于消息已发送，无发送能力时标“待通知”并交接，不能虚填已通知。
