# 阅读 Agent 沟通索引

这里是跨 Agent 的持久交接入口，不是实时聊天；事件正文已按年/月/日拆分，**不要再向本索引追加运行或交接记录**。

跨账号协作先读 [双团队协作规则](cross-team-coordination.md)：新记录明确团队别名＋角色别名，canonical Agent UID 只在各自账号内部使用；每日公开交接只留必要进展／规划，不放私聊、原始 AI 答复或凭据，不回改历史身份。

## 每场先读什么

1. 先获取权威仓库最新 `main`，阅读本索引、最新 `book-registry.json` 与 `agent-roster.json`。
2. 按 **Asia/Shanghai** 的今天日期，仅读取 `agent-communication/YYYY/MM/YYYY-MM-DD.md`；当天文件尚不存在时视为暂无记录，首次写入时创建，不能把缺文件当成任务失败。
3. 只在续接跨日任务、核对未解决交接或追溯证据时，再读相关日期文件；跨午夜先查上一日尚未结束的同一 run。不要例行加载全部历史，也不要根据旧的“进行中”条目推断当前仍运行；活动锁、责任归属及续读点按最新 registry 核对。
4. 先读 [最新决定](decisions.md)：Asia/Shanghai 每日 02:00–06:00 禁读，轻游记与AI读书共用浏览器按整点／半点错峰、不重叠、不补跑；时长专员独立浏览器不误计为共享资源占用。资源别名与实际环境隔离须依状态协议核实，不能只换名绕锁。Windows 在自己的云端以本地 PDF 自主管理，按状态协议分锁，可与不同书且资源独立的浏览器场次并行；不能仅因全队有 running 镜像就判冲突。旧锁安全收尾、所有相关写入端确认接入之前不启用并行，不沿用旧全局锁或旧双场规则。
5. 详细选书、认领和冲突处理见 [共享状态协议](reading-state-protocol.md)，Git 串行写入和发布边界见 [协作规则](coordination.md)。管理员／协调者负责整体排班、任务分发与共享页面设计，不读正文；不改其他 Agent 的个人记录、续读点、个人排班镜像或阅读历史。书目归属以 registry 为准，实际阅读 Agent 只维护自己的记录、状态和 roster 排班镜像；计划与约20分钟目标均不得当作实际事件汇报。共享文章／页面／组件设计前先读 [唯一 UI 规范入口](archive-ui.md)。

## 新记录写到哪里

- 开始、交接、完成、受阻、失败或未能开始时，按事件**实际发生日期**追加到对应日文件文末；跨日的结束事件写结束当天，沿用同一 run ID 并注明开始记录所在日期。补记写事件发生日并明确标明补记时间，不伪造当时已同步。
- 新建日文件时使用 `# YYYY-MM-DD · Agent 沟通记录`，并加入 `[沟通索引](../../../agent-communication.md)` 与 `[本月目录](index.md)`。条目标题沿用 `### [YYYY-MM-DD HH:MM] <Agent> / <run-id>`；记录实际起止、书目、准确状态、必要输出与下一步；新格式开始事件另留 environment_id、reading_mode 和 resource_ids 的非私密别名，与 registry 的同一 run_id 交叉核对。完整旧模板按需查 [未注明日期原文](agent-communication/legacy.md#记录格式)。
- 新日期只在当月 `agent-communication/YYYY/MM/index.md` 添加一个相对链接；新月份再更新当年 `YYYY/index.md`，新年份才更新下方年度入口。各层目录只列导航，不复制事件正文；日期倒序排列，不将固定日期冒称“今天”。
- 只追加本人事件，不覆盖、改写或删除其他 Agent 的历史记录；共享写入前后检查 `git status`、`git diff --check`、`git diff --stat`。推送被并发更新拒绝时，先获取最新 main 并核对新增记录，再合并本次增量、重新校验后正常推送；禁止强推。
- 只写适合公开的最少协作元数据，不写凭据、私人聊天、私有原始运行记录、跨书综合或长篇书籍摘录。旧记录仅做位置迁移，不扩展新的公开授权。
- 实际阅读的开始前、结束后仍须在当前 Cue 私聊通知用户；失败/受阻立即直报。Git 记录、提交或监听命中不等于消息已发送，无发送能力时标“待通知”并交接，不能虚填已通知。
