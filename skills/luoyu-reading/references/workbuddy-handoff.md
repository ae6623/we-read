# WorkBuddy 阅读接手：先自检，再续接

当用户要求 WorkBuddy 接手，或当前 Agent 因用量不足、连接中断等无法继续时，先读本文件。它是可复用沟通规范，不是某本书的现场交接；安装本 Skill 或收到模板不等于取得阅读、转交或发布授权。管理员接手统筹时使用独立的 `reading-admin` Skill；管理员仍不读正文。

## 交出前：留下可核验的最小包

1. 能安全收尾时，保存已有成果和真实停止事实，不为凑完读继续操作。突然失联则由接手者先做只读核查；不要把“未收到结束消息”写成任务已停止。
2. 私下填好下方模板，分清已完成、未完成、不确定与下一步；为结论给出可访问的文件、提交或记录定位。不附私人聊天摘录、凭据、原始场次全文或模型内部分析。
3. 已获授权的公开成稿、待提交补丁与私有草稿分开列位置。私有材料留在仓库外权限受控位置，只向有权访问的接手者私下提供必要定位；无访问权就标待提供，不复制进 Git。
4. 交接不自动结束活动锁、不自动改变 owner、不创建额外阅读场次。无法完成收尾或通知的部分明确标“未完成／待通知”。公开沟通日文件只留获准的最少协作元数据，不提交填好的私有交接包。

## 接入后：逐项自检，缺一项就停在对应边界

- [ ] 确认用户明确授权的接手人、任务、书目、阅读／整理／发布范围及限制；只读核查与继续阅读分开。缺少授权则回报请求，不凭旧会话或管理员派活扩大权限。
- [ ] 在本环境定位获授权的同一权威仓库，获取最新 `main` 并记完整 commit；无法获取就标“最新状态未核验”，不得用安装副本、本地旧分支或旧交接包裁定实时状态。不回退 main，不重建他人工作树。
- [ ] 读取该 commit 的 [最新决定](decisions.md)、[状态协议](reading-state-protocol.md)、[协作规则](coordination.md)、[沟通索引](agent-communication.md) 与 Asia/Shanghai 当日日文件；只按需追溯未结事件。实际路径以权威仓库内本 Skill 目录为准，不假设本机安装位置即权威记录。
- [ ] 对照官方书目核实 `book_id`、平台 ID、书名、作者、版本／译者。最新 `book-registry.json` 才是 owner、claim、active_sessions（兼容旧 active_session）、resume_point 和 completion 的权威；`agent-roster.json` 仅登记身份、实现类型、排班及个人状态镜像。旧稿、网页或完成文件的存在不证明完读。
- [ ] 核清 active_sessions 全集及兼容旧锁，按同书、同 environment_id 或 resource_ids 相交核冲突；不同书且环境／资源独立不阻塞，共享阅读器仍独占。开始／结束证据核对 main 上携同一 `run_id` 的 `reading-state:` 提交、registry 与实际日期日文件；不以排班、日志或 roster 单独断言运行。冲突、残留锁或旧任务是否已停不明就阻塞，不按超时抢占、不代清他人锁。
- [ ] 转交须用户明确授权，且原 owner 依协议释放并确认无运行，新责任人再按串行协议认领；认领／活动登记进入权威 main，且浏览器场次满足最新协议要求的管理员转达后（Windows 独立本地 PDF 自主管理，不套此门槛），才继续阅读。原 owner 失联且无法完成释放时，报告待用户和责任方核定的恢复事项，不冒充旧 owner、不擅改其记录。
- [ ] 在实际操作环境分别核对平台登录、目录／AI入口、Skill 及依赖是否可用、Git 身份与读写权限、公开范围和通知通道。**会话、浏览器登录、Skill 安装、Git 权限、活动锁和用户授权均不自动继承**；已有只读权限或别处成功写入不证明这里能写。
- [ ] 权限不足时，只回传经脱敏且在授权范围内的补丁及基线，由有既有获批通道的责任方审查提交；不传令牌、Cookie、密码、验证码或任何秘密，不借其他 Agent 凭据、不绕过验证或权限。锁登记未进入 main 时不能先读后补。
- [ ] 比较最新 main 与交接包，确认哪些成果已合入、哪些仍是本地草稿；只续未完部分。同一场重试沿用原 `run_id`，不重复计数、重发完成或重读；未能核实的发布／通知状态保持未知。恢复后重新核查最新规则，不自动恢复暂停任务或补跑漏场。

## 内容验收：交付理解，不交付流水账

公开读书笔记和归档卡先让人知道书讲什么、为什么值得读，再给有判断与证据链的实质分析及可精读的输入。长书 AI 笔记按官方目录逐章问答是输入要求，不能跳章或用一行导览代替；公开输出按“论证主线 → 章节分析 → 跨章综合与可精读问题”组织，各章按实际内容选择角度，不机械套表、不按场次或提问顺序排版。具体流程及完成条件读 [AI 问书规范](ai-ask-book.md)。

去掉场次时间流水账、浏览窗口、页数、后台续读点和重复的无用进度／流程免责声明；必要来源、事实缺口、亲读／AI状态及其范围仍须清楚。AI覆盖不冒充亲读状态或实读时长。后台证据按协议私存或保留最少共享元数据，不因前台去冗余而删除事实。不回改旧页阅读事实，不借接手重写他人历史。

## 可复制交接模板（填好后仅经获授权私下通道传递）

未知填“待确认”，不填推测；不得把真实私有路径或填好的交接包提交 Git。只填写任务相关项。

```text
请 WorkBuddy 接手【统筹／阅读／整理／补丁审查】；先只读自检，不直接续读。

任务目标与验收：〈期望成果；何时算完成〉
用户授权：〈明确授权事项与确认时间／可核验决定定位；不粘贴聊天〉
授权边界：〈可读书目、可写文件、可否提交／发布、明确禁止事项〉
交出方／预期接手人／角色：〈身份；管理员不读正文〉
中断原因与当前是否仍可能运行：〈已停证据／待确认；不要凭失联推断〉

权威仓库与最新 main：〈获授权仓库标识；完整 commit；核验时间与时区〉
规则定位：〈最新 decisions；状态协议；协调规则；平台规则〉
关键权威记录：〈registry 路径与 revision；相关事件提交；当日日文件条目〉
书目：〈book_id／平台ID；书名；作者；版本／译者；待确认项〉
责任与锁：〈owner_agent_id；claim.state；active_sessions 各项的 run_id／agent_id／environment_id／resource_ids 与兼容旧锁 active_session；核验依据〉
转交门槛：〈用户确认；旧 owner 释放与任务停止证据；新认领是否已进 main；浏览器管理员转达状态／本地 PDF 不适用〉

已完成：〈事项 → 证据／产物位置；是否已进 main〉
未完成：〈事项 → 仍缺什么〉
不确定：〈矛盾／未知 → 最小核查动作；不能当已完成〉
成果位置：〈已获授权公开成稿／本地待提交补丁／私有草稿，分别列；私有定位仅私传〉
内容状态：〈官方章节AI问答实际覆盖与缺章；亲读覆盖另列；综合分析待办；不可冒充完读〉
下一步：〈优先动作1–3；责任人；前置条件；锁不明先停〉

环境与权限自检：〈实际设备／环境；平台登录；Skill与依赖；Git读／写；发布；通知通道，各填已核验／缺少〉
不得做：〈不继承授权／登录／锁；不抢占／代改他人记录；不传秘密；不公开私稿；不回改旧页事实；不绕过权限〉
受阻兜底：〈返回无秘密补丁与基线给谁；待谁核定授权／锁；未登记前不读正文〉
用户回报：〈当前可用联系通道；接手自检后先报结论；完成／受阻时再报；无发送能力标待通知〉
```

### 给用户的简短接手回报

```text
我已核对最新 main〈commit〉及权威记录。已确认〈成果／责任与锁〉；
未完成〈事项〉，仍不确定〈缺口〉。接下来〈动作〉，前置条件是〈授权／解锁／权限〉。
本次〈仅核查／已满足条件可继续／受阻仅交补丁〉；〈产物位置〉。
〈若受阻：需要你决定或补充的最小事项〉。
```

区分“已准备交接”“已自检接手”“已开始”“内容完成”“已合入”“已部署并在线验证”“已通知”；只对有证据的阶段报成功。不要承诺失联时自动唤醒 WorkBuddy、自动安装 Skill 或自动恢复权限；本规范不创建调度或监控。
