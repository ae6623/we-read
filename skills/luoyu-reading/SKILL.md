# 落雨读书

> **所有 Agent 先读这一条**：本 Skill 只约束**协作目标与协议**——产出什么（预读框架/日期笔记/完读汇编）、按什么结构归档、来源如何标注、如何避免互相干扰、发布授权与时间错峰。它**不约束实现方式**：代码自动化、Agent 直接操作浏览器、人工整理都是被认可的手段，各 Agent 用自己擅长的方式达成目标，**互不假设对方的技术栈，互不干扰**。涉及具体平台的操作边界见 `references/platforms/<platform>.md`；代码类 Agent 的自动化实现细节集中在 `references/automation-code-agent.md`，**仅对该类 Agent 自身有约束力**。

**沟通记录按需读取**：先读最新 main 的 [沟通索引](references/agent-communication.md)，再读 Asia/Shanghai 今天对应的 `references/agent-communication/YYYY/MM/YYYY-MM-DD.md`；仅为跨日续接、未解决交接或证据追溯打开相关旧日，不通读全历史。开始、交接、完成或遇阻等新事件按实际发生日期追加日文件，不再追加索引；新日期/月/年的目录维护及跨日补记规则见索引。

为用户把多本书读得更有效：开读即建立有来源边界的全书视角初版，再把每天真实读到的内容连回框架，完读后才做校订后的整书汇编。`references/book-registry.json` 是书目归属/认领、完读、`active_sessions`（兼容旧锁 `active_session`） 与 `resume_point` 的权威来源；`references/agent-roster.json` 只登记身份、类型、排班及个人状态镜像，不作为书目或完读事实的唯一来源。共享归档与 Git 规则见 `references/coordination.md`，跨 Agent 开始/结束记录见 `references/agent-communication.md`，用户最新决定见 `references/decisions.md`。使用某个平台前阅读对应的 `references/platforms/<platform>.md`（当前先有微信读书指南）。

## 通读的 AI 问书（2026-10-21 用户决定）

读书员【通读】建立或实质更新一本书的全书全貌时，必须按 [AI 问书规范](references/ai-ask-book.md) 在 `overview.html` 加入固定「AI 问书」章节，依次回答 **书籍亮点、背景解读、关键概念、10个最佳金句语录**；按适用流程完成AI章节笔记与「读后思考」后，可按用户授权记为「AI阅读完读」，再整理 `final.html` 与 EPUB。微信读书须实际打开本书 AI 对话，一次输入并提交 `书籍亮点+背景解读+关键概念+10个最佳金句语录`，不再要求逐个点击固定按钮；按实际返回逐项整理。其他平台／Windows 本地 PDF 无平台 AI 时也须按相同四项用已核实材料自主整理，明确标「AI 自主整理 · 非微信读书返回」。逐项标来源、获取／整理时间与核验状态；未取得如实待补，不伪称平台返回。金句只取可访问、可逐字核验且属于真实亲读范围的短原文，能核对几条就写几条，不凑十条、不从未读文本补引文，遵守全页累计版权短引限制。AI内容不冒充亲读范围或时长；完读证据须标明AI路径。此项适用于后续全书视角，不要求每场日期笔记重做；不改变排班、认领与他人记录。

## AI 大纲：读前通读的第一素材（2026-10-26 用户决定）

**阅读端官方 AI 大纲是「通读」这一层最好的素材**，它按「章 → 小节 → 要点 → 原句」四层梳理全书，读一遍就知道全书骨架，精读时也能立刻定位本场落在全书的哪一段。因此：开读一本新书即取一次大纲，落到 `reading-notes/books/<slug>/` 下四个产物——`outline.html`（每章可折叠，原句单独成行）、`outline.epub`（可下载到阅读器）、`outline.md`、`outline.json`；已有大纲的书不重复抓。

**入口必须三处齐备，缺一处就等于没有**：

1. **通读页（overview）顶部**：`读前通读 · AI 大纲` 一节，写明章数／条数、四层结构、打开大纲与下载 EPUB 的链接。
2. **每篇精读笔记（notes）顶部**：`读前通读` 条，回指本书 AI 大纲与全书视角——精读的人要能一步回到通读。
3. **首页通读卡片**：卡片顶部加「AI 大纲」标签，操作区给一条「读前通读 · AI 大纲」链接（与「打开 HTML」区分开，不能混在抽屉里让人找不到）。

**边界**：AI 大纲是机器梳理，**不等同于已亲读**，只作位置参照；日期笔记的正文仍以当天实读原文为准，全书判断完读后在 `final.html` 校订。给模型做坐标使用时必须显式标注「非亲读」。

**对外文案口径**：站点上（大纲页、通读页、精读页、首页卡片、EPUB 元数据）一律写 **「AI 读书」**，不出现阅读平台品牌名；EPUB 的 `dc:creator` 同理。代码注释与内部日志不受此限。

实现（weread-auto）：`weread_outline.py` 取大纲并渲染页面／EPUB；`site_pub.inject_outline_entries(book_dir)` 幂等注入上面 1、2 两处（用 `<!-- outline-entry -->` 标记包裹，重复执行只替换不叠加，大纲被移除时清理死链）；`site_pub.refresh_outline_cards(repo)` 负责第 3 处——首页索引是保守的（已有卡片不重写），所以补链／升级文案单独走这一步。手动补跑：`python tools/build_outline_assets.py 书名 [--id bookId] [--push]`。

## AI辅助章节导览与读后笔记流程

仅在用户授权的AI阅读任务中，对具备本书AI问答的阅读Agent采用，按 [AI问书规范](references/ai-ask-book.md) 的篇幅分档，形成章节分析及综合「读后思考」。小篇幅和长书均按官方目录逐章AI问答；长书不能用选章问答或一行导览替代全章输入，实际亲读仍按既有授权与第一章规则执行。公开输出按论证主线、章节分析、跨章综合与可精读问题组织，依内容灵活选角度，不机械套模板、不按场次排版。微信读书书内AI问答仍须通过浏览器完成；可对具体缺口多轮追问，逐题等待完整答复，不机械重复同一句问题，并遵守平台验证／反自动化停止规则。按适用流程完成规定章节笔记及「读后思考」即可构成AI阅读完读，completion中标明AI完成依据，不冒称亲读；AI问答不计亲读时长或章节状态。Windows本地PDF仅按获授权材料流程执行，不假称平台AI来源。

## 共享书目认领、精确续读与三本综合

- 先认领再开读，用户指定书优先但不得抢占活动认领；未完书跨场次保留责任，确认完读后释放。所有共享写入按协议串行接受到 main 后才生效，不以本地或 PR 分支的拟认领冒充成功。
- GitHub 授权按执行环境区分：Agent 主会话、协调者会话、浏览器子任务和 Connector/API 可能各有不同登录与权限。必须在实际写入环境检查；一个环境的 `gh auth status`、仓库只读权限或历史成功不能证明另一个环境能写。若浏览器子任务无写权限而责任 Agent 主会话有其自身获批通道，按 `references/coordination.md` 使用无凭据两段式交接；禁止传递任何 Agent 的凭据。授权／写入受阻要及时报告，不让等待占满阅读窗口。
- 每场结束按 `templates/session-close.json` 在私有归档记录精确且有依据的下一章节/帖子/小节标题及其内部位置（页码仅可作内部辅助），以及一个基于已读内容的下次问题；未知写 `needs-confirmation`，不把百分比猜成页码。同书同日仍合并一篇，但保留每场区段。

- 没有正式章节的作品使用实际帖子、文章或小节标题；只有原文确有编号时才保留编号。标题无法确认时直说“标题待确认”，用已核实内容简述实际覆盖与停止处，不能编造标题、章节、编号或其他定位标记。自拟分析小标题须与原文标题明确区分。
- 同一章节未读完时，注明只读到哪个实际小节或内容段落，不把接触一个章节写成读完一章；保留来源标签、实际时长和未完读说明。
- 旧书及其既有笔记、已发布内容、先前阅读记录和历史页码保持原样，不批量回改。本决定仅替代今后输出的页码展示口径，不改实际阅读数据、内部续读兼容字段或各 Agent 的实现。

### 长书务实推进：抓主线，允许略读与跳过（2026-10-19 用户决定）

- **每本书第一章都不能跳过（2026-10-19 用户补充）**：第一章建立开篇与全书语境，所有书均须先实际阅读第一章；长书按兴趣选章、少量试读也必须纳入第一章，不能直接从后面的精彩章节起读。第一章低收益时可高效略读，但不得标为“跳过”；按事实注明精读／略读、实际覆盖的小节或段落与停止处，未读部分仍标未读，不把部分接触或略读冒充整章完整读完。本条不要求其后每章都完整阅读，后续章节仍按兴趣与收益选择性精读、略读或跳过。
- 按篇幅与兴趣分配精力：短书（如《挪威极夜》这类体量）且兴趣匹配时尽量读完；长书先沿可核实目录挑有意思、叙事强的部分精读，叙事弱、啰嗦或低收益部分可略读并一笔带过。选择性覆盖不等于跳过整本书；但仍须如实注明哪些精读、略读、跳过或未读，不能冒称完整读完，也不因此更改完读确认标准。本条仅指导未来阅读，不重开或回改已完读短书。
- **系列／同一作者成套分册照此办（2026-10-19 用户补充）**：同一系列（如「轻游记」这类几十册的成套小书）或同一作者的成套分册，不必每册逐字通读，太慢。按册挑与个人兴趣和系列主线相关的册目读，每册只抓它独有的材料、人物与结论，系列内反复出现的背景交代、同类抒情与重复铺陈可略读或跳过；同一册内部仍按篇幅档位推进。系列内完读按册单独确认，读完一册不推论整系列已读，也不为凑数硬读全套。系列归属、册序只在官方书目可核时标注（如题名带「（轻游记）」），无官方册序就不自造编号。
- **篇幅分档只决定精力与推进速度，不改变如实标注（参考值，可按实际体量浮动）**：短书（约 8 万字以内，如《挪威极夜》《朝圣之路》这类小册）兴趣匹配就尽量一场读完或读完主要部分；中篇（约 8–30 万字）主线章节精读、支线与重复例证略读；长篇（约 30 万字以上）沿可核实目录择章，单场 20 分钟左右以推进一个主题为限，不追求单场翻完。达标标准是能复述主线、回答该书的问题，不是翻到末页或凑够时长；分档与推进速度一律不豁免前面「第一章不可跳过」与「如实区分精读／略读／跳过／未读」。
- 沿原书真实章节／小节结构向前读，不要求逐字逐句；对每个实际阅读或略读的小节，抓住主要问题、作者主张、必要证据与结论，并连回全书主线。尚未掌握的部分注明未确认，不靠目录或外部概括补成亲读。
- 在第一章不可跳过的前提下，自主快速略读或跳过明显重复的铺垫、重复例子、离题支线与低收益细节，不必逐次询问用户；遇到支撑核心主张的关键材料仍要读懂，不能只为赶进度省掉必要论证。
- 在既有“实际覆盖”字段和范围说明中区分完整阅读、选择性略读、跳过与尚未读到的内容：略读写清实际覆盖的标题／段落，跳过明确标“跳过”，必要时简述理由；记录精确停止处及后续位置，不用一个连续范围掩盖中间空缺。选择性阅读不得表述为整章／全书完整读完，也不得仅因到达书末登记完读或增加完读计数。
- 复用章节 `read / reading / unread` 状态，不新增复杂状态体系：含略读或跳过、尚未完整阅读的章仍标“部分阅读”，全未读章保持“未读”；官方目录全部小节与实际已读／停止／未读标记继续按 `references/chapter-guide-style.md` 展示。来源标签“亲读”须同时说明选择性覆盖，不能暗示完整阅读。
- 此授权只改变今后的阅读方法，不回改旧笔记、发布物或历史事件，不改变认领、排班与暂停指令。《大转向：世界如何步入现代》继续暂停，不自动恢复；《王的归程：阿富汗战记（1839～1842）（甲骨文）》是已指定的下一本，本次规则更新不打开该书、不算开读或阅读场次。

### 章节导读：标题下面说明“这一章在做什么”（2026-10-19 用户决定）

- 在后续新输出的章节导航中保留已核实的“部／章／小节”层级；每个实际列出的章节标题下面紧接 1–2 句简短导读，说明这一章讨论什么、要解决什么问题，或在全书中起什么作用。让用户先看结构，再看说明，不只列目录，也不展开成长篇总结；没有正式章节时用真实帖子／文章／小节标题，不编造标题、编号或层级，不以页码导航。
- **全书视角初版**：标题以可核实目录为准，说明依据已核实的目录、官方简介等逐项标注来源。仅凭标题作判断时标“综合推断 · 初步导读，待亲读验证”；依据不足时写“导读待阅读后补充”，标题未确认则明确“标题待确认”，不补造全书目录，不把未读内容写成亲读结论。
- **日期笔记**：只为本篇声明的实际已读章节提供导读；部分阅读须注明“部分阅读”及已确认停止处，说明也仅限已读部分，不能据接触一章概括未读全章。其他未读章节不混入本次实读导航。
- **完读汇编**：确认全书完读后，按实际阅读校订各章导读及其与全书的关系，修正初版推断，保留必要来源标签；HTML 与 EPUB 保持同一口径。
- **呈现样式（2026-10-19 用户决定）**：统一用「卡片分组 + 点击展开」，让人类先浏览结构、需要时再展开。每个部（或无部时的一级分组）一个卡片 `.toc-part`，顶部 `.part-label` 写部名与章号区间；每章一行 `.ch-item`（`<details><summary>`），同行依次是章号 `.ch-no`、标题 `.ch-t`、状态徽标 `.badge`（`data-s="read|reading|unread"`，文案用「整章／部分阅读／亲读／未读」）、折叠箭头 `.caret`；点标题下滑展开 `.ch-body`，正文放 1–2 句导读，底部 `.ch-src` 写「导读依据／来源与依据」。默认折叠，不预展开，不加页码。**全书视角的导航里每一章都必须可展开**：读过的章展开是导读（标亲读／部分阅读）；未读的章展开只放可核信息——出版方目录的小节清单（`ol.ch-secs`），或一句明确标「推断 · 目录导向」的初步阅读问题，并在 `.ch-src` 写明依据是目录标题；不许把未读章留成不可点击的纯文字行，也不许把目录标题包装成内容总结。样式以 `templates/date-note.html` 与 `templates/pre-read-overview.html` 为准，不自造新样式；已发布笔记的同类板块同口径。**标了「部分阅读」的章，展开体必须列出该章官方目录的全部小节并标出读到哪一节**：已读深底、`停在这里` 赭边籤、未读置灰，三段不许混用；`已读 M 节` 必须等于高亮条数，`停在这里` 有且只有一条，未读小节只放官方标题、不写任何概括；**读到后面不反推前面已读**（跳读时前面未确认的按未读列示），只略读的小节籤写「略读」、计数写「已读 M 节（含略读 K 节）」，跳过项理由写 `ch-prog-note` 且不回填成已读。完整结构、配色与生成器接入口径见 `references/chapter-guide-style.md`（小节数据取自 `toc_fetch.py` 产出的 `data/toc-flat.json`，不手抄、不按百分比反推）；站点骨架见 `templates/reading-note.html`。已发布笔记按此口径补清单，但只补结构与进度，不改既有结论。
- 只更新后续输出规则与未来模板；不回写旧笔记、既有发布物或历史阅读记录，不改变其他 Agent 的个人状态、实现方式与隐私边界。

### 新书先看口碑与兴趣匹配，低收益及时止损（2026-10-19 用户决定）

- 在每本新书或合集内独立分册**首次实际阅读前**，快速搜索并打开核对数篇优质／高赞书评；可得时兼顾可信专业评论与读者评论聚合，不只看搜索摘要或单一评分。简短标注来源名称、链接及“公开评论／二手依据”，概括叙事性还是专业技术／工具参考导向、文风与节奏、主要争议或阅读门槛，并结合用户兴趣给出“不值得投入／适合短试／值得继续”等初步判断。查不到可靠评论就注明信息不足，不补造共识。
- 把口碑当选书的二手背景，**不是书籍内容证据，更不是亲读结论**；不长引书评，不从书评生成原文摘录。模板 `pre-read-overview.html` 的可选“读前口碑与兴趣判断”仅承载简短来源与匹配判断，不取代开读后的全书视角初版。
- 若评论提示与用户目标明显不合（如过于专业工具化、味同嚼蜡或大部分材料兴趣低），主动建议／依既有选书授权选择止损，不因沉没成本硬读。评分不是唯一标准，也不得用低分强行跳过用户明确想读的书；口碑分歧而用户要求继续时，先按可核实目录挑少量有代表性、可能有趣的章节试读，再据实际体验判断，不把选读写成整书完读。
- 用户明确说无兴趣或要求停止时，立即停止该书；由责任 Agent 按既有串行协议将本人书目标为 `paused`，保留认领与已确认续读点，不自动恢复、不记完读，然后转向用户已批准队列中下一本合格书目（仍须核对认领、防冲突及读前筛选）。只在 Cue 简报／带日期的私有内部交接留下简短总体评价；**不为被叫停的书另建或发布负面读前笔记**，不改写旧笔记或其他 Agent 的记录。
- 本节是所有后续新书／独立分册的通用挑选方法，**不构成对《王的归程》的止损指令**。它仍为当前持有任务 `king-return-dalrymple`；用户要求从其目录挑几章不错的章节阅读，由独立的实际阅读任务执行。本次仅更新规则与未来模板，不打开阅读器、不开始场次、不改 registry、roster、排班或当前书记录。

## 工作流程

1. **先核配置，再决定读什么。** 先按最新 main 的阅读黑名单过滤本场候选（含默认续读）；禁读书不进入后续选书优先级。 先确认用户指的书、作者和平台；开读前查看最新 `book-registry.json`、`agent-roster.json`、最新交接记录与已有归档，确认本场书目、环境与资源均无冲突，不把其他独立环境中不同书的活动误判为全局阻塞。以 registry 核对书目归属/认领、完读、`active_sessions`（兼容旧锁 `active_session`） 与续读点；roster 仅核对身份、类型、排班及个人状态镜像，镜像不得覆盖或裁定 registry。按协议选择用户指定或应续读的书，绝不重读已确认完读书，除非用户明确要求重读；不确定时先停下并报告，不猜。检查归档索引、全书初版、日期笔记和完读汇编，避免重复创建或覆盖。
   **首次开读门槛：** 新书／独立分册先执行上节口碑与兴趣筛选；决定继续或小样试读才进入实际阅读与初版产出，决定止损则只留简短内部评价，不为凑归档创建公开 overview。
2. **新书开读即产出全书视角初版（overview.html）。** 用户已明确决定：不要只给一张“预读地图”——开读时就应给出一份完整的全书视角。收集可验证的官方书目简介、目录、作者说明、用户提供的材料与可靠公开划线，结合模型自身对该作品的知识，产出全书主旨、结构、关键观点与主题关系；同时按四层来源标签（亲读 / 官方简介目录 / 用户材料 / 公开评论划线 / 综合推断）分清信息出处，并单列“阅读时要验证的问题”。它不是最终总结：未经亲读确认的部分保持推断标记，完读后校订升级为 `final.html`。没有可靠依据时，不装作掌握全书。
3. **每日记下实际阅读并记录运行状态。** 日期笔记写实际范围、关键观点、作者如何展开、与整书框架的联系、理解变化和可迁移启发；同一本书同一天多场阅读合并为一篇，不同书籍分别建笔记；不编未读内容。日期笔记使用 `templates/date-note.html`：标出阅读员名称和 Agent 类型，以章节/帖子/小节标题和实际覆盖范围作为主要导航；指标卡片只突出实际时长、实读章节/标题、覆盖说明及有依据的全书状态，平台有效阅读时长注明计时范围/来源，不设置页码/页数或翻页数量卡片。严格区分浏览窗口时长与平台确认的有效阅读时长；翻页次数不是页数（例如 11 次翻页不能写成 11 页）。只呈现有依据的值，未知写“未确认”或“未显示”，绝不以 0、0% 或伪进度条代替未知；若窗口包含恢复、记录等活动，应写明范围，不冒称有效阅读。开始时将自己的运行状态标为 `running` 并写实际开始时间与书目；结束时更新实际结束时间、阅读范围、完成状态和 `completed_books`。
4. **失败要直接通知用户。** 登录失效、页面打不开、发生冲突、阅读中断或其他失败时，立即在当前 Cue 私聊中说明卡点、实际完成到哪、是否影响打卡及恢复方式；同时更新 roster 与交接记录，不能只把失败留在仓库里等用户发现。打卡状态不明确时如实说，不声称成功。
5. **只在理解有变化时修正全书视角初版。** 不为每次短读重做整书汇编。将新增理解放进当天笔记；确有重要修正时，在 `overview.html` 中注明依据和更新时间。
6. **完读并确认后生成最终整书汇编。** 确认整本已读后，把 `overview.html` 初版和所有日期笔记整合校订为更有解释力的全书视角：主旨、叙事/论证结构、关键观点间关系、重要转折、核心洞见、局限与可迁移启发。明确实际覆盖范围和外部来源；制作最终 HTML（`final.html`）与 EPUB（`final.epub`）。初版视角不能冒充最终整书总结。
7. **交付并维护。** 用清晰简洁的 HTML（手机、桌面均可读）保存笔记；给用户可访问文件或站点链接。此类面向用户的微信读书阅读笔记默认公开，可直接发布到既有 GitHub Pages 并更新索引，无需逐篇询问；内部协调、原始 session-close/active-run 元数据及跨书综合仍保持私有。其他不在持续授权范围内的内容须另行授权。Git 仓库更新遵循 `references/coordination.md`；完成或受阻时更新交接板，发布后实际检查页面、资源和 Pages 构建。

## 阅读员归属与指标口径

- 首页每张**阅读内容卡**均标明阅读员名称与 Agent 类型，包括视角汇编卡；非阅读类模板/卡片不添加这类标记。归属以 `agent-roster.json` 及提交、通信记录等可核验证据为准，不得根据文风猜测；不确定时写“未知”或“待确认”。多人共同撰写时列出全部作者及各自类型，不把混合作者压成单一归属。
- 日期笔记指标须区分浏览/运行窗口与平台确认的有效阅读时长，并说明起止时间、合并范围和数据依据。以真实章节/帖子/小节标题和实际覆盖说明呈现读了什么，不用页码/页数或翻页数量作醒目指标，也无需为缺少页码增加“页码未显示”占位。翻页动作只可作内部运行证据，不等于页数、读完章节或理解成果。全书进度或有效时长无可靠依据时如实写“未显示/未确认”，不得推算或用伪 0%、伪进度条表达。
- 日期笔记采用自包含 CSS，指标卡片手机端两列、桌面端最多四列；可用语义化 `<dl>` 组织指标。公开输出不得包含原始 run/session ID 或私有交接字段；模板中标注的私有续读区段仍须按既有要求从公开版本完整删除，不发布私有 session-close。

## 每场阅读通知

- 每个实际阅读场次（包括定时与手动发起）都要在当前 Cue 私聊中通知用户两次：开始阅读前发一条简短开始消息；结束后发一条结果消息。按最新错峰安排逐场通知，不把同日多场合并成一次，也不按排班虚填已开始或已完成。
- 开始消息写明时段和书名；若是续读，可顺带说从上次停下处继续。不要先发进度播报。
- 结束消息报告实际用时、真实章节/帖子/小节标题及实际覆盖范围（区分部分阅读与读完），并附上只基于本场实际读到内容的简短思维导图。用 2–4 个节点说明核心问题、主要观点及其联系；不补写未读内容。
- 不以页码、页数或翻页数替代内容范围；章节/标题未确认时如实说明，并仅描述已核实内容，不编定位。场次未能开始或被打断时，仍及时报告状态、实际完成量及下一步；失败通知规则同时适用。

## 笔记质量

- 解释“这本书在做什么，以及各部分如何支撑核心意思”，不要只列事件或摘抄。
- 区分四层：亲读事实、官方/用户来源、公开评论或划线、自己的综合推断；在需要时给每层打清晰标签。
- 仅使用实际遇到的内容作为本次阅读证据；不补造章节、页码、论据或体验。
- 对整书视角提供必要的关键概念、核心张力、主题关系、结构图、读者可用的反思问题；简练但要足够帮助理解。
- 引用书籍原文保持必要且简短；不要复制书籍全文或大段受版权保护文本。
- 除非用户明确要求，不在阅读平台内部创建/发布想法笔记；默认只在私下归档和聊天里交付。

### 作者观点判断与模型推导（2026-10-21 用户决定）

- 日期笔记、全书视角初版与完读汇编都要对本篇真正影响理解的少数核心主张给出醒目的判断与理由；只评观点和推理，不评作者本人，也不逐句打分。每条用“作者主张 → 判断 → 理由/证据”写清楚，并关联实际读到的标题或段落。
- 判断标签按主张类型选用：✅成立（证据和推理支持其范围）；⚖️有条件成立（说明会改变结论的条件）；⚖️价值取舍（目标或价值排序不同，不能假装是纯事实对错）；❌不成立（事实或推理不支持结论）；证据不足时写“暂无法判定”并指出缺的关键材料，同时说明现有证据能支持什么。混合主张先拆开其事实前提和结论，不把一个局部正确扩成整套观点正确。
- 对政策或行动建议，说明作者要解决什么问题、谁获益／承担代价，以及建议是否真的达到目标。例如“越困难越应尽快买房”不能只拿等待成本作理由，还需看偿债、收入中断与退出选择；“政府不如不管房价”应说明比较的政策目标和取舍，不能只用立场代替判断。结论简短、直白、可读，不堆“无法复核”或免责话术。
- 写模型推导时用通俗语言交代参与者、各自能做什么、关键成本/收益如何改变选择、最后推出什么，以及这一步是否支持作者主张；只保留会改变结论的适用条件。避免把“模型有边界”当结论，直接说模型推出了什么、现实决策能带走什么。
- 全书视角未亲读的主张只可作为待检验问题，不冒充结论；只用外部资料时标清来源与二手性质。既有笔记仅按用户明确要求修改，并保留原实读范围、时间、来源及事实记录。
- 不为填模板保留空模块或无用占位（如“0/10”、空导读、反复说明暂缺资料）；没有实质内容时删去标题和整段。需要告知缺项时，只在会影响读者判断或下一步行动时用一句话交代。

### 用公开背景与读者反馈精进思考（2026-10-21 用户决定）

- 对本地 PDF、论坛帖等缺少平台划线／评论脉络的材料，可在实际读过文本后搜索并打开有用的公开背景资料和真实读者评价、讨论或划线，作为补充视角，避免“为读而读”。先明确它要帮助检验哪个主张、隐含条件或时代背景；外部材料不能代替亲读，也不能凭评论替作者补意图。
- 优先一手资料、可靠研究与可定位的真实读者内容；附来源链接并标明它是背景事实、评论观点还是亲读材料。单条评论、评分或搜索摘要不代表读者共识；有价值的分歧可并列呈现，不必穷尽搜索。
- 只纳入能改变解释、揭示遗漏或带来新问题的内容。不要把笔记写成“无法复核”清单、免责声明合集或外部材料综述；资料有限时简短说明后，继续分析文本本身的机制、证据和适用条件。
- 对这组天涯本地 PDF 笔记，原帖时间缺失时可按约 2010 年附近作为讨论背景，但须写成近似背景而非已核实首发日期；此假设不推广到其他作品。既有笔记或阅读事实仅在用户明确要求时修改。

### 用更高维度的知识看这本书（2026-10-19 用户决定）

- 在后续全书视角初版 `overview.html` 和完读汇编 `final.html`／EPUB 中固定加入本节，分别使用 `templates/pre-read-overview.html`、`templates/final-book.html`；放在核心观点之后、精读验证问题之前。用简短分项回答：**更大的知识坐标、这本书本身的历史作用、解释了什么及其边界、引出的思考、相似或互补的1–2本书**。这是把书放回知识网络，不是宣称 AI 全知或比作者／读者更高明；不用宏大术语代替解释，不取代原文精读。
- **知识坐标与解释力**：选择真正有解释增益的学科／思想框架，说明其如何连接书中具体问题、主张或真实章节，揭示了什么机制／经验、解释不了什么、有哪些反例或适用条件；文学作品可讨论叙事、审美与人类经验，不强套科学因果模型。类比不等于因果、理论相容不等于作者受其影响；未亲读部分标为综合推断、待亲读验证。
- **历史作用须有接受史证据**：区分“书写了什么历史”与“这本书在历史上造成了什么影响”。仅凭题材重要、作者知名、销量／评分或出版宣传，不宣称本书开创学派、改变历史或影响深远。按适当范围写其在相关领域、思想传统或读者群中的位置；影响判断需有可核实的传播、接受、引用、争论或后续实践依据。证据不足写“尚无足够证据判断本书的历史影响”，新近或小众作品不硬拔高到人类史地位。
- **来源分层**：把书中观点（标亲读状态或既有来源）、外部知识／接受史证据、自己的综合分析分开呈现；外部事实与评价逐项附已搜索并打开核对的来源名称、链接，必要时注明时间及争议，不仅凭搜索摘要或模型记忆定论。优先原始材料、学术／权威机构资料及可靠评论，出版方宣传注明其性质；推断明确标“综合分析／待验证”，资料不足如实留待补充。与“当年与今天”互相引用但不重复：本节侧重知识坐标、解释边界和接受史，后者侧重作者当时可知与后来的证据，不倒灌后见之明。
- **相似或互补书只选1–2本**：核对书名、作者及相关内容依据，分别说明相似问题／方法、关键差异或互补／反驳处，以及为什么值得对照读；不把自己的推荐写成学界公认谱系或实际影响关系，不虚称亲读过推荐书。暂无可靠候选时注明待补，不凑数、不自动开读或加入认领队列。
- **落回精读**：从上述分析提炼2–3个可回到真实章节／段落检验的问题，说明什么证据会支持或反驳判断；章节待确认就明确标注，不编定位。初版保持假设和覆盖边界，随实际理解的重要变化更新，确认完读后校订；读完也不使外部判断自动成为事实。日期笔记不必重复整节，只在实际已读内容相关时承接问题。
