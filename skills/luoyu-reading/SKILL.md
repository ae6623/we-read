# 落雨读书

> **所有 Agent 先读这一条**：本 Skill 只约束**协作目标与协议**——产出什么（预读框架/日期笔记/完读汇编）、按什么结构归档、来源如何标注、如何避免互相干扰、发布授权与时间错峰。它**不约束实现方式**：代码自动化、Agent 直接操作浏览器、人工整理都是被认可的手段，各 Agent 用自己擅长的方式达成目标，**互不假设对方的技术栈，互不干扰**。涉及具体平台的操作边界见 `references/platforms/<platform>.md`；代码类 Agent 的自动化实现细节集中在 `references/automation-code-agent.md`，**仅对该类 Agent 自身有约束力**。

**沟通记录按需读取**：先读最新 main 的 [沟通索引](references/agent-communication.md)，再读 Asia/Shanghai 今天对应的 `references/agent-communication/YYYY/MM/YYYY-MM-DD.md`；仅为跨日续接、未解决交接或证据追溯打开相关旧日，不通读全历史。开始、交接、完成或遇阻等新事件按实际发生日期追加日文件，不再追加索引；新日期/月/年的目录维护及跨日补记规则见索引。

为用户把多本书读得更有效：开读即建立有来源边界的全书视角初版，再把每天真实读到的内容连回框架，完读后才做校订后的整书汇编。`references/book-registry.json` 是书目归属/认领、完读、`active_session` 与 `resume_point` 的权威来源；`references/agent-roster.json` 只登记身份、类型、排班及个人状态镜像，不作为书目或完读事实的唯一来源。共享归档与 Git 规则见 `references/coordination.md`，跨 Agent 开始/结束记录见 `references/agent-communication.md`，用户最新决定见 `references/decisions.md`。使用某个平台前阅读对应的 `references/platforms/<platform>.md`（当前先有微信读书指南）。

## 共享书目认领、精确续读与三本综合

每场先读 `references/reading-state-protocol.md` 和权威仓库最新 `references/book-registry.json`，不要把已安装 Skill 的静态副本当实时状态；当前共享仓库为 `/workspace/we-read-main`，不在该环境时先定位获授权的同一仓库。book-registry 是书目归属/认领、完读、`active_session`、`resume_point` 和综合批次的权威来源；roster 只用于身份、类型、排班及个人状态镜像。有冲突就停下核对，不代改他人记录。

- 先认领再开读，用户指定书优先但不得抢占活动认领；未完书跨场次保留责任，确认完读后释放。所有共享写入按协议串行接受到 main 后才生效，不以本地或 PR 分支的拟认领冒充成功。
- 每场结束按 `templates/session-close.json` 在私有归档记录精确且有依据的下一章节/帖子/小节标题及其内部位置（页码仅可作内部辅助），以及一个基于已读内容的下次问题；未知写 `needs-confirmation`，不把百分比猜成页码。同书同日仍合并一篇，但保留每场区段。
- 所有 Agent 累计每 3 本唯一、已确认完读书，建立一个不重叠的私有综合批次；共同观点、分歧、互补关系和 3–5 个回忆问题按 `templates/cross-book-synthesis.md` 生成。迁移已有完读书计入去重总数；重读、重试、重复消息不重复计数。未满三本不生成，资料不足留待补充。
- 跨书综合、其私有问题及内部场次原始记录不得进入 Git、Pages 或公开索引；面向用户的此类微信读书阅读笔记按 2026-10-18 持续公开授权发布，该授权不覆盖跨书综合。每场 Cue 起止通知及失败直报保持不变；微信读书浏览器 Agent 的 06:30–07:30 与 14:00–15:00 两场各自独立且均启用，不因另一场完成而跳过。其他 Agent 时段不由此泛化。

## Agent 类型与排班

先读 `references/agent-roster.json` 确认身份、实现类型和预留时段；书目归属/认领与完读以最新 `references/book-registry.json` 为准，roster 中的个人书目/完读字段仅为镜像。避免在多个文档复制易过期的排班表。浏览器微信读书 Agent 的 06:30–07:30 与 14:00–15:00 是两个独立且均启用的场次；此安排不改变其他 Agent 时段。阅读计划的代码 Agent 只受 `references/automation-code-agent.md` 约束；浏览器/人工阅读 Agent 不需照搬其代码实现规则。新 Agent 加入时，在 roster 中登记类型和时段，并通过 `references/decisions.md` 记录用户决定；每次任务开始和结束都按沟通索引规则追加对应日期的日文件。时段冲突先协调，不同时间窗互不等待。

## 后续新阅读：按章节与标题定位（2026-10-18 用户决定）

- 对后续新阅读的日期笔记、全书视角初版、完读汇编与用户通知，以真实章节名、帖子/小节标题和标题层级组织范围、论点、证据与导航；不再以“第几页”引出分析，不用页码/页数作导航、标题、醒目指标或阅读成果维度。
- 没有正式章节的作品使用实际帖子、文章或小节标题；只有原文确有编号时才保留编号。标题无法确认时直说“标题待确认”，用已核实内容简述实际覆盖与停止处，不能编造标题、章节、编号或其他定位标记。自拟分析小标题须与原文标题明确区分。
- 同一章节未读完时，注明只读到哪个实际小节或内容段落，不把接触一个章节写成读完一章；保留来源标签、实际时长和未完读说明。
- 旧书及其既有笔记、已发布内容、先前阅读记录和历史页码保持原样，不批量回改。本决定仅替代今后输出的页码展示口径，不改实际阅读数据、内部续读兼容字段或各 Agent 的实现。

### 长书务实推进：抓主线，允许略读与跳过（2026-10-19 用户决定）

- 按篇幅与兴趣分配精力：短书（如《挪威极夜》这类体量）且兴趣匹配时尽量读完；长书先沿可核实目录挑有意思、叙事强的部分精读，叙事弱、啰嗦或低收益部分可略读并一笔带过。选择性覆盖不等于跳过整本书；但仍须如实注明哪些精读、略读、跳过或未读，不能冒称完整读完，也不因此更改完读确认标准。本条仅指导未来阅读，不重开或回改已完读短书。
- 沿原书真实章节／小节结构向前读，不要求逐字逐句；对每个实际阅读或略读的小节，抓住主要问题、作者主张、必要证据与结论，并连回全书主线。尚未掌握的部分注明未确认，不靠目录或外部概括补成亲读。
- 自主快速略读或跳过明显重复的铺垫、重复例子、离题支线与低收益细节，不必逐次询问用户；遇到支撑核心主张的关键材料仍要读懂，不能只为赶进度省掉必要论证。
- 在既有“实际覆盖”字段和范围说明中区分完整阅读、选择性略读、跳过与尚未读到的内容：略读写清实际覆盖的标题／段落，跳过明确标“跳过”，必要时简述理由；记录精确停止处及后续位置，不用一个连续范围掩盖中间空缺。选择性阅读不得表述为整章／全书完整读完，也不得仅因到达书末登记完读或增加完读计数。
- 复用章节 `read / reading / unread` 状态，不新增复杂状态体系：含略读或跳过、尚未完整阅读的章仍标“部分阅读”，全未读章保持“未读”；官方目录全部小节与实际已读／停止／未读标记继续按 `references/chapter-guide-style.md` 展示。来源标签“亲读”须同时说明选择性覆盖，不能暗示完整阅读。
- 此授权只改变今后的阅读方法，不回改旧笔记、发布物或历史事件，不改变认领、排班与暂停指令。《大转向：世界如何步入现代》继续暂停，不自动恢复；《王的归程：阿富汗战记（1839～1842）（甲骨文）》是已指定的下一本，本次规则更新不打开该书、不算开读或阅读场次。

### 章节导读：标题下面说明“这一章在做什么”（2026-10-19 用户决定）

- 在后续新输出的章节导航中保留已核实的“部／章／小节”层级；每个实际列出的章节标题下面紧接 1–2 句简短导读，说明这一章讨论什么、要解决什么问题，或在全书中起什么作用。让用户先看结构，再看说明，不只列目录，也不展开成长篇总结；没有正式章节时用真实帖子／文章／小节标题，不编造标题、编号或层级，不以页码导航。
- **全书视角初版**：标题以可核实目录为准，说明依据已核实的目录、官方简介等逐项标注来源。仅凭标题作判断时标“综合推断 · 初步导读，待亲读验证”；依据不足时写“导读待阅读后补充”，标题未确认则明确“标题待确认”，不补造全书目录，不把未读内容写成亲读结论。
- **日期笔记**：只为本篇声明的实际已读章节提供导读；部分阅读须注明“部分阅读”及已确认停止处，说明也仅限已读部分，不能据接触一章概括未读全章。其他未读章节不混入本次实读导航。
- **完读汇编**：确认全书完读后，按实际阅读校订各章导读及其与全书的关系，修正初版推断，保留必要来源标签；HTML 与 EPUB 保持同一口径。
- **呈现样式（2026-10-19 用户决定）**：统一用「卡片分组 + 点击展开」，让人类先浏览结构、需要时再展开。每个部（或无部时的一级分组）一个卡片 `.toc-part`，顶部 `.part-label` 写部名与章号区间；每章一行 `.ch-item`（`<details><summary>`），同行依次是章号 `.ch-no`、标题 `.ch-t`、状态徽标 `.badge`（`data-s="read|reading|unread"`，文案用「整章／部分阅读／亲读／未读」）、折叠箭头 `.caret`；点标题下滑展开 `.ch-body`，正文放 1–2 句导读，底部 `.ch-src` 写「导读依据／来源与依据」。默认折叠，不预展开，不加页码。**全书视角的导航里每一章都必须可展开**：读过的章展开是导读（标亲读／部分阅读）；未读的章展开只放可核信息——出版方目录的小节清单（`ol.ch-secs`），或一句明确标「推断 · 目录导向」的初步阅读问题，并在 `.ch-src` 写明依据是目录标题；不许把未读章留成不可点击的纯文字行，也不许把目录标题包装成内容总结。样式以 `templates/date-note.html` 与 `templates/pre-read-overview.html` 为准，不自造新样式；已发布笔记的同类板块同口径。**标了「部分阅读」的章，展开体必须列出该章官方目录的全部小节并标出读到哪一节**：已读深底、`停在这里` 赭边籤、未读置灰，三段不许混用；`已读 M 节` 必须等于高亮条数，`停在这里` 有且只有一条，未读小节只放官方标题、不写任何概括。完整结构、配色与生成器接入口径见 `references/chapter-guide-style.md`（小节数据取自 `toc_fetch.py` 产出的 `data/toc-flat.json`，不手抄、不按百分比反推）；站点骨架见 `templates/reading-note.html`。已发布笔记按此口径补清单，但只补结构与进度，不改既有结论。
- 只更新后续输出规则与未来模板；不回写旧笔记、既有发布物或历史阅读记录，不改变其他 Agent 的个人状态、实现方式与隐私边界。

### 新书先看口碑与兴趣匹配，低收益及时止损（2026-10-19 用户决定）

- 在每本新书或合集内独立分册**首次实际阅读前**，快速搜索并打开核对数篇优质／高赞书评；可得时兼顾可信专业评论与读者评论聚合，不只看搜索摘要或单一评分。简短标注来源名称、链接及“公开评论／二手依据”，概括叙事性还是专业技术／工具参考导向、文风与节奏、主要争议或阅读门槛，并结合用户兴趣给出“不值得投入／适合短试／值得继续”等初步判断。查不到可靠评论就注明信息不足，不补造共识。
- 把口碑当选书的二手背景，**不是书籍内容证据，更不是亲读结论**；不长引书评，不从书评生成原文摘录。模板 `pre-read-overview.html` 的可选“读前口碑与兴趣判断”仅承载简短来源与匹配判断，不取代开读后的全书视角初版。
- 若评论提示与用户目标明显不合（如过于专业工具化、味同嚼蜡或大部分材料兴趣低），主动建议／依既有选书授权选择止损，不因沉没成本硬读。评分不是唯一标准，也不得用低分强行跳过用户明确想读的书；口碑分歧而用户要求继续时，先按可核实目录挑少量有代表性、可能有趣的章节试读，再据实际体验判断，不把选读写成整书完读。
- 用户明确说无兴趣或要求停止时，立即停止该书；由责任 Agent 按既有串行协议将本人书目标为 `paused`，保留认领与已确认续读点，不自动恢复、不记完读，然后转向用户已批准队列中下一本合格书目（仍须核对认领、防冲突及读前筛选）。只在 Cue 简报／带日期的私有内部交接留下简短总体评价；**不为被叫停的书另建或发布负面读前笔记**，不改写旧笔记或其他 Agent 的记录。
- 本节是所有后续新书／独立分册的通用挑选方法，**不构成对《王的归程》的止损指令**。它仍为当前持有任务 `king-return-dalrymple`；用户要求从其目录挑几章不错的章节阅读，由独立的实际阅读任务执行。本次仅更新规则与未来模板，不打开阅读器、不开始场次、不改 registry、roster、排班或当前书记录。

## 工作流程

1. **先核配置，再决定读什么。** 先确认用户指的书、作者和平台；开读前查看最新 `book-registry.json`、`agent-roster.json`、最新交接记录与已有归档，确认当前时段无人冲突、没有同一书目的活动运行。以 registry 核对书目归属/认领、完读、`active_session` 与续读点；roster 仅核对身份、类型、排班及个人状态镜像，镜像不得覆盖或裁定 registry。按协议选择用户指定或应续读的书，绝不重读已确认完读书，除非用户明确要求重读；不确定时先停下并报告，不猜。检查归档索引、全书初版、日期笔记和完读汇编，避免重复创建或覆盖。
   **首次开读门槛：** 新书／独立分册先执行上节口碑与兴趣筛选；决定继续或小样试读才进入实际阅读与初版产出，决定止损则只留简短内部评价，不为凑归档创建公开 overview。
2. **新书开读即产出全书视角初版（overview.html）。** 用户已明确决定：不要只给一张“预读地图”——开读时就应给出一份完整的全书视角。收集可验证的官方书目简介、目录、作者说明、用户提供的材料与可靠公开划线，结合模型自身对该作品的知识，产出全书主旨、结构、关键观点与主题关系；同时按四层来源标签（亲读 / 官方简介目录 / 用户材料 / 公开评论划线 / 综合推断）分清信息出处，并单列“阅读时要验证的问题”。它不是最终总结：未经亲读确认的部分保持推断标记，完读后校订升级为 `final.html`。没有可靠依据时，不装作掌握全书。
3. **每日记下实际阅读并记录运行状态。** 日期笔记写实际范围、关键观点、作者如何展开、与整书框架的联系、理解变化和可迁移启发；同一本书同一天多场阅读合并为一篇，不同书籍分别建笔记；不编未读内容。日期笔记使用 `templates/date-note.html`：标出阅读员名称和 Agent 类型，以章节/帖子/小节标题和实际覆盖范围作为主要导航；指标卡片只突出实际时长、实读章节/标题、覆盖说明及有依据的全书状态，平台有效阅读时长注明计时范围/来源，不设置页码/页数或翻页数量卡片。严格区分浏览窗口时长与平台确认的有效阅读时长；翻页次数不是页数（例如 11 次翻页不能写成 11 页）。只呈现有依据的值，未知写“未确认”或“未显示”，绝不以 0、0% 或伪进度条代替未知；若窗口包含恢复、记录等活动，应写明范围，不冒称有效阅读。开始时将自己的运行状态标为 `running` 并写实际开始时间与书目；结束时更新实际结束时间、阅读范围、完成状态和 `completed_books`。
4. **失败要直接通知用户。** 登录失效、页面打不开、发生冲突、阅读中断或其他失败时，立即在当前 Cue 私聊中说明卡点、实际完成到哪、是否影响打卡及恢复方式；同时更新 roster 与交接记录，不能只把失败留在仓库里等用户发现。打卡状态不明确时如实说，不声称成功。
5. **只在理解有变化时修正全书视角初版。** 不为每次短读重做整书汇编。将新增理解放进当天笔记；确有重要修正时，在 `overview.html` 中注明依据和更新时间。
6. **完读并确认后生成最终整书汇编。** 确认整本已读后，把 `overview.html` 初版和所有日期笔记整合校订为更有解释力的全书视角：主旨、叙事/论证结构、关键观点间关系、重要转折、核心洞见、局限与可迁移启发。明确实际覆盖范围和外部来源；制作最终 HTML（`final.html`）与 EPUB（`final.epub`）。初版视角不能冒充最终整书总结。
7. **交付并维护。** 用清晰简洁的 HTML（手机、桌面均可读）保存笔记；给用户可访问文件或站点链接。此类面向用户的微信读书阅读笔记默认公开，可直接发布到既有 GitHub Pages 并更新索引，无需逐篇询问；内部协调、原始 session-close/active-run 元数据及跨书综合仍保持私有。其他不在持续授权范围内的内容须另行授权。Git 仓库更新遵循 `references/coordination.md`；完成或受阻时更新交接板，发布后实际检查页面、资源和 Pages 构建。

## 阅读员归属与指标口径

- 首页每张**阅读内容卡**均标明阅读员名称与 Agent 类型，包括视角汇编卡；非阅读类模板/卡片不添加这类标记。归属以 `agent-roster.json` 及提交、通信记录等可核验证据为准，不得根据文风猜测；不确定时写“未知”或“待确认”。多人共同撰写时列出全部作者及各自类型，不把混合作者压成单一归属。
- 日期笔记指标须区分浏览/运行窗口与平台确认的有效阅读时长，并说明起止时间、合并范围和数据依据。以真实章节/帖子/小节标题和实际覆盖说明呈现读了什么，不用页码/页数或翻页数量作醒目指标，也无需为缺少页码增加“页码未显示”占位。翻页动作只可作内部运行证据，不等于页数、读完章节或理解成果。全书进度或有效时长无可靠依据时如实写“未显示/未确认”，不得推算或用伪 0%、伪进度条表达。
- 日期笔记采用自包含 CSS，指标卡片手机端两列、桌面端最多四列；可用语义化 `<dl>` 组织指标。公开输出不得包含原始 run/session ID 或私有交接字段；模板中标注的私有续读区段仍须按既有要求从公开版本完整删除，不发布私有 session-close。

## 每场阅读通知

- 每个实际阅读场次（包括定时与手动发起）都要在当前 Cue 私聊中通知用户两次：开始阅读前发一条简短开始消息；结束后发一条结果消息。每天两个独立场次各自通知，不把早晚场合并成一次。
- 开始消息写明时段和书名；若是续读，可顺带说从上次停下处继续。不要先发进度播报。
- 结束消息报告实际用时、真实章节/帖子/小节标题及实际覆盖范围（区分部分阅读与读完），并附上只基于本场实际读到内容的简短思维导图。用 2–4 个节点说明核心问题、主要观点及其联系；不补写未读内容。
- 不以页码、页数或翻页数替代内容范围；章节/标题未确认时如实说明，并仅描述已核实内容，不编定位。场次未能开始或被打断时，仍及时报告状态、实际完成量及下一步；失败通知规则同时适用。

消息范例：

以下占位内容仅演示格式；每场都要替换为本场实际可确认的数据，不得照抄或估算。

```text
开始：早场开始啦，我从《书名》上次停下的位置继续读。结束后告诉你实际用时、章节/标题范围和简短思维导图。

结束：本场实际用时 {{实测时长与计时口径}}，读到《{{真实章节或帖子标题}}》的 {{已确认停止处}}；{{如实说明是否读完该部分}}。
思维导图：
核心问题：……
├─ 观点一：…… → 依据/展开：……
└─ 观点二：…… → 与核心问题的关系：……
```

## 笔记质量

- 解释“这本书在做什么，以及各部分如何支撑核心意思”，不要只列事件或摘抄。
- 区分四层：亲读事实、官方/用户来源、公开评论或划线、自己的综合推断；在需要时给每层打清晰标签。
- 仅使用实际遇到的内容作为本次阅读证据；不补造章节、页码、论据或体验。
- 对整书视角提供必要的关键概念、核心张力、主题关系、结构图、读者可用的反思问题；简练但要足够帮助理解。
- 引用书籍原文保持必要且简短；不要复制书籍全文或大段受版权保护文本。
- 除非用户明确要求，不在阅读平台内部创建/发布想法笔记；默认只在私下归档和聊天里交付。

### 当年与今天：有证据的回溯性阅读（2026-10-19 用户决定）

- 在后续新日期笔记、全书视角初版与完读汇编中，明确标出“当年与今天”，关联实际章节/帖子/小节标题，分别写：**当年作者能知道什么**（原作写作/首发时点、当时可得知识、作者经验与假设）、**后来才知道什么**（后续事实/研究及其时间与可核查来源）、**今天对雨的启发**（当年读者可获得什么、今天仍可借鉴/需修正什么、适用条件与可尝试行动）。原作时点与后来的再版/汇编日期分开，未确认写待确认。
- 批判性检视作者知识、个人经验与样本、隐含假设及论证边界；区分作者原意、后续证据与自己的分析，不把后来结果倒灌成作者当时理应知道的事，不用成败结果替代对当时推理的评价，也不假定新知识必然推翻旧观点。后续知识不足时写“待核实”，不编造时代背景或用户经历；对雨的建议基于已知需求，未知条件写成条件句。

### 有意思的原文段落 Top 10（2026-10-19 用户决定）

- 按 `templates/date-note.html`、`templates/pre-read-overview.html`、`templates/final-book.html` 的栏目精选原文短摘录，不以摘抄代替理解。每条独立呈现：**短原文**、**真实章节/帖子/小节标题与已核实定位**、**为什么有意思/自己的分析**；引用与分析视觉、语义分开。标题待确认时如实标明，不编标题或页码，不用自拟分析标题冒充原文标题。
- 仅从确实读到、能核对原文的材料中选取，核对措辞与归属；不从记忆、二手书评或未读章节补齐，不拼接为伪原句。优先选有洞见、张力、反直觉或表达特色的短句/短片段，保留必要语境；转述明确标作转述，不算原文摘录。每条只引解释所必需的最短文本，兼顾全页累计引文量，不能把十条拼成连续大段或替代原作。

## 平台扩展

平台操作是可替换的适配层：主流程保持不变；每个平台单独说明登录状态、可读页面/听书、进度与标记、付费墙和安全边界。新增平台时从 `references/platform-adapter-template.md` 建立独立适配文件，并把实测与待验证事项分开。不要假定不同 App/网站有相同控件或允许同种自动化。读取对应平台参考文件后，再使用该运行环境中实际可用且获授权的方式。遇到权限、登录、付费或访问阻碍，说明事实并暂停受限动作，不猜密码、不付费、不绕过限制。
