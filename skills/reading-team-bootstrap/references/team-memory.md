# 团队精简工作记忆

**性质：** 由授权共享规则提炼的工作摘要，不是私人Memory导出；不含当前书目、排班、锁或计数。冲突时读同一仓库最新main的最新决定，不用摘要覆盖事实。

## 为雨读出什么

- 把书讲清楚，并给雨继续精读的输入：先介绍书与论证主线，再分析关键章节，最后联系跨章关系与值得追问的问题；不要只有复述和流水账。
- 对重要主张明确判断“成立／有条件成立／价值取舍／不成立／暂无法判定”及关键理由；把模型里的参与者、选择、成本收益和推导讲成人话，不堆抽象词。
- 用真实章名／小节／帖子标题组织，不编标题，不以页数、后台续读点、运行时间堆成果。公开页面不塞场次流水账；原始证据仍保存。
- 新书先快速核实可靠口碑和兴趣匹配；低收益可止损，不为沉没成本硬读。亲读的第一章按最新授权处理，略读、跳过、未读须如实区分。

来源：`luoyu-reading/SKILL.md`；`references/decisions.md` 中公开内容原则、作者观点评估、口碑与长书规则。

## 来源不能混

- 亲读、官方简介／目录、公开评论、用户材料、AI问答、自主推断分别标注。官方Skill可辅助书架／目录／进度，但不证明本场读过正文或问过AI。
- 微信读书书内AI通过获授权浏览器实际提问；逐题等完整返回，针对具体缺口追问，不机械复问。长书按最新规范覆盖官方目录全部章节，不能只挑几章或用一行导览替代。
- 金句只能用可逐字核实且符合真实已读边界的必要短原文，不凑数量，不把AI引语当原文。AI章节流程完成可按授权记AI阅读完读，但不等于亲读或平台有效时长。

来源：`luoyu-reading/references/ai-ask-book.md`、`platforms/weread.md`、`decisions.md`。

## 团队如何不撞车

- registry管owner／claim／活动场次／续读点／完读与综合；roster管身份排班镜像。先查最新main再串行登记；分支、本地提交或计划均不等于已开始。
- 同平台全队锁，不因不同书就并行；管理员转达、本场授权和运行窗口分别核实。暂停不自动恢复，错过不补跑，不靠超时清锁或换号接管。
- 实际阅读、平台有效时长、AI交互、Git准备分别记；约20分钟是目标，不是事实。开始、完成、发布、线上可用、通知、安装都需各自证据。
- 每三本唯一完读做不重叠私有综合，按book_id去重；私有原始场次、承接问题、跨书综合不进Git／Pages。具体批次与资料缺口读registry和获授权私下交接，不在此复制。

来源：`luoyu-reading/references/reading-state-protocol.md`、`coordination.md`、`agent-communication.md`。

## 中断后保留什么

保留已有成果、确认证据和未知项；按实际事件与停止处接续，不重复计数，不把旧位置当本场新核验。权限按实际环境核查，子任务无写权限则走无凭据补丁交接。平台反自动化／验证提示即停，不模拟真人规避。新账号重建只迁移规则，不能继承旧账号的权限、锁或私人资料。

来源：`reading-admin/SKILL.md`、`luoyu-reading/references/workbuddy-handoff.md`、`coordination.md`、`platforms/weread.md`。
