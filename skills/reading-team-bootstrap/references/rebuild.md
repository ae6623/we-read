# 重建流程与验收

## 1. 找到包与最新事实

以本Skill所在目录为起点解析 `team-manifest.json` 与本Skill资源；仓库目录可移动。其他角色及共享规范从获授权的同一仓库定位，不假定安装路径，也不假定各Skill安装后互为相邻目录。读取仓库身份与最新main，记下实际commit；如果只有离线包，完成角色草拟与本地校验即可，暂不安排运行。

运行前从同一main核对最新decisions、registry、roster和实际日期日文件。registry管书目，roster不是完读裁判；最新用户决定覆盖旧排班，遇冲突先协调。不得把离线包中的历史状态覆盖main。

## 2. 装载规范和角色

读取manifest的每个Skill、角色职责和对应memory。按当前Cue实际支持的导入流程安装并确认可用；本地文件不是安装回执。先查新账号已有哪些角色，按名称和职责核对，不因同名就覆盖。

由主协调者在其私有顶层会话使用当前支持的Agent配置流程：配置管理员（可复用自己）及四类读书员。把各角色Skill内稳定职责作为Instructions的依据，把团队摘要和本人摘要作为工作记忆上下文；不能声称已写入Cue原生Memory，除非有实际支持的写入路径与成功结果。若不能写Memory，在角色Instructions中指定每次按需加载摘要，明确报告采用此方式。

不要把临时任务subagent当成持久Agent。每次创建用独立临时草稿与稳定请求标识，拿到实际完成回执才登记新UID；部分失败只续失败项。若当前环境没有创建能力，交由主协调者或用户在应用中按角色清单建立，不伪造UID或成功回执。

## 3. 新账号的联系表留在私下

把逻辑角色键与新账号实际Agent UID的对应、新群组、实际Skill资源和任务回执保存在仓库外权限受控位置，不提交本仓库。此处只给未填字段，不生成携带旧ID的导入配置：

```json
{
  "logical_role": "填写manifest中的角色键",
  "new_account_agent_uid": "根据真实回执填写",
  "skills_confirmed": [],
  "memory_delivery": "摘要上下文或已确认的原生写入方式",
  "permissions_checked": [],
  "handoff_status": "needs-confirmation",
  "scheduler_status": "not-created"
}
```

逻辑键不是身份凭证。若用户要创建群组，须等待成员都确认建立后再用真实新UID创建，并核对协调者也在组中。已有群组先复用，不重复建队。填好的映射仅供新账号私下使用；不含秘密，秘密仍保存在新账号获授权的秘密存储。

## 4. 恢复阅读前的门槛

先核实旧账号是否仍有运行与调度，不复制原任务ID；不能从新账号看到就写未知。需要关闭或交接旧任务但无权限时，请原账号责任方处理，不能靠新号同时启动。旧owner未明确释放或用户未明确核准交接，新角色不冒用旧owner，即使逻辑ID相同。

在原运行已安全停止且责任合法交接后，由各读书员本人按最新协议认领／维护自己的状态。管理员只核查协调，不代改他人的个人记录或释锁。每场活动登记必须被权威main接受，且收到本场管理员明确“已转达”、仍在允许窗口，才可操作正文或AI面板。权限、通知或锁有一项不清楚就报告阻塞。

应用、微信读书登录、官方Skill辅助查询和Git写入按新账号与实际环境核查；不导入cookie、profile、旧API Key或他人凭据。没有官方辅助API权限时，可依已授权浏览器预检；平台AI仍用浏览器。平台验证／反自动化警示立即停止，不复制历史随机节奏或规避识别措施。

## 5. 排班另做，不随包启动

本迁移包不内置固定时刻、cron、机器计划任务、后台服务或自动启用脚本。如需恢复定时工作，读取当前自动化与调度技能，按最新main的实际角色安排和新账号支持的任务系统建立，先检查已有任务避免重复。停用／请假／受阻角色不自行恢复；云端自动化历史变体不默认启用。读取不到实时状态则只完成草拟，不创建运行任务。

## 6. 验收并给雨一句简报

| 验收项 | 通过的证据 | 不通过怎么办 |
| --- | --- | --- |
| 文件完整 | 本包只读校验通过，Skill入口及memory齐全 | 修补本地文件 |
| Skill实际可用 | 新账号实际导入结果，可加载正文 | 报待导入，不称已安装 |
| 团队建立 | 当前协调者与四角色有真实配置／创建结果 | 保留成功项，仅续缺项 |
| 记忆装载 | 每个角色可加载团队和本人摘要 | 报待装载；不冒称私人Memory复制 |
| 权限与联系 | 当前环境必要应用／设备／发送能力验证 | 私下补授权；不复制旧凭据 |
| owner与运行 | 同一main、旧停止证据、明确合法交接、全队无冲突 | 停在恢复预检，绝不抢锁 |
| 定时部署 | 实际保存／启用结果与下一运行时间 | 无回执就写未部署 |

回报示例：“管理员及四类读书员已准备／还缺哪些；规范和摘要已装载／待导入。当前main为已核commit，阅读与排班尚未启动／实际已启用哪些；剩余阻塞是什么。”只填写有证据的结果，不把本模板当成功状态。
