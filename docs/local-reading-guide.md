# 本地书稿阅读与分析指引

适用于接到单书阅读任务、并获准使用本地 PDF 的阅读员。它规定阅读前的状态门槛、文本分析和公开整理边界；实际身份、书目状态、资源锁及收尾字段一律以最新 `main` 和现行角色规范为准。

## 开始前：确认书目与本场

1. 先更新并阅读最新 `main` 中的阅读状态协议和适用角色规范，核对书目、owner、claim、暂停/阻塞状态、当前活动场次及资源冲突。不要凭旧交接或本地副本推断授权。
2. 每位阅读员只处理自己有效认领的一本书。同一本书不并行分给不同阅读员；切换书目须保留原有责任并按协议处理，不得悄悄丢弃认领。
3. 按当前协议完成单书 claim 与本场 run 登记。只有认领和活动场次已被权威 `main` 接受、且资源检查通过后，才能开始分析；本地改动或未合并分支不算成功登记。
4. 仅打开本场明确授权且可访问的 PDF，核对书名、作者和版本。权限、来源、书目状态、owner 或锁有任何不确定，先停下并报告，不尝试绕过访问限制。

## 提取文本并分段分析

- 优先从 PDF 提取可检索文本，并保留可核实的原始页码标记。把文本按连续页段交给当前任务允许使用的模型，逐段推进；每段都记录实际覆盖范围，避免遗漏、重复或把“已提取”误写成“已分析”。
- 只使用当前获准的本地分析方式。不得把书稿、提取文本或 chunks 发送给 Gemini 或其他外部模型/API；不得因本地模型不可用而自行切换外部服务。若文本无法可靠提取或当前模型不可用，停止并报告阻塞。
- 对每个故事或章节，按同一结构整理：
  1. 论证或叙事链：作者从什么材料或观察出发，经过哪些关键推理，得出什么结论；
  2. 关键前提与隐含假设：哪些条件被默认成立，哪些因果关系尚未证明；
  3. 薄弱环节：证据不足、概念含混、选择性取材、推理跳跃或反例未处理之处；
  4. 与主流观点的冲突：明确区分书中主张与已被广泛接受的解释；没有足够依据时写“尚未核实”，不要把个人判断包装成共识。
- 不以章节标题或模型生成的目录替代正文覆盖；分析结论须能回到实际处理过的文本。未处理、抽取失败或无法定位的部分要明确列为缺口。

## 引文与覆盖记录

- 只选与分析直接相关的短引文；逐字对照实际提取文本，保留原意，不用模型转述冒充原文。无法确认文字或定位时不引用，并标明未核。
- 在内部工作记录中保存 PDF 总页数、逐段实际分析页码范围、未覆盖范围及抽取/定位异常。页码范围只反映真实分析过程，不可由已提取页数、章节数或模型声称推算。
- 公开笔记必须服从仓库内容规范：不写总页数、页码、进度、时长等流水账。需要说明覆盖情况时，使用简洁的文字说明分析范围或缺口；详细页码覆盖仅留在私有工作记录中，不公开 PDF 私有路径。

## 标注与收尾

- 范围不完整、存在漏页或部分章节未分析时，标注“部分 AI 分析”，并在私有工作记录说明已分析范围与缺口。
- 只有实际覆盖并核对了全书内容、且没有未处理的文本缺口时，才可标注“AI 全文分析”。全文分析说明的是 AI 分析覆盖，不代表人工亲读或平台完读。
- 不得写成“雨亲读”“雨完读”，也不得把 AI 分析结果当成人工阅读、平台阅读时长或完读证明。AI 不确定之处须标注，不把推断伪装成事实。
- 完成后按最新状态协议收尾本人的 run，记录实际状态与续读点；只清理自己的活动项，不改他人状态，也不因完成 AI 分析自动变更书目 owner 或完读状态。

## 公开与私有边界

公开内容只发布经过提炼的分析和必要的短引文。不得发布原始 PDF/书稿、全书文本、chunks、原始模型输出、私有路径、凭据、登录态或私人运行日志。内部覆盖记录与公开读者笔记分开保存；提交前检查新增内容没有私人资料或不符合当前仓库规范的页码、页数、进度信息。
