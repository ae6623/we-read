## 二、书架顶部筛选：按内容类型（本方案定义）

书架 = 全部书，顶部筛选条切「这本书当前提供到哪一步」：

| 筛选项 | 含义 | 判定依据 |
|--------|------|----------|
| 全部 | 默认 | — |
| 通读 | 有全书视角页 | 存在 overview.html |
| 精读 | 有精读页 | 存在 mindmap.html |
| 归档 | 有整书汇编/日期笔记 | 存在 final.html 或 notes/ |

实现：每张卡加 `data-mode="whole|jingdu|archive"`（可多选，空格分隔），筛选按钮切 class；搜索框同时上移到书架顶部并 sticky（通读面板原本没有搜索框，这是本次必补）。

> 系列仍在独立 Tab，不进书架筛选（避免与 Tab 重复）。

## 三、deep-read（58 页「精读深读」）合并进精读

### 3.1 deep-read 有什么（与精读页不重复的部分）

以《1984》为例（deep-read 38KB / 精读页 86KB）：

| 区块 | 内容 | 精读页是否已有 |
|------|------|----------------|
| 这本书怎么读 | 分册/章节/摘录数概览 | 部分重复（精读页有章数、要点数、原句数） |
| **《章名》这一章围绕什么展开？** ×25 | **逐章 AI 追问** | ❌ 精读页没有，这是 deep-read 独有 |
| 核心追问 | 跨书追问 | ❌ 独有 |
| 精选原文 | 金句摘录 | 部分重复（精读页有每章原句） |

### 3.2 合并方式（推荐）

1. **逐章追问 → 挂到对应章条目下**：精读页每章 `<details class="mmx-cn">` 内，在原句块之后追加一段「追问」（`mmx-ask`），按章名匹配；匹配不上的章跳过并计数。
2. **核心追问 → 精读页新增尾部区块「核心追问」**（跨书视角，放在章节树之后）。
3. **精选原文 → 不单独迁**：精读页每章已有落库原句，重复；若某书原句为空则迁入。
4. **「这本书怎么读」概览 → 不迁**：精读页顶部已有命题卡与统计。
5. 合并完成后：**删除 notes/deep-read.html**，并清理首页/笔记页/任何指向它的链接（目前首页无链接，主要是目录页与可能的互相引用）。

### 3.3 验收

| 项 | 标准 |
|----|------|
| 内容不丢 | 58 页的逐章追问全部落到对应精读页，未匹配数 ≤ 5% 且逐本记录 |
| 无重复入口 | 站点上不再存在「精读深读」字样；deep-read.html 404 或无引用 |
| 页面不炸 | 合并后单页 ≤ 现有最大页（294 章那本 1.7MB），gzip 后 <600KB |

## 八、补充决策与验收（2026-10-28 追加）

按站主最新决定，后续不安排亲读或以「完读」作为流程目标，书籍内容通过 AI 问答与 LLM 总结整理。本节补充并取代前文中把归档绑定到「读完之后」的门槛；不删除或改写既有阅读事实与历史记录。

### 8.1 明确「归档」收录范围

- 「归档」表示已整理、可回看的书目内容，不代表亲读完成或读完一本书。可收录 AI 问答、LLM 总结及保留的历史日期笔记，并分别标明来源与内容类型。
- 首页的「精读」表示按章节组织的详细 AI 内容；如继续保留日期笔记，应明确它是历史记录入口，不暗示未来会持续产生亲读笔记。
- 通读、精读、归档筛选按实际存在的资源判定。一本书可同时具有多种资源；筛选结果可重叠，但「全部」视图只显示一张书目卡，具体入口由卡片内资源链接指向。

### 8.2 标明 AI 内容与引文来源

- 逐章要点、章节追问、跨章总结等 LLM 生成内容，应在首屏可见处说明其 AI 来源和依据；不以「读后感」「亲读」「已完读」描述这些内容。
- 只有能够逐字对应到可访问原文的内容才标作「原文引句／金句」，并尽量提供章节或小节位置。模型生成的概括、转述或无法核对的句子不得加引号伪装原文，应标为「AI 概括」或不展示。
- AI 问答应保留问题、回答与书内依据之间的对应关系；外部资料另行标明，不与书内引源混为一谈。

### 8.3 deep-read 迁移的内容保全闸门

- 章名匹配失败的追问不得只计数后跳过。迁移清单须逐条记录原页、原问题、处置结果及目标章节／锚点；处置仅限迁移到对应章节、合并为跨章追问，或经人工确认重复后舍弃。
- 仍未判定的项目不得删除或静默丢弃。只有逐项处置完毕、未匹配未处置数为 0，并完成迁移前后抽查后，才可下线原 deep-read 正文。
- GitHub Pages 不提供通用重定向时，原 deep-read URL 应保留轻量迁移页，说明内容已迁到哪本书的精读页并给出链接；书签和站外链接仍应有去处。站内导航则统一改指新精读页。

### 8.4 页面体量与可访问性验收

- 保留本方案现有 gzip 体积预算，并在最大章节数页面上实测首屏加载、展开首章响应和低速网络体验；只测压缩总量不足以代表手机体验。
- 逐章追问默认收起。若内容超过预算，应按章节分段或延迟载入，并保留可直接打开的章节锚点；不能以删除内容或截断回答来过关。
- 每批至少检查 320px、390px 与桌面宽度，键盘展开／收起、焦点可见、搜索筛选叠加及无 JavaScript 时的基本导航；sticky 搜索不得遮住标题或占用过多首屏空间。

### 8.5 搜索与筛选的组合规则

- 搜索范围应包含折叠入口文字和书名；搜索词与内容类型筛选同时生效，结果计数反映筛选后的卡片数。
- 一本书有多种内容时，可出现在对应的多个筛选结果中，但「全部」视图只显示一张卡；空结果应给出清除筛选的入口。
- 验收覆盖筛选后搜索、搜索后切筛选、清除搜索与筛选、刷新页面等路径，并确认书名和入口在手机上都可见可点。
