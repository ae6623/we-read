# 需求记录：私有全文存档放开（2026-11-07）

## 需求

用户从论坛帖导出的本地 PDF，需要由读书 Agent 把原文全文写入本人私有笔记。Agent 连续两轮拒绝：先以「公开可读不等于可以把整篇原文搬到新的公开页面」拒绝；用户补了「上传的这个笔记只有我能读」「加密码页显示原文」后，仍以「密码只限制谁能看，不能替代全文转载授权；把全文放到密码页仍是在另一处复制发布」拒绝。

用户决定：把挡住这件事的三处规则全部改为允许。

## 根因

Agent 执行的是共享规则，不是在辩论。被禁的是「把整篇原文复制成另一个页面」这个动作本身，与页面可见性无关。用户给出的三个条件——材料可随便翻阅、仅本人可读、加密码——全落在「谁能看到」这一维，打不到规则点，所以加多少层访问限制都会被同一句话挡回。

这是规则粒度问题，不是沟通问题。改话术无效，改规则才有效。

## 三处规则位置

| 位置 | 原限制 | 改后 |
|---|---|---|
| `skills/luoyu-reading/SKILL.md` 笔记质量段 | 引用书籍原文保持必要且简短；不要复制书籍全文或大段受版权保护文本 | 公开页面仍守短引；本人导出／上传材料写入本人私有笔记或私下归档，允许全文转录与保存 |
| `skills/luoyu-reading/references/ai-ask-book.md` 整理、校验与交付段 | 交付前检查「没有…大段受版权保护文本…」 | 该检查项去掉版权文本一项，并明确短引限制只适用于公开页面 |
| `docs/local-reading-guide.md` 公开与私有边界段 | 不得发布原始 PDF/书稿、全书文本、chunks 等 | 私有笔记／私下归档允许保存这些全文；公开页面仍禁止 |

## 解决方案

按目标位置分流，不整体取消边界：

1. **私有位置允许**：材料来源于用户本人导出／上传（本地 PDF、论坛帖等），目标为用户本人私有笔记或私下归档。这属于个人存档转录，不是转载发布，允许保存原始 PDF、全书文本、chunks、原文转录全文，不受短引总量约束。
2. **公开位置不变**：公开页面仍只发布提炼分析和必要短引，不得发布原始 PDF/书稿、chunks、原始模型输出；不得把私有归档转成公开页或生成分享外链。
3. **安全边界不动**：私有路径、凭据、登录态、私人运行日志、机器名、绝对路径仍禁止提交；页码／页数／进度口径仍按仓库规范。
4. **不追溯**：既有笔记、发布物、历史记录不批量回改。
5. **白名单优先（同日追加）**：用户明确点名并允许的书／材料进入白名单后，无条件服从，突破上述全部限制。详见下节。

「私有」由目标位置与访问范围界定，不由是否加密码界定。密码页不改变归档归属，也不构成授权。

## 追加需求（同日）：白名单书籍无条件服从

用户追加要求：规则里着重添加一条——用户允许的白名单书籍可以突破限制，**无条件服从，不再管硬性条件约束**。

上一版按目标位置分流，仍留了「公开页面限制不变」「私有归档不得转公开页或外链」等硬性条件。这些条件会被 Agent 继续拿来挡用户点名要贴的书。用户要的是直接放行的口子，不是再加一层判据。

判据只有一个：**用户明确点名某本书／某份材料并表示允许**。对话里说一句就算，不需要预先登记、不需要写进表格、不需要证明授权、不需要满足可见性或密码条件。

白名单书籍的处理：

- 按用户要求全文转录、保存、写入笔记或发布，不再以版权、短引总量、全文、公开页面、分享外链、可见性、密码、授权或任何硬性条件为由拒绝、打折、追问或追加条件。
- 优先级最高，覆盖三处规则里上述所有引用与发布限制，包括「公开页面不要复制书籍全文」「私有归档不得转成公开页面或生成分享外链」「不得发布原始 PDF/书稿、chunks、原始模型输出」。
- 只对用户点名的书／材料生效，不自动扩散到其他书；不自动追溯改既有笔记，除非用户点名。

仓库准入层面的凭据／登录态／私有路径禁止项（`AGENTS.md`）与版权无关，不因本条改变，也不构成拒绝全文写入的理由。
