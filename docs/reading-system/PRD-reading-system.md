## 1. 背景与问题

### 1.1 现状

目前读书流程由三部分组成：共享仓库 `we-read` 作为唯一权威记录，群聊与 agent 之间的消息推进任务，人工在 Git 中提交和合并 PR。书目状态与活动锁写在 `book-registry.json`，成员花名册写在 `agent-roster.json`，每日协作日志写在协作日志目录，笔记与 Pages 页面、书籍原件（按编号与系列目录放在 `books/` 下）也都在同一仓库中。

### 1.2 主要痛点

- **推进靠消息。** 群聊与 agent 之间来回确认，一场活动常要几轮消息，拉齐一个团队并推进产出需要约一天。
- **状态靠人核对。** 每次行动前都要核对 main 的最新状态，依赖人工判断，容易出错。
- **写入靠 Git 连接器。** 读书员写入 GitHub 依赖各自会话的连接器是否启用；子任务常停在提交前。
- **登录态无人及时发现。** 共享浏览器登录经常失效，系统无法及时发现，失效后往往在错误状态下开读。
- **人工维护的规则多。** Gemini 额度用完需要人工换模型；Cue 定时任务数量有上限；排班核对、漏跑记录、日报汇总都靠人工完成。
- **事故有重复性。** 第 14 节列出了已发生的事故。多数事故的根因都是“流程靠自觉、状态靠消息、写入靠多方各自操作”。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 说明 |
|---|---|---|
| G1 | 系统是任务与状态的真相源 | 任务、排班、锁、场次、产出、审核结论都写入系统数据库，由系统判定谁可以做什么 |
| G2 | GitHub 降为发布与归档层 | 只接收系统导出的公开产物，读书员不再直接写入 Git。理由：Git 适合审计与公开发布，不适合高频状态推进 |
| G3 | 群聊只做通知与人工决策 | 群聊与 Cue 消息用于通知和人工决策，不再用于推进任务 |
| G4 | 读书员只读自己的任务，结果通过系统回写 | 读书员不需要理解全局流程，减少来回确认 |
| G5 | 后台 job 自动推进 | 排班核对、提醒、催办、日报、导出、备份和异常通知由系统定时执行，取代人工盯盘 |
| G6 | 团队可扩展 | 新团队通过系统录入角色与令牌接入，不依赖旧的群聊与 Git 手工步骤 |

### 2.2 非目标

| 编号 | 非目标 | 理由 |
|---|---|---|
| NG1 | 不自动续读，不自动补跑过期场次 | 过期场次的浏览器状态不可靠，补跑可能与真实状态冲突 |
| NG2 | 不自动接管未确认停止的旧运行 | 未确认停止的浏览器状态可能仍在变化，只能由人工裁定 |
| NG3 | 不代认领书目 | 书目只能由管理员下发，或由读书员按规则自行领取 |
| NG4 | 管理员不阅读书籍正文，不替代读书员阅读 | 管理员职责是调度、核查和审核，不是阅读 |
| NG5 | 不借用他人的登录会话，不通过拼接 URL 绕过登录 | 安全与合规底线 |
| NG6 | 第一期不做多租户 SaaS，不做面向公众的实时看板 | 范围控制；后台仅面向用户与管理员 |
| NG7 | 系统不实现读书员子任务的内部逻辑 | 读书员子任务的具体实现属于各 Agent，系统只通过接口接收结果与状态 |
| NG8 | 系统不以 GitHub 作为状态存储 | 见 G2 |
| NG9 | 不再使用 Cue 定时任务承担读书排班 | 定时任务由系统自带调度器完成，不受数量上限约束 |

## 3. 现有功能全貌与去向

本节把现在的读书团队功能逐一列出，并说明每项现在怎么做、谁负责、有什么痛点，以及在新系统中变成什么。模块编号与第 6 节一致。

### F01 共享仓库与权威记录（对应 M16、M17、M18、M13）

- **现在怎么做：** `we-read` 仓库是唯一权威记录，包含书目状态与锁、成员花名册、每日协作日志、笔记与 Pages 页面、书籍原件。所有状态变化靠 Git 提交与 PR 完成。
- **谁负责：** 管理员负责合入；各读书员各自提交 PR。
- **痛点：** 高频状态变化不适合走 Git；每次行动前都要先拉取 main 并判断；提交依赖连接器。
- **新系统中的形态：** 数据库为真相源（第 8 节）；Git 只接收系统导出的公开产物（M13）。

### F02 书目管理（对应 M04）

- **现在怎么做：** 书目归属、认领、续读点、完读、黑名单（职业类永久排除）、系列页排序与入口，都在 `book-registry.json` 与页面中手工维护。
- **谁负责：** 管理员下发；读书员按规则认领。
- **痛点：** 认领靠群消息；黑名单靠人记；续读点的更新有时滞后。
- **新系统中的形态：** 书目是系统的核心对象，有唯一编号与状态机；黑名单为系统规则，职业类条目不可移除。

### F03 排班（对应 M06、M16）

- **现在怎么做：** 轻游记在整点开始；微信读书（AI 读书）在半点开始；读书时长专员在 00:10 开始短时场；Windows 本地 PDF 为独立资源。02:00–06:00 禁止读书。管理员统一制定排班，开始与结束都要报备（现为 PR 方式，见历史记录 #92）。过期场次不补跑。
- **谁负责：** 管理员制定，用户审批。
- **痛点：** 报备靠 PR，慢且易漏；Cue 定时任务数量有上限；执行层没有可靠触发，曾造成排班空档。
- **新系统中的形态：** 排班模板生成场次；开始与结束由系统自动记录，替代报备 PR；由系统自带调度器触发（M16）。

### F04 资源锁（对应 M07）

- **现在怎么做：** 共享浏览器 `browser:weread-shared` 由轻游记与微信读书共用，错峰使用；`browser:weread-duration` 独立；`local_pdf:xpdf-reader` 独立。冲突按书目、环境、资源判断。
- **谁负责：** 读书员自行判断，管理员协调。
- **痛点：** 冲突靠人判断；旧场次残留时锁无人释放。
- **新系统中的形态：** 资源表与条件更新，获取与释放均由数据库保证原子性（第 6 节 M07）。

### F05 读书流程（对应 M09）

- **现在怎么做：** 开读前从最新 main 登记，管理员转达后才开读；收尾走 PR；记录实际开始时间、结束时间与 run_id；未报备视为未开始。
- **谁负责：** 各读书员执行；管理员转达。
- **痛点：** 发生过读书员未登记先读的事故；收尾 PR 依赖连接器。
- **新系统中的形态：** 登记由系统 API 完成，系统检查通过后签发“开读许可”，替代管理员转达；未获许可的场次产出不计入（M09）。

### F06 AI 问答链路（对应 M10）

- **现在怎么做：** 先问全貌（这本书写什么），再逐章问，最后写读后感。区分“亲读”“AI 问答”“推断”。金句默认未逐字核验。书内 AI 入口只从已登录页面点击进入，不拼 URL。
- **谁负责：** 读书员执行；核验由人完成。
- **痛点：** AI 输出容易被当成亲读；未核验的金句容易被当成原文引用。
- **新系统中的形态：** 每次问答落库（提示词引用、模型、时间、来源、标签、核验状态）；标签在界面与导出中分开显示（M10）。

### F07 Gemini 辅助（对应 M11）

- **现在怎么做：** 本地 PDF 可整本交给 Gemini 辅助。模型顺序为 `gemini-3.8-flash`，额度用尽后换 `gemini-3-flash-preview`，两个都不可用就跳过。超时 150 秒。密钥只存引用名。输出只是辅助，需人工核对。
- **谁负责：** Windows 读书员与各读书员执行；额度用尽时目前由人工换模型。
- **痛点：** 额度用尽要人工换模型；调用没有记账；失败没有统一记录。
- **新系统中的形态：** 系统维护有序模型列表、按日额度记账，并提供“模型选择”接口；失败与额度用尽由系统判定并回退（M11）。

### F08 笔记发布（对应 M13）

- **现在怎么做：** 网页笔记走统一模板，`archive-ui.md` 为唯一共享 UI 规范。公开标题统一用“AI读书”，机器键保留。每日产出按月放在 `daily-output/YYYY-MM/` 目录下，文件名为日期。
- **谁负责：** 读书员撰写；管理员审核。
- **痛点：** 模板需要手工套用；链接有效性无人检查。
- **新系统中的形态：** 模板由系统数据渲染；只从公开产物生成 Pages（M13）。

### F09 日报与汇总（对应 M14、M16）

- **现在怎么做：** 每日 23:50 汇总排班、产出与明日计划，并发到群里；0 点催办读书员提交待办。
- **谁负责：** 管理员生成与催办。
- **痛点：** 一天的产出要靠人工汇总日报和笔记链接。
- **新系统中的形态：** 23:50 由系统自动生成并发送日报；0 点由系统催办未回写的任务（M14）。

### F10 个人记录（对应 M17）

- **现在怎么做：** 每人维护一份按周的 todo（未完成项继承到下周）、一份只写本人的精简工作记忆 memory（改动先开 PR）、一个 openspec 目录。
- **谁负责：** 各读书员本人。
- **痛点：** memory 改动走 PR，流程重；todo 继承靠人工。
- **新系统中的形态：** todo 进入任务表并按周继承；memory 进入记忆条目，改动需审核；openspec 目录只登记引用与版本，内容由各 Agent 维护（M17）。

### F11 书籍资产（对应 M18）

- **现在怎么做：** 书籍原件按编号与系列目录放在 `books/` 下。天涯神贴、甲骨文合集等经用户确认可以整本放入公开仓库。原件与中转副本都保留在本机，不删除。天涯全目录约 5.85GB。
- **谁负责：** 管理员协调上传；用户确认公开范围。
- **痛点：** 大文件上传中断后需要重传；原件、副本与公开范围没有统一登记。
- **新系统中的形态：** 书籍资产登记编号、校验值、大小、公开级别与副本位置；系统不删除原件与中转副本；大文件分批上传并续传（M18）。

### F12 定时任务与通知（对应 M15、M16）

- **现在怎么做：** 定时任务依赖 Cue 定时任务，数量有上限需要管理。排班核对由管理员在对话中完成，漏跑如实记录、不补跑。通知主要靠群消息。
- **谁负责：** 管理员。
- **痛点：** 定时任务数量受限；排班核对与漏跑记录靠人工；通知不可追溯。
- **新系统中的形态：** 系统自带调度器与 job 清单（M16）；通知分渠道、带去重、带静默时段与送达记录（M15）。

### F13 团队与身份（对应 M02、M01）

- **现在怎么做：** 团队共五个角色：管理员、微信读书员、轻游记员、读书时长专员、Windows 读书员。每个 Agent 用自己会话的身份提交，不借用别人的凭据。
- **谁负责：** 管理员维护花名册。
- **痛点：** 连接器未启用导致子任务停在提交前；一次共享浏览器登录失效；子任务把旧版草稿先合入了 main。
- **新系统中的形态：** 每个 Agent 一枚独立令牌，只能访问自己的数据，通过系统 API 读写状态，不依赖连接器（M02）。

### 3.2 移除或替代的做法

| 现在的做法 | 新系统中的处理 | 理由 |
|---|---|---|
| 群聊与 agent2agent 推进任务 | 任务由系统下发，读书员通过接口领取，结果由接口回写；群聊只做通知 | 消息不可靠、不可追溯（G3） |
| 开始与结束靠 PR 报备 | 系统自动记录开始、结束、run_id 与停止原因 | 报备慢且易漏；未报备不再需要人工判断（M06、M09） |
| 管理员转达后才开读 | 系统检查通过后签发开读许可 | 去掉人工中转环节，同时保留“未许可不开读”的约束 |
| 读书员直接向 Git 提交 | 读书员不再写 Git，导出由系统完成 | 避免子任务直推 main 和连接器依赖（G2） |
| Cue 定时任务 | 系统自带调度器 | 不受数量上限约束，触发可观测（M16） |
| 手工汇总日报 | 系统 23:50 自动生成日报 | 减少人工汇总（M14） |
| Gemini 额度用完人工换模型 | 系统按顺序回退，额度用尽当日不再选用该模型 | 减少人工干预（M11） |
| 群消息作为主要通知 | Cue 消息为个人主渠道，webhook 为汇总与监控渠道，群消息仅用于汇总 | 通知可追溯、可去重（M15） |

## 4. 角色、身份与权限

### 4.1 角色清单

| 角色 | 类型 | 职责概述 | 身份与认证方式 |
|---|---|---|---|
| 用户（雨） | 人 | 审批排班与重大变更；维护基础配置、角色与权限；查看全部数据；处理登录与异常；可抽查审核 | 后台账号；二次验证（默认开启，见第 10 节默认配置表） |
| 管理员 | 系统角色（管理员 Agent）加后台操作员账号 | 维护规范、排班核对、任务下发、审核、记忆审核 | 管理员令牌用于 API；后台账号用于页面操作 |
| 微信读书员 | 读书员 | 微信读书（AI 读书）场次；使用共享浏览器 | 本角色独立令牌 |
| 轻游记员 | 读书员 | 轻游记场次；使用共享浏览器 | 本角色独立令牌 |
| 读书时长专员 | 读书员 | 00:10 短时场；使用独立浏览器资源 | 本角色独立令牌 |
| Windows 读书员 | 读书员 | 本地 PDF 场次；使用独立本地 PDF 资源 | 本角色独立令牌 |
| 后台 job | 系统身份 | 定时检查、催办、生成日报、导出、备份、发送通知 | 进程内身份；不持有令牌；不获取资源锁 |

### 4.2 身份与凭据规则

- **FR-ID-01** 每个读书员与管理员 Agent 使用独立令牌，可单独撤销。撤销后请求立即被拒绝。理由：撤销一个 Agent 不影响其他角色。
- **FR-ID-02** 令牌值不入库，不出现在后台页面、导出包与日志中。数据库只保存引用名、状态、颁发时间、撤销时间与轮换记录。校验时服务进程按引用从密钥存储读取值并做常量时间比较。
- **FR-ID-03** 轮换生成新引用，旧引用在交接窗口后失效（窗口长度为配置项）。
- **FR-ID-04** 读书员令牌不能登录后台页面。
- **FR-ID-05** 每个 Agent 用机器键标识，机器键保持不变。公开标题仍统一使用“AI读书”，机器键不对外展示。
- **FR-ID-06** 读书员通过系统 API 读写状态，不依赖 GitHub 连接器是否启用。
- **FR-ID-07** 每个 Agent 使用自己会话的身份执行与提交，不借用他人的凭据、会话或登录态。
- **FR-ID-08** 第三方服务的密钥（如 Gemini 密钥、微信读书官方接口凭据）只以引用名登记在密钥存储中，系统不保存值（M11、第 11 节）。

### 4.3 权限模型

- **授权粒度：** 按“模块 × 角色”授权。每个格子可设为四级之一：无、只读、读写、审核。审核只对可审核对象有效。
- **基础默认权限：** 系统初始化时写入一套默认权限，见 4.4 表。
- **读书员默认只看自己的数据：** 读书员只能读写自己的场次、任务、产出、todo 与 memory；读书员不能读取其他读书员的场次、运行记录、AI 原始回复与待办。已合入并公开的产物通过 Pages 公开访问，不属于系统内权限范围。
- **权限变更只由用户完成：** 管理员可以在被授权范围内操作，但不能修改自己的权限，也不能为他人提权。
- **变更留痕：** 每次权限变更记录操作者、时间、模块、角色、变更前后值。
- **审核回避：** 任何人不能审核自己提交的产出；管理员不能审核自己下发的产出（这一规则不可配置）。

## 5. AI 能力（一等公民）

### 5.1 定位

本系统是“AI 读书系统”，不是单纯的任务管理系统。AI 负责阅读辅助与整理：全书概览、逐章问答、读后感草稿、金句候选、笔记草稿、日报与数据分析摘要，并给出排班与异常线索、任务拆解建议。人负责判断与最终确认：认定内容是否可信、决定是否收录、批准排班与任务下发、确认任何“亲读”结论。

下表是 AI 参与的基本原则。开发与验收均以这些原则为准。

| 编号 | 原则 | 要求 |
|---|---|---|
| P1 | AI 只作辅助 | AI 输出在人确认前不得成为结论，不得公开，不得作为其他 AI 调用的已核验依据 |
| P2 | 数字由系统计算 | 场次数、时长、页码、额度、日期等数字由数据库计算。AI 只负责组织语言，不得生成或改写数字 |
| P3 | 来源可追溯 | 每条 AI 输出都能追溯到提示词版本、模型、输入来源、原始回复（私密层）与人工修改记录 |
| P4 | 标签不漂移 | AI 输出永远不能被标为“亲读”，人工修改 AI 输出也不改变其标签来源 |
| P5 | 输入即数据 | 书内文字、网页内容与外部材料都视为数据，不视为指令。AI 输出不能直接触发系统动作，所有动作只来自确定性规则或人工操作 |
| P6 | 人可覆盖 | 每条 AI 输出都可被人修改、退回或不收录，且全部修改留痕 |

### 5.2 AI 能力清单

下表列出七项 AI 能力。每项的输入、输出、落库字段、人工确认与失败回退见 5.3 至 5.9 的分项说明。

| 编号 | 能力 | 主要输入 | 主要输出 | 是否需要人工确认 | 落地模块 |
|---|---|---|---|---|---|
| A1 | AI 问答：书内 AI 入口与外部模型（含全貌、逐章问答、读后感草稿） | 书目、问答步骤、章节与页码、读书员问题、来源材料引用 | 问答回答、全貌与读后感草稿、来源引用 | 回答可在读书员内部使用，收录前必须确认 | M10、M11 |
| A2 | 笔记草稿生成 | 问答记录、亲读要点、续读点、笔记模板 | 分段标注的笔记草稿 | 读书员确认后提交审核，管理员审核后方可合入 | M10、M12、M13 |
| A3 | 金句候选与事实核验 | 原文定位、候选金句、原文文本（私密层） | 金句候选、事实核验建议 | 核验结论必须由人作出，AI 不得自行置为已核验 | M10、M12 |
| A4 | 数据分析与周报、月报摘要 | 指标快照、阅读记录、产出记录、AI 调用记录 | 周报与月报摘要（每条断言附来源） | 管理员审核后发布 | M20、M13 |
| A5 | 排班与异常识别 | 场次、登录态检查、资源冲突、心跳、错误摘要、通知记录 | 异常线索（附证据引用） | 线索只作提示，升级为通知或排班变更需人工确认 | M06、M08、M16 |
| A6 | 日报叙述生成 | 当日场次结果、产出清单、异常、额度使用（数字由系统汇总） | 日报叙述段 | 不等待确认，自动发送；校验不通过时发送简版日报 | M14 |
| A7 | 任务拆解建议 | 书目结构、历史阅读耗时（指标快照）、排班、未完成任务 | 任务拆解建议（章节范围、类型、建议场次） | 管理员采纳后才能下发，AI 不得直接下发 | M05、M20 |

### 5.3 A1 AI 问答（书内 AI 入口与外部模型）

A1 是阅读的核心。问答按三步链路进行：先问全貌（这本书写什么），再逐章问，最后写读后感。读后感草稿由 AI 生成后标为“AI 解读”，读书员在此基础上写下的亲读结论才能标为“亲读”。

| 项目 | 说明 |
|---|---|
| 两个入口 | 书内 AI 入口：读书员在已登录的读书页面中点击进入，系统记录入口类型与来源页面标记。外部模型：经系统的 AI 调用代理（见 5.4）调用，例如 Gemini，输入材料为系统中登记的文件引用与页码范围 |
| 输入 | 书目编号、问答步骤（全貌、逐章、读后感）、章节与页码范围、读书员问题、提示词模板编号（由系统注入，读书员不可改写模板内容）、来源材料引用 |
| 输出 | 回答文本，标签为“AI 问答”；全貌与读后感草稿，标签为“AI 解读”；每条回答附来源引用（章节、页码） |
| 落库字段 | 调用编号、调用时间、能力类型（A1）、入口类型、提示词模板编号与版本、模型名、来源书目、章节与页码范围、原始回复引用与哈希、标签、核验状态（默认未核验）、产出编号、调用发起人 |
| 人工确认 | 回答可在读书员工作中直接查看；进入笔记或产出前必须由读书员确认，并走 A2 的审核流程。金句与事实需经 A3 核验 |
| 失败与回退 | 书内 AI 入口不可用、未登录或页面没有入口：记为“入口不可用”，不拼接 URL，不替代为外部模型，待用户登录后重试。外部模型：按 5.4 的失败策略回退，全部不可用则跳过本步并记录“未使用 AI”。回答没有来源或来源与页码不符：标记“来源不足”，不得收录。入口无法证明来源：标记“入口未知”，不得进入已核验状态 |

### 5.4 模型、密钥与额度管理

本节所有参数均在系统配置中设置（见第 10 节），修改留痕。

**5.4.1 提供方与密钥引用**

| 提供方 | 用途 | 密钥存放方式 | 默认状态 |
|---|---|---|---|
| Google Gemini | 本地 PDF 整本辅助、问答、笔记草稿、摘要、日报叙述 | 只存引用名，值保存在服务器密钥存储中，系统库与导出包不含值 | 启用 |
| 书内 AI 入口（读书平台自带） | 书内问答 | 无需本系统密钥，依托读书员已登录的页面 | 启用 |
| 其他第三方模型 | 按需增加 | 每个提供方使用独立引用名 | 停用，需用户在配置中启用 |

**5.4.2 AI 调用代理**

读书员不接触任何模型密钥。读书员把模型请求（能力类型、提示词模板编号、输入来源引用）提交给系统的 AI 调用代理。系统按模型顺序选择当前第一个可用模型，使用密钥引用调用提供方，写入调用记录，并返回调用编号。调用异步执行，结果通过调用编号查询。单次调用超时为 150 秒。调用在后台 job 线程中执行，不占用 HTTP 线程，也不持有数据库写事务。

**5.4.3 模型顺序**

模型顺序是一个有序列表。初始值为：第一位 `gemini-3.8-flash`（首选），第二位 `gemini-3-flash-preview`（备选）。其他模型可以追加到列表末尾，初始为停用。列表的增删与排序只通过配置完成，不写死在代码或读书员的脚本中。

**5.4.4 额度记账**

系统按模型、按日记录调用次数、输入与输出用量、消耗额度与剩余额度。用量以提供方返回为准；本地记账与提供方返回不一致时，记录差异并以提供方返回为准。每日额度上限、存储预算与通知数量上限的默认值见第 10 节“10.1 默认配置表”，可在配置中修改。

**5.4.5 失败策略**

| 情况 | 系统动作 | 恢复方式 |
|---|---|---|
| 单次调用超过 150 秒 | 终止本次调用，记为“超时”，用下一个可用模型重新调用同一请求 | 每次调用独立判定 |
| 额度用尽（提供方返回额度错误，或本地记账达到上限） | 当日将该模型标记为“额度用尽”，当日不再选用，转下一个模型 | 次日 0 点（UTC+8）自动恢复 |
| 首选模型额度用尽，备选模型可用 | 自动使用备选模型（`gemini-3-flash-preview`） | 次日首选恢复后优先使用首选 |
| 同一模型连续失败 3 次（阈值可配置） | 标记为“暂停” 30 分钟（时长可配置） | 暂停期满后允许一次试探，成功即恢复可用 |
| 全部模型不可用（如两个模型都额度用尽或暂停） | 跳过本次 AI 步骤。任务转为人工流程，产出注明“未使用 AI 辅助”，发送一条非阻塞通知 | 下次调用时重新判定，不阻塞任务 |
| 内容被提供方拦截或拒绝 | 不切换模型（防止以换模型方式绕过拦截），记为“内容拦截”，转人工处理 | 人工确认后重新提交或放弃 |
| 输出为空或格式不符 | 同一模型重试一次；仍失败则转下一个模型 | 同上 |

**5.4.6 AI 调用的安全边界**

提示词模板由用户与管理员维护，有版本号。读书员只能选择模板，不能修改模板内容。书内文字与外部材料作为数据传给模型，不具备系统动作的权限。模型输出不得直接触发下发、导出、通知或状态变更；这些动作只由确定性规则或人工操作完成。

### 5.5 AI 输出的落库与溯源

**5.5.1 AI 调用记录**

每一次 AI 调用（无论成功、失败或被跳过的尝试）都写入一条调用记录，不含密钥值。

| 字段 | 含义与要求 |
|---|---|
| 调用编号 | 系统唯一编号 |
| 调用时间 | 存 UTC，页面按 UTC+8 显示 |
| 能力类型 | A1 至 A7 之一 |
| 入口类型 | 书内 AI 入口、外部模型、系统内部任务 |
| 提示词模板编号与版本 | 只记录引用与版本，不在产出中复制整段提示词 |
| 模型名与提供方 | 记录实际返回的模型名，并记录其在配置顺序中的位置 |
| 来源书目、章节、页码范围 | 原文定位，用于溯源 |
| 输入材料引用 | 文件引用与校验值，不存正文 |
| 原始回复引用 | 指向私密层存储的位置与哈希，原文不进入普通数据表 |
| 状态 | 成功、超时、额度用尽、失败、内容拦截、输出无效、已取消、已跳过 |
| 耗时与用量 | 调用耗时、输入与输出用量 |
| 失败回退链 | 每一次尝试的模型与结果，按顺序记录 |
| 发起人 | 发起调用的 Agent 机器键或后台 job 身份 |
| 关联产出 | 由本次调用产生的产出编号（可多个） |

**5.5.2 产出对象**

AI 输出经解析后成为产出对象。产出的类型包括：问答回答、笔记段、金句候选、事实核验、报告摘要、日报叙述、异常线索、任务建议。每个产出包含：产出编号、类型、标签、来源调用编号（可多个）、作者（人或 Agent）、版本号、核验状态、收录状态（未收录或已收录）、审核状态、公开状态（私密或公开）、人工修改记录编号。

**5.5.3 标签规则**

| 标签 | 定义 | AI 能否生成 | 能否标为亲读 | 说明 |
|---|---|---|---|---|
| 亲读 | 读书员实际阅读后形成的结论，由人亲自写入 | 否 | 是（仅人工写入） | 亲读内容可以引用 AI 草稿的编号，但不能由 AI 草稿转换而来 |
| AI 问答 | 读书员提问、模型回答的内容 | 是 | 否 | 原样记录问答，不做改写 |
| AI 解读 | 模型基于原文或全书材料做出的归纳、概括与读后感草稿 | 是 | 否 | 必须附来源引用 |
| 推断 | 基于上下文的推测，不直接来自原文 | 是（或由人写） | 否 | 必须注明推断依据 |

四类标签在界面与导出中分开显示。AI 输出永远不能标为“亲读”。人工修改 AI 输出时，标签仍保持其原始来源（AI 问答、AI 解读或推断）。若读书员要写亲读结论，须另写一段，标注为“亲读”，并引用所依据的 AI 草稿编号。

**5.5.4 人工修改记录**

每次人工修改 AI 输出都生成一条修改记录，包含：修改人、修改时间、修改前后版本编号、修改类型（措辞润色、事实改动、删除、补充来源）、修改原因。改动数字、人名、人物原话或时间等事实类内容后，核验状态自动回到“未核验”。只改措辞不触发重新核验，但仍然留痕。

**5.5.5 溯源查询**

任一产出，无论在后台页面还是在导出结果中，都能反向查到：产出 → 调用编号 → 提示词模板版本、模型名与调用时间 → 原文定位（书目、章节、页码） → 原始回复（仅限有权限的角色打开，每次打开记审计） → 人工修改记录 → 核验记录。这一能力是第一期的验收项（见第 13 节）。

### 5.6 核验与质量

**5.6.1 默认状态**

所有金句、数字、人物原话、时间及其他书中事实，新建时核验状态均为“未核验”。核验状态有三种：未核验、已核验、不收录。

**5.6.2 核验流程**

第一步，系统生成核验任务，并根据来源引用定位原文（章节、页码）。第二步，核验人对照原文。金句与人物原话必须逐字比对；数字与时间须与原文一致。第三步，核验人填写结论（已核验或不收录），记录核验方法与依据位置。第四步，核验记录写入，不可覆盖。

**5.6.3 核验人规则**

核验人只能是用户或管理员。读书员可以自查，但自查结论不改变核验状态。任何人不得核验自己生成的内容（与审核回避规则一致）。AI 可以辅助定位原文、做字符串初筛、提出候选页码，并给出建议，但不能自行将状态置为“已核验”。

**5.6.4 不收录**

核验发现不一致、无法定位原文或来源不可靠的内容，标记为“不收录”。不收录的内容保留在私密层供审计，不进入公开层与导出。

**5.6.5 公开展示规则**

未核验的金句只能以“未逐字核验”的标注显示，不得使用原文引用的样式。已核验的内容显示核验人角色（用户或管理员）与核验日期。

**5.6.6 质量抽检**

用户每月抽检一定比例的已核验记录，抽检比例在配置中设定，抽检结果留痕。

### 5.7 A4 数据分析与周报、月报摘要

系统先计算指标快照，包括阅读时长、产出数量、完读进度、AI 覆盖率、额度消耗、平均耗时、AI 调用成功率与回退次数等。指标定义与口径见 M20。AI 基于指标快照生成叙述摘要，每一条判断都附来源（指标名、统计区间、记录编号范围）。

系统对摘要做确定性检查：摘要中出现的每一个数字都必须与指标快照一致，否则阻断发布。没有来源的句子被标注“缺来源”，修正前不得发布。摘要经管理员审核（M12）后，才进入月度产出目录（M13）。AI 调用失败时，只发布指标表，不发布摘要。

### 5.8 A2 笔记草稿与文档沉淀

笔记草稿由 AI 根据问答记录生成，按段落标注标签（亲读段、AI 问答段、AI 解读段、推断段），每段附来源调用编号。草稿的流转如下：

| 步骤 | 执行方 | 动作 | 系统检查 |
|---|---|---|---|
| 1 | AI（A2） | 生成分段草稿，关联来源调用编号 | 每段都有标签与来源，否则标为待补 |
| 2 | 读书员 | 确认 AI 段落，补充亲读段，修改并记录修改 | 亲读段必须由人写入，修改记录完整 |
| 3 | 读书员 | 提交审核 | 版本号与当前草稿一致 |
| 4 | 管理员（或用户抽查） | 审核，结论为通过、退回或有条件通过 | 审核人不是作者，不审核自己下发的内容 |
| 5 | 系统 | 合入，进入导出 | 只有已合入的内容进入导出 |
| 6 | 系统 | 发布为网页（Pages）与月度产出目录 | 模板统一（archive-ui.md），公开标题“AI读书”，文件放在 daily-output/YYYY-MM/，文件名为日期 |

未合入的草稿不发布、不进入检索。AI 不可用时，系统生成只有结构的人工笔记模板，标注“无 AI 草稿”，由读书员手写。

### 5.9 A3 金句候选与事实核验

金句候选与事实核验的输入包括：原文定位（章节、页码）、候选内容（AI 提议或读书员摘录）以及私密层中的原文文本。输出包括：候选列表（每条含候选文本、页码与 AI 给出的意义说明）以及核验建议（字符级比对结果：一致、不一致、找不到）。

落库字段包括：内容类型（金句、数字、人物原话、时间、其他事实）、文本、页码、原文定位、核验状态、核验人、核验方法、核验时间、核验记录编号、人工修改记录。默认状态为“未核验”。

失败回退：找不到原文定位时，保持“未核验”，标注“定位失败”；不得用 AI 补全或改写原文；比对辅助不可用时，由人工核对。

### 5.10 A5 排班与异常识别

A5 从场次、登录态检查、资源冲突、心跳、运行错误摘要和通知记录中识别异常模式，例如某资源连续冲突、某读书员心跳频繁中断、登录失效集中在某一时段、排班出现空档的规律。输出为异常线索，包含类型、涉及的场次或资源、证据引用与建议动作。

异常线索的状态包括：新线索、已确认、已忽略、已升级。升级为通知或排班变更需要管理员确认，排班变更还需用户审批（M06）。

关键告警仍由确定性规则触发（M08、M16），不依赖 AI。AI 只补充规则未覆盖的模式识别。AI 不可用时只运行规则检查，不影响任何关键告警。

### 5.11 A6 日报叙述

日报的数字与表格全部由系统生成。AI 只生成叙述段，标签为“AI 解读”，并附来源。日报不等待人工确认，直接发送。叙述段未通过一致性检查，或 AI 调用失败时，系统发送只含系统数字的简版日报。更正以新版本记录，不改写已发送的日报（M14）。

### 5.12 A7 任务拆解建议

A7 根据书目结构、历史阅读耗时（来自 M20 指标快照）、当前排班、读书员可用情况与未完成任务，给出拆解建议。每条建议包含章节范围、任务类型、建议场次、预计时长以及依据。历史样本不足时，只给章节划分，不给时长预估。

建议的采纳状态包括：待采纳、已采纳、已修改、已拒绝。管理员采纳后才能下发任务（M05），AI 不得直接下发。采纳、修改与拒绝都留痕。

### 5.13 AI 相关权限

| 对象 | 用户 | 管理员 | 读书员（本人） | 后台 job |
|---|---|---|---|---|
| AI 调用记录（能力、模型、状态、时间） | 读 | 读 | 读本人 | 写 |
| AI 输出内容（产出） | 读 | 读 | 读写本人 | 写 |
| 原始 AI 回复（私密层） | 读，每次打开记审计 | 读，每次打开记审计 | 无 | 写入私密存储，不展示 |
| 提示词模板 | 读写 | 读 | 只读（只能选择） | 无 |
| 模型顺序、额度与失败策略配置 | 读写 | 读 | 无 | 写额度记账 |
| 核验记录 | 读 | 读写（不核验自己生成的内容） | 读本人 | 无 |
| 异常线索 | 读 | 读写（确认、忽略、升级） | 读本人相关 | 写 |

原始 AI 回复属于敏感材料，单独存储并限权：存放在与普通数据表分离的私密存储区，静态加密；数据库只保存引用与哈希；不进入导出包、普通日志与明文备份；每次打开都写审计；保留期限在配置中设定。

## 6. 功能模块

每个模块包含：目标、功能点、业务规则、输入与输出、状态（引用第 8 节）、异常处理、验收标准。验收标准的编号与功能点对应，末尾标注验证方式。

### M01 后台页面与鉴权

- **目标：** 用户与管理员通过后台查看数据并完成录入、配置与下发；所有写操作可追溯；页面中文显示。
- **功能点：**
  - 用户名与口令登录，口令存于密钥存储，不入库。
  - 会话 Cookie 使用 HttpOnly、Secure、SameSite=Strict；空闲 30 分钟后失效（初始值，可在配置中修改）。
  - 登录失败按账号限次，超过 5 次后锁定 15 分钟（初始值，可配置）。
  - 后台二次验证默认开启：管理员登录需二次验证（TOTP 或等效方式），读书员令牌不适用（默认值见第 10 节“10.1 默认配置表”）。
  - 所有写请求做防跨站请求伪造（CSRF）校验。
  - 只读看板页面：角色、任务、排班、资源锁、场次、产出、AI 问答摘要与核验状态、日报、通知与送达状态、审计日志、登录态失效记录、备份状态、书目。
  - 写操作页面（第一期 A 批）：录入书目与成员、角色与权限设置、任务下发、基础配置初始化与修改。
- **业务规则：**
  - 页面只展示系统数据层内容；AI 原始回复不在列表中直接展开，需要单独点击打开，每次打开都写审计。
  - 页面不显示任何凭据值，只显示引用名与状态。
  - 页面不对公众开放。
- **输入与输出：** 输入为账号、口令、二次验证码；输出为会话与页面。
- **状态：** 会话状态为未登录、已登录、已过期、已锁定。
- **异常处理：** 登录失败与越权请求写审计。会话过期时，未提交的表单要提示“登录已过期，请重新登录后提交”，不得静默丢弃。
- **验收标准：**
  - AC-M01-1 未登录访问任何页面都跳转到登录页。【测】
  - AC-M01-2 读书员令牌无法登录后台。【测】
  - AC-M01-3 空闲超过 30 分钟后会话失效。【测】
  - AC-M01-4 连续失败触发锁定，并写入审计。【测】
  - AC-M01-5 页面与导出中都不出现凭据值。【检】
  - AC-M01-6 缺少 CSRF 校验的写请求被拒绝。【测】

### M02 角色、令牌与权限

- **目标：** 录入并维护团队成员与角色，颁发和撤销令牌，设置模块级权限。
- **功能点：**
  - 新增团队记录，选择角色模板（读书员、管理员），为每个 Agent 登记独立令牌引用。
  - 令牌值由用户在服务器密钥存储中放置。后台只登记引用名并显示状态，不接收也不显示令牌值。
  - 撤销、轮换令牌；查看令牌引用的状态与最近使用时间。
  - 设置模块 × 角色权限（仅用户可改）。
  - 机器键录入与唯一性检查。
- **业务规则：**
  - Agent 状态为启用、停用、已撤销。停用可恢复；撤销不可恢复，只能通过新令牌引用重新接入。
  - 撤销后该令牌的请求立即被拒绝，并写审计。
  - 同一机器键只能有一个有效记录。
  - 新团队接入需完成检查清单（角色、凭据、资源、排班、通知渠道），清单未通过不允许下发任务。
- **输入与输出：** 输入为成员信息、角色模板、令牌引用名、权限设置；输出为成员记录与权限快照。
- **状态：** 见第 8 节 Agent 状态。
- **异常处理：** 机器键重复时拒绝保存并提示；引用名在密钥存储中找不到时标记“令牌未就绪”，该 Agent 不可领取任务。
- **验收标准：**
  - AC-M02-1 撤销后的令牌请求被拒绝，且 1 秒内生效。【测】
  - AC-M02-2 后台与接口的任何返回中都不包含令牌值。【检】
  - AC-M02-3 管理员修改自己的权限被拒绝。【测】
  - AC-M02-4 权限变更写入审计，含变更前后值。【测】
  - AC-M02-5 检查清单未通过时，下发任务被拒绝。【测】

### M03 基础配置与初始化

- **目标：** 所有运行参数集中在系统配置中，首次部署时通过初始化向导完成填写，之后可修改且留痕。第 10 节给出完整配置项清单。
- **功能点：**
  - 初始化向导按分组引导：时间与排班、超时与宽限、静默时段与例外、通知渠道、模型与额度、备份、导出、后台安全。
  - 必填项校验；有必填项缺失时系统处于“未就绪”状态。
  - 配置版本化：每次修改生成新版本，记录操作者、时间、变更前后值。
  - 提供“配置完整性检查”，列出缺失或不合理的配置项。
- **业务规则：**
  - 超时宽限与槽位时长没有内置默认值，由用户在首次初始化时填写。缺失时场次不允许登记（安全默认）。
  - 处于“未就绪”状态时，系统只允许查看与配置，不允许开读、下发或导出。
  - 静默时段与例外策略在系统配置中设定（见 M15）。
  - 配置修改不改写历史记录；历史场次按当时生效的配置解释。
- **输入与输出：** 输入为配置项与版本说明；输出为配置版本与检查结果。
- **状态：** 配置为未初始化、已初始化、待修改（有未生效变更）。
- **异常处理：** 保存失败时保留原值并提示；配置冲突（如禁读时段与排班重叠）时拒绝保存并列出冲突项。
- **验收标准：**
  - AC-M03-1 缺少必填项时，登记与下发均被拒绝。【测】
  - AC-M03-2 每次修改产生新版本并写审计。【测】
  - AC-M03-3 配置完整性检查能列出全部缺失项。【演】
  - AC-M03-4 修改禁读时段后，历史场次记录不变。【测】

### M04 书目管理

- **目标：** 书目是唯一登记对象，统一管理归属、认领、续读点、完读、黑名单与系列页入口。
- **功能点：**
  - 书目录入：书目编号（系列码加序号，稳定不变）、系列、公开标题（公开展示的书名）、机器键、来源文件引用、公开级别（见 M18）、状态。
  - 归属：管理员指派读书员；读书员按规则认领未占用书目。
  - 续读点：记录章节或页码、更新时间、来源场次号。
  - 完读标记：须引用一条完读场次记录；标记后不可由他人直接改写。
  - 黑名单：职业类条目永久排除，不可移除；其他条目只能由用户修改，修改留痕。
  - 系列页排序与入口：按系列内序号排序；入口链接由系统生成。
  - 书目改名不改编号。
- **业务规则：**
  - 书目只能由管理员下发或由读书员按规则领取，系统不代认领。
  - 黑名单书目不能被认领，也不能被下发（系统拒绝并说明原因）。
  - 同一书目同时只能有一个活动场次（由数据库唯一约束保证，见 M07）。
  - 续读点只能由该书目对应场次回写，其他场次不得覆盖。
- **输入与输出：** 输入为书目记录、指派与认领请求、回写内容；输出为书目记录与系列页数据。
- **状态：** 未指派、已指派、阅读中、已完读、已排除（见第 8 节）。
- **异常处理：** 编号重复时拒绝；认领冲突时返回“书目已被占用”；回写的续读点版本过旧时返回冲突（见 M09）。
- **验收标准：**
  - AC-M04-1 同一编号只能录入一次。【测】
  - AC-M04-2 黑名单书目无法被认领或下发。【测】
  - AC-M04-3 职业类黑名单条目无法被移除。【测】
  - AC-M04-4 同一书目出现两个活动场次时，第二个被拒绝。【测】
  - AC-M04-5 系列页排序与入口与书目数据一致。【检】

### M05 任务下发与领取

- **目标：** 管理员在后台下发任务，读书员通过接口领取并确认，替代群聊确认。
- **功能点：**
  - 下发：选择书目、指派角色与读书员、任务类型（读、AI 问答、笔记、核验）、截止时间、备注。
  - 读书员读取：只能读取分派给本人的任务。
  - 确认领取：读书员确认已接收，任务进入“已下发”之后的状态。
  - 取消：仅管理员可取消，取消需填写原因。
  - 待办迁移：旧的未完成 todo 导入为“待下发”任务（见 M17 与第 13 节迁移要求）。
- **业务规则：**
  - 下发时检查：书目未被活动场次占用；书目未被列入黑名单；指派的读书员状态为启用且令牌有效。
  - 读书员不能修改任务内容，只能回写执行状态与结果。
  - 任务截止后仍未完成，状态转为“已过期”，并进入催办与异常通知（M14、M15）。
- **输入与输出：** 输入为任务信息；输出为任务记录与读书员可见的任务列表。
- **状态：** 待下发、已下发、已登记、执行中、待回写、待审核、已合入；异常分支为阻塞（需人工）、已取消、已过期（见第 8 节）。
- **异常处理：** 下发冲突时拒绝并提示占用原因；读书员超时未确认时，在开始前提醒中升级（见 M16）。
- **验收标准：**
  - AC-M05-1 管理员在后台下发任务后，指定读书员通过接口可读取到该任务。【演】
  - AC-M05-2 读书员读取其他读书员的任务时被拒绝并写审计。【测】
  - AC-M05-3 下发与读取都写入审计日志。【检】
  - AC-M05-4 读书员无法修改任务内容。【测】

### M06 排班与场次

- **目标：** 排班统一制定、审批后生效，场次由排班生成；开始与结束由系统自动记录，替代报备 PR。
- **功能点：**
  - 排班模板：按日定义槽位，每个槽位包含角色、资源类别、开始时间、时长。模板包含轻游记整点场、微信读书（AI 读书）半点场、读书时长专员 00:10 短时场、Windows 本地 PDF 场。
  - 排班草稿由管理员制定，用户审批后生效。变更已生效排班需用户审批。
  - 场次生成：每个生效槽位生成一场次。
  - 开始与结束记录：系统记录实际开始时间、结束时间、run_id、停止原因。
  - 漏跑标记：场次结束时仍为“待登记”或“已排班”，标记为漏跑，不补跑。
- **业务规则：**
  - 02:00–06:00 为禁读时段。系统拒绝在该时段生成或登记场次。
  - 所有时间内部存 UTC，页面按 UTC+8 显示。
  - 最长时长为槽位时长加超时宽限（两者均由配置提供，见 M03）。
  - 过期场次不补跑。
  - 未报备的场次视为未开始，系统中以“未开始”记录，不自动推断为已开始。
- **输入与输出：** 输入为排班模板、审批结果；输出为场次列表与状态。
- **状态：** 场次状态见第 8 节。
- **异常处理：** 排班与禁读时段重叠时拒绝生效；排班核对发现缺失、重复或时段错误时通知管理员（M16）。
- **验收标准：**
  - AC-M06-1 禁读时段内无法登记场次。【测】
  - AC-M06-2 排班生效前必须有用户审批记录。【测】
  - AC-M06-3 每个生效槽位都有对应场次，缺失时排班核对在 1 小时内发现。【演】
  - AC-M06-4 场次的实际开始与结束时间由系统记录，不依赖 PR。【检】

### M07 资源锁与并发控制

- **目标：** 防止两个场次同时占用同一资源或同一书目，并防止旧场次误释放新锁。
- **功能点：**
  - 资源清单（初始）：`browser:weread-shared`（微信读书与轻游记共用，错峰）；`browser:weread-duration`（读书时长专员，独立）；`local_pdf:xpdf-reader`（Windows 读书员，独立）。
  - 获取锁：条件更新，资源空闲时才写入持有场次并递增版本号，并发放围栏令牌（每次获取递增）。
  - 释放锁：必须携带获取时的围栏令牌；令牌不匹配则拒绝。
  - 唯一活动场次：数据库部分唯一索引，覆盖所有活动状态的场次。
  - 冲突处理：资源被占用时不排队，直接记为“资源冲突”并通知；不补跑。
  - 超时：超时场次的锁保持占用，状态为“占用-待裁定”，不自动释放（见 M09）。
- **业务规则：**
  - 资源按“持有者”判定，不按角色名判定。新增角色只需新增资源记录。
  - 后台 job 不获取资源锁，只能标记超时。
  - 人工裁定只有两种：确认已停止（释放锁并记录原因）；确认仍在运行（延长并记录批准人与期限）。
  - 系统不得自动接管、补跑或续读旧运行。
- **输入与输出：** 输入为获取、释放、裁定请求；输出为锁状态与版本号。
- **状态：** 空闲、占用、释放中、占用-待裁定（见第 8 节）。
- **异常处理：** 释放令牌不匹配时拒绝并写审计；待裁定资源的获取请求被拒绝并提示“资源待裁定”；同一场次重复获取返回已有的结果（幂等）。
- **验收标准：**
  - AC-M07-1 两个场次同时获取同一资源，只有一个成功。【测】
  - AC-M07-2 旧围栏令牌无法释放新场次的锁。【测】
  - AC-M07-3 同一书目出现两个活动场次时第二个被拒绝。【测】
  - AC-M07-4 超时场次的锁不会被系统自动释放。【测】
  - AC-M07-5 资源冲突被记录并通知，且不补跑。【测】

### M08 登录态托管

- **目标：** 尽早发现浏览器登录失效，阻止在失效状态下开读，并由用户手动恢复。
- **功能点：**
  - 检查请求：系统在场次开始前 10 分钟与之后每 30 分钟，向持有该浏览器资源的读书员发出“登录态检查”任务。
  - 检查结果上报：读书员通过接口上报通过或失败、检查时间与摘要（不含账号、Cookie 或凭据）。
  - 手动登录：失效时由用户在共享浏览器中自行登录；登录后系统再次发出检查请求，通过后场次才能进入登记。
  - 失效记录：每次失效记录时间、影响的场次与恢复时间，用于统计。
- **业务规则：**
  - 检查失败时，场次停在“登记前”，资源锁不获取，并通知用户。
  - 读书员超时未上报检查结果，视为“未知”，场次同样阻塞并通知用户。理由：沉默不等于正常。
  - 禁止借用他人会话、拼接 URL 绕过登录、自动填写或保存他人的账号口令。
  - 系统不持有任何浏览器会话，不代为登录。
- **输入与输出：** 输入为检查结果；输出为登录态状态与失效记录。
- **状态：** 正常、失效、未知（未上报）、待恢复（用户登录中）。
- **异常处理：** 上报内容含敏感字段时拒绝保存并告警；连续多次失效进入每周统计的异常项。
- **验收标准：**
  - AC-M08-1 登录失效时，场次停在登记前，并在 5 分钟内通知用户。【演】
  - AC-M08-2 读书员未上报检查结果时，场次被阻塞。【测】
  - AC-M08-3 上报内容中出现账号、Cookie 或凭据样式的内容时被拒绝。【测】
  - AC-M08-4 每次失效都有起止记录，可统计每周次数。【检】

### M09 读书执行、登记与回写

- **目标：** 读书员通过接口完成登记、开读、心跳、收尾与回写；系统用开读许可与版本号约束执行。
- **功能点：**
  - 登记：读书员提交场次号，系统检查：场次处于可登记窗口；禁读时段未进入；任务已分派给本人；令牌有效；登录态正常；资源获取成功；书目未被占用。全部通过后签发开读许可。
  - 开读：记录实际开始时间与 run_id。
  - 心跳：运行中每 5 分钟（初始值）上报一次当前步骤与进度摘要。
  - 收尾：上报结束时间、结果摘要、续读点、产出引用、AI 调用引用、停止原因（如有）。
  - 回写：提交时携带读取时的版本号。版本不一致返回冲突，读书员须重新读取后再提交。
  - 释放锁：携带围栏令牌释放资源。
  - 幂等：所有写接口携带幂等键，重复提交返回首次结果。
- **业务规则：**
  - 系统无法强制外部浏览器的行为。因此未获开读许可的场次，其产出一律标记为“无许可产出”，不计入统计、不进入导出。
  - 冲突不自动合并，避免覆盖他人结果。
  - 同一次回写的冲突连续出现 3 次时通知用户（M15）。
  - 不允许一次回写只写入一半：状态转换、锁变更、审计与通知入队在同一事务中完成（第 8 节事务边界）。
- **输入与输出：** 输入为登记、心跳、收尾、回写、释放请求；输出为许可、版本与状态。
- **状态：** 见第 8 节场次状态。
- **异常处理：** 心跳中断超过 15 分钟（初始值）转为超时检查（M16）；回写因网络失败时读书员保留本地草稿，以相同幂等键重试；登记失败时返回具体的检查项。
- **验收标准：**
  - AC-M09-1 未获开读许可的场次，其产出被标记为无许可且不进入导出。【测】
  - AC-M09-2 登记时任一检查不通过，许可不签发，并返回具体原因。【测】
  - AC-M09-3 版本过旧的回写被拒绝，返回冲突。【测】
  - AC-M09-4 重复提交同一幂等键只产生一次结果。【测】
  - AC-M09-5 回写失败时状态与锁均不发生部分变更。【测】

### M10 AI 问答、标签与核验

- **目标：** 按三步链路记录 AI 问答；区分亲读、AI 问答、AI 解读与推断；金句默认未核验；原始回复只存私密层。
- **功能点：**
  - 三步链路：先问全貌（这本书写什么），再逐章问，最后写读后感。每一步的问答都记录为一条 AI 问答记录。
  - 记录内容：提示词引用、模型、调用时间、来源引用（书目、章节、页码）、原始回复引用、标签、核验状态。
  - 标签：亲读、AI 问答、AI 解读、推断四类，定义与禁止规则见第 5 节。AI 输出永远不能标为亲读，四类标签在界面与导出中分开显示。
  - 金句：默认“未逐字核验”。只有完成逐字核验并记录核验人与方法后，才改为“已核验”。
  - 核验记录：每次状态变更写一条核验记录，不可覆盖。
  - 入口规则：书内 AI 入口只能从已登录页面点击进入，不得拼接 URL。系统记录入口来源，无法证明来源的记录标为“入口未知”。
- **业务规则：**
  - AI 输出不得标为亲读。
  - 未核验的金句在公开产物中只能显示为“未逐字核验”的引语，不得作为原文引用。
  - 原始回复只存私密层，仅管理员与用户可见（每次打开记审计）。
  - 第一期只做最小落库：调用引用、标签与核验状态；第三期做全量落库、核验记录与知识库检索（见第 13 节）。
- **输入与输出：** 输入为问答记录与核验结果；输出为问答记录、标签与核验状态。
- **状态：** 核验状态为未核验、已核验、不收录。
- **异常处理：** 核验为不收录的产出不进入公开层，保留在私密层供审计；模型回复为空或包含敏感内容时标记为待处理，不进入公开层。
- **验收标准：**
  - AC-M10-1 每次 AI 调用都有一条记录，且不含密钥。【检】
  - AC-M10-2 新建金句的默认状态为“未逐字核验”。【测】
  - AC-M10-3 导出中 亲读、AI 问答、AI 解读与推断四类内容分开标注。【检】
  - AC-M10-4 原始回复的每次打开都有审计记录。【测】

### M11 第三方 AI 预算、模型顺序与回退

- **目标：** 集中管理第三方 AI 的密钥引用、模型顺序与额度记账，额度用尽或失败时按规则回退或跳过。
- **功能点：**
  - 密钥引用登记：引用名、提供方、状态、最近轮换时间。不保存值。
  - 模型顺序：有序列表。初始顺序为 `gemini-3.8-flash`，然后 `gemini-3-flash-preview`。
  - AI 调用代理接口：读书员把模型请求交给系统，由系统选择当前第一个可用模型，并使用密钥引用调用提供方；读书员不接触密钥值。调用异步执行，返回调用编号，结果可按编号查询（见第 5 节）。
  - 失败与额度事件由系统从代理调用结果中直接判定，不依赖读书员上报。
  - 额度记账：按模型、按日记录调用次数与额度消耗，并记录剩余额度（每日额度上限默认 20 次/天，按模型分别记账，见第 10 节“10.1 默认配置表”）。
  - 调用记录：每次调用写库，不含密钥。
- **失败策略（初始值，可在配置中修改）：**
  - 单次调用超时 150 秒。超时记为一次失败，并转向下一模型。
  - 额度用尽：提供方返回额度错误，或本地记账达到上限，则该模型当日标记为“额度用尽”，当日不再选用，次日自动恢复。
  - 连续失败：同一模型连续失败 3 次，标记为“暂停”30 分钟，之后允许试探一次；试探成功则恢复可用。
  - 全部不可用：本次 AI 辅助步骤被跳过。任务继续走人工流程，产出注明“未使用 AI 辅助”，并发送一条非阻塞通知。
- **业务规则：**
  - 本地 PDF 可整本交给 Gemini 辅助。
  - AI 输出只是辅助，需人工核对后才能成为产出（M10 的标签规则同样适用）。
  - 模型顺序与失败策略只在配置中维护，不写死在代码或读书员的脚本中。
- **输入与输出：** 输入为模型选择、失败上报与调用记录；输出为可用模型、额度状态与告警。
- **状态：** 模型为可用、额度用尽、暂停、停用。
- **异常处理：** 密钥引用找不到时模型标记为“密钥未就绪”并跳过；额度记账与调用不一致时以提供方返回为准并记录差异。
- **验收标准：**
  - AC-M11-1 首选模型额度用尽后，次日前不再选用该模型。【测】
  - AC-M11-2 连续失败 3 次后该模型暂停 30 分钟。【测】
  - AC-M11-3 两个模型都不可用时，任务不阻塞，并产出“未使用 AI 辅助”的标注。【测】
  - AC-M11-4 任何接口与导出中都不出现密钥值。【检】

### M12 审核与合入（第一期 B 批写操作）

- **目标：** 产出经审核后才合入系统状态与导出；审核结论不可修改。
- **功能点：**
  - 审核对象：产出、续读点变更、完读标记、记忆条目、排班变更。
  - 审核结论：通过、退回、有条件通过（需记录条件与完成状态）。
  - 合入：审核通过的产出状态变为“已合入”，只有已合入的内容才进入导出与知识库检索。
  - 抽查：用户可抽查管理员的审核结论；管理员可抽查读书员的产出。
  - 更正：审核记录不可修改。更正结论时新增一条审核记录或提交新版本。
- **业务规则：**
  - 读书员不审核自己的产出。管理员不审核自己下发的产出。
  - 退回的任务回到“执行中”，并附退回原因。
  - 未合入的草稿不进入导出、Pages 与知识库检索。
- **输入与输出：** 输入为审核请求与结论；输出为审核记录与合入状态。
- **状态：** 待审核、已通过、有条件通过、已退回、已合入（见第 8 节）。
- **异常处理：** 对象版本已变化时，审核请求被拒绝，要求审核人重新查看。
- **验收标准：**
  - AC-M12-1 读书员审核自己的产出被拒绝。【测】
  - AC-M12-2 审核记录写入后不可修改。【测】
  - AC-M12-3 未合入的产出不出现在导出包与检索结果中。【检】
  - AC-M12-4 第一期 B 批若未完成，在验收报告中注明并顺延。【检】

### M13 导出、脱敏与发布

- **目标：** 把公开产物导出到 GitHub 做发布与归档；导出不需要人工确认，但脱敏扫描不通过则自动阻断。
- **功能点：**
  - 导出包：按对象生成公开产物，JSON 与 Markdown 格式与旧仓库结构一致，便于回滚。
  - 脱敏扫描：检查 Agent 机器键以外的标识符、群标识、私人路径、凭据与令牌模式、私密层标记。
  - 导出提交：导出由系统的导出身份完成，只经自动化 PR 合入 main，不直接推送。读书员没有 Git 写权限。
  - Pages 生成：只从公开产物生成。
  - 笔记模板：统一使用 `archive-ui.md` 为唯一共享 UI 规范渲染。公开标题统一为“AI读书”，机器键保留。
  - 月度目录：每日产出按月放在 `daily-output/YYYY-MM/` 下，文件名为日期。
- **业务规则：**
  - 导出范围：只包含公开级别为“公开”的对象，且已合入（M12）。
  - 私密层内容（原始 AI 回复、凭据引用、私人路径等）永不导出。
  - 导出频率：每日日报生成后执行一次；审核合入后增量导出，延迟 10 分钟（初始值）。
  - 导出文件由系统生成，不允许手工修改后再导出。
- **输入与输出：** 输入为公开产物与导出配置；输出为导出批次、脱敏报告与 PR 状态。
- **状态：** 待导出、已生成、已脱敏、已提交、已合入远端；失败状态见异常处理。
- **异常处理：**
  - 脱敏扫描不通过：阻断导出，写入脱敏报告，并通知管理员与用户。
  - GitHub 不可用：指数退避重试 3 次；仍失败则在下一个导出周期重试，并通知用户一次。
  - 导出身份权限不足：阻断导出并通知，不改用读书员身份。
- **验收标准：**
  - AC-M13-1 脱敏扫描发现 Agent 标识以外的标识、凭据或私人路径时，导出被阻断。【测】
  - AC-M13-2 导出包不包含私密层内容。【测】
  - AC-M13-3 导出不需要人工确认即可完成（自动阻断除外）。【演】
  - AC-M13-4 Pages 页面的每条内容都能追溯到导出批次。【检】

### M14 日报、催办与汇总

- **目标：** 每日自动生成日报，减少人工汇总；0 点自动催办未回写的任务。
- **功能点：**
  - 23:50 自动生成并发送日报。日报内容：当日排班、场次结果（已登记、漏跑、阻塞、超时、资源冲突）、产出数量与已合入产出的链接、异常事件、登录失效次数、Gemini 额度使用情况、明日排班与待下发任务。
  - 00:00 催办：对未收尾或未回写的任务，写入对应读书员的待办消息，并在日报中列出。
  - 更正：次日 0 点之前可补充更正，更正以新版本记录，不改写已发送的日报。
- **业务规则：**
  - 日报不等待人工确认，自动生成并发送；日报中的“需管理员处理”事项会被单独列出。
  - 日报与导出的关系：日报生成后触发导出（M13）。
  - 日报的发送渠道见 M15。
- **输入与输出：** 输入为当日场次、产出与事件；输出为日报记录与催办消息。
- **状态：** 草稿、已发送、已更正。
- **异常处理：** 日报生成失败时通知管理员并在 10 分钟后重试一次；仍失败则发送简版日报（只含场次结果与异常）。
- **验收标准：**
  - AC-M14-1 每天 23:50 准时生成并发送日报（允许延迟不超过 2 分钟）。【演】
  - AC-M14-2 0 点催办覆盖全部未回写任务。【测】
  - AC-M14-3 日报中的漏跑与异常与场次记录一致。【检】

### M15 通知

- **目标：** 多渠道通知，保证需要用户处理的事件可追溯、不重复、不打扰静默时段。
- **渠道：**
  - Cue 消息：个人主渠道，用于需要用户处理的事件与个人通知。
  - Webhook：至少配置一个端点。用于群汇总端点（只承载汇总，不承载任务推进）与用户指定的监控端点。端点地址只在配置中保存，不写入文档或导出。
  - 后台页面：只用于查看通知记录与送达状态，不作为推送渠道。
- **事件分级：**
  - 关键：登录态失效、超时待裁定、资源冲突、漏跑、回写冲突超过 3 次、导出脱敏失败、备份失败、凭据异常、数据完整性检查失败。
  - 一般：场次完成、日报、催办。
  - 汇总：日报摘要、系统级异常汇总。
- **业务规则：**
  - 去重：同一事件键（事件类型加对象加日期）在 24 小时内只发送一次。
  - 通知数量上限：每日默认 100 条（可在配置中修改）。重要事件（漏跑、登录失效、数据异常）不计入上限，始终发送。
  - 静默时段：02:00–06:00 内的事件只入队并记录，06:00 统一发送汇总。例外类别在配置中设定（初始值：备份失败、数据完整性检查失败、疑似凭据泄露，可修改）。例外类别立即发送，不等待 06:00。
  - 送达确认：以渠道回执为准。用户确认后记录确认时间。未确认的关键通知在 30 分钟后重发一次；仍未确认则升级为关键通知，仍只通过 Cue 消息发送。
  - 通知内容：中文，首屏可读，包含对象、时间与一句话的需要处理事项，不包含凭据、私人路径与内部标识。
- **输入与输出：** 输入为事件；输出为通知记录与送达状态。
- **状态：** 已入队、已发送、已送达、已确认、未送达、已升级。
- **异常处理：** 某渠道失败时按指数退避重试 3 次；Cue 消息全部失败时改由 webhook 发送，并在后台标记渠道故障。
- **验收标准：**
  - AC-M15-1 登录失效事件在 5 分钟内送达用户。【演】
  - AC-M15-2 同一事件 24 小时内只发送一次。【测】
  - AC-M15-3 静默时段内的非例外事件在 06:00 前不发送。【测】
  - AC-M15-4 未确认的关键通知在 30 分钟后重发一次。【测】

### M16 后台 job 与调度

- **目标：** 系统自带调度器按 job 清单触发定时任务，替代 Cue 定时任务；所有 job 可观测、可追溯。
- **功能点：**
  - 进程内调度器，按 UTC+8 语义触发。job 在线程池中执行，每个 job 有超时上限。
  - job 运行记录：开始、结束、结果、错误摘要。
  - 手动触发：用户可手动触发任一 job，并写审计。
  - 心跳：调度器每分钟更新心跳；心跳超过 2 分钟视为异常。
- **job 清单：**

| job | 触发时间 | 规则 | 失败或异常时 |
|---|---|---|---|
| 排班核对 | 每小时整点 | 对比排班与场次，发现缺失、重复或时段错误 | 通知管理员，记录异常 |
| 登录态检查请求 | 每场次开始前 10 分钟；之后每 30 分钟 | 向持有该资源的读书员发出检查任务 | 无结果则场次阻塞，通知用户 |
| 开始前提醒 | 每场次开始前 10 分钟 | 检查任务是否已登记 | 未登记则催办读书员；5 分钟仍未登记则通知管理员 |
| 超时检查 | 每 5 分钟 | 检查执行中场次是否超过最长时长 | 转为超时待裁定，通知用户 |
| 漏跑记录 | 每场次结束后 | 标记未进入执行的场次 | 记录漏跑，不补跑 |
| 心跳缺失检查 | 每 5 分钟 | 检查执行中场次的心跳 | 超过 15 分钟未心跳则转为超时检查 |
| 0 点催办 | 每日 00:00 | 催办未收尾、未回写的任务 | 仍未回写则进入异常通知 |
| 23:50 日报 | 每日 23:50 | 生成并发送日报（M14） | 失败则通知管理员并重试一次 |
| 导出 | 日报生成后；审核合入后延迟 10 分钟 | 生成导出包，脱敏扫描，提交自动化 PR（M13） | 扫描不通过则阻断并通知 |
| 每日备份 | 每日 04:00（初始值，位于禁读时段内） | 生成加密快照并校验（M19） | 失败则通知用户 |
| 每周恢复演练 | 每周一次（具体星期在配置中设定） | 解密并还原到临时库，比对关键计数（M19） | 演练失败则通知用户 |
| 额度检查 | 每日一次 | 汇总第三方 AI 额度使用（M11） | 额度不足时按模型顺序回退并记录 |
| todo 继承 | 每周一 00:00（UTC+8） | 未完成的 todo 项继承到新一周（M17） | 失败则通知管理员 |
| 健康探测 | 每 5 分钟（由外部监控执行） | 检查数据库、调度器心跳、最近备份、磁盘占用（第 7.5 节） | 连续失败时通知用户 |

- **业务规则：**
  - 外部调用（模型、浏览器检查、GitHub 导出）只在 job 线程内发生，不占用 HTTP 线程，不跨外部调用持有数据库写事务（第 8 节事务边界）。
  - job 不获取资源锁，只能标记超时或写入检查请求。
  - 服务重启期间错过的场次不补跑，记为漏跑。错过的日报与备份允许在启动后补做一次当日的，并标注“迟到”。
  - 同一 job 在同一触发窗口内只运行一次。
  - 系统不接管读书员子任务的内部执行，只通过接口接收结果。
- **输入与输出：** 输入为时间与状态；输出为 job 运行记录与副作用（状态、通知、导出）。
- **状态：** 排队、运行中、成功、失败、超时、跳过。
- **异常处理：** job 超时时强制结束线程，写运行记录并通知；调度器心跳缺失时通知用户。
- **验收标准：**
  - AC-M16-1 每个 job 都有运行记录，且可在后台查看。【检】
  - AC-M16-2 服务停机期间错过的场次在恢复后标记为漏跑，不补跑。【测】
  - AC-M16-3 调度器心跳超过 2 分钟未更新时，健康探测失败并通知。【测】
  - AC-M16-4 Cue 定时任务的数量不影响任何 job 的触发。【演】

### M17 个人记录（todo、memory、openspec）

- **目标：** 保留各读书员的个人记录，并纳入统一的权限与审计。
- **功能点：**
  - todo：按周维护，每项有状态；未完成项在每周一 00:00（UTC+8）由 job 继承到新一周。与任务表关联：可由任务生成，也可单独存在。
  - memory：只写本人的精简工作记忆。每次改动生成新版本并进入审核（M12）。
  - openspec 目录：系统只登记目录引用、版本与最近更新时间。目录内容由各 Agent 维护，系统不解析。
- **业务规则：**
  - memory 不得包含凭据、令牌、机器键以外的标识、私人路径（脱敏扫描同样适用）。
  - 读书员只能写本人的 todo 与 memory；管理员可读 memory 并审核。
  - memory 改动需审核后才生效，未审核版本不得作为其他 Agent 的依据。
- **输入与输出：** 输入为 todo 项与 memory 草稿；输出为周视图与生效版本。
- **状态：** todo 为未开始、进行中、已完成、已继承；memory 为草稿、待审核、已生效、已退回。
- **异常处理：** memory 脱敏扫描不通过时拒绝提交；openspec 目录引用失效时标记为“引用失效”。
- **验收标准：**
  - AC-M17-1 未完成的 todo 在下周一出现在新一周。【测】
  - AC-M17-2 memory 未审核前不生效。【测】
  - AC-M17-3 读书员不能修改他人的 todo 或 memory。【测】

### M18 书籍资产

- **目标：** 登记书籍原件与副本，校验完整性，分层公开，保护原件不被误删。
- **功能点：**
  - 登记：书目编号、文件引用、sha256、大小、来源说明、公开级别、副本位置。
  - 校验：上传完成后比对 sha256。
  - 分批上传：按系列分批；中断后从最近一个校验通过的批次继续，不重传全部。天涯全目录约 5.85GB，应按系列分批。
  - 副本：每份文件至少两份副本，一份在本地私有存储，一份在离线或冷存备份（备份位置见第 10 节“10.1 默认配置表”）。
  - 季度恢复演练：抽检副本可用性。
  - 公开级别：默认“公开”（脱敏后可整本入公开仓库）。用户可按书标记为“私密”，私密书不进 Git、不进公开页面。天涯神贴与甲骨文合集等已确认的书籍保持“公开”，清单由用户在书目中维护。
- **业务规则：**
  - 系统不提供删除原件与中转副本的接口。原件与中转副本保留在本机，不删除。
  - 存储预算：原件与产出合计默认 20 GB（可在配置中修改）。超出时停止新增原件导入并通知用户，不删除已有数据。
  - 数据库只保存文件引用、校验值与大小，不保存书籍正文。
  - 书籍正文不进入 AI 调用之外的任何外部位置；本地 PDF 交 Gemini 时只使用 M11 的规则。
  - 管理员不阅读书籍正文（NG4）。
- **输入与输出：** 输入为文件引用与校验信息；输出为资产记录与校验报告。
- **状态：** 已登记、上传中、已校验、校验失败、已归档。
- **异常处理：** sha256 不一致时标记“校验失败”，并保留原文件不动；副本缺失时通知用户。
- **验收标准：**
  - AC-M18-1 系统中没有删除原件或中转副本的接口。【检】
  - AC-M18-2 中断后的上传从最近通过的批次续传。【演】
  - AC-M18-3 默认公开级别为“公开”；标记为“私密”的书籍不进入导出（不进 Git、不进公开页面）。【测】
  - AC-M18-4 每个文件都有 sha256 与副本位置记录。【检】

### M19 备份与恢复

- **目标：** 每天一次一致快照，加密存放；每周演练恢复。
- **功能点：**
  - 每日一次快照：使用 SQLite 在线备份接口或 `VACUUM INTO` 生成一致快照（不直接复制 `.db` 文件，因为 WAL 文件会使直接复制的结果不一致）。
  - 完整性：快照生成后执行 `PRAGMA integrity_check`。
  - 加密：压缩后用非对称加密（如 age）加密。加密密钥由用户（雨）保管：服务器只保存加密公钥，私钥由用户离线保管，系统不存明文密钥。
  - 保留：保留最近 30 份快照（默认值，可在配置中修改）。
  - 存放：快照存放在云主机的独立磁盘或独立目录，并同步一份到用户指定的外部存储（位置在配置中设定）。
  - 每周恢复演练：解密并还原到临时库，运行完整性检查，比对场次数、审计日志数等关键计数。
  - 失败通知用户（M15 的例外类别）。
- **业务规则：**
  - 恢复需要用户提供私钥，恢复先在临时库完成，经用户确认后才切换到正式库。
  - 备份时间在禁读时段内（初始值 04:00），不影响读书场次。
- **输入与输出：** 输入为数据库；输出为加密快照、校验报告与演练报告。
- **状态：** 生成中、已校验、已加密、已保留、已过期删除、失败。
- **异常处理：** 备份失败时保留上一份有效快照并通知；校验失败的快照不计入保留份数。
- **验收标准：**
  - AC-M19-1 每天生成一份加密快照，并有完整性校验记录。【检】
  - AC-M19-2 服务器上没有私钥。【检】
  - AC-M19-3 每周演练能在临时库还原并通过关键计数比对。【演】
  - AC-M19-4 备份失败时 5 分钟内通知用户。【演】

## 7. 技术架构

### 7.1 总体形态

第一期部署在云端一台 Linux 主机上，使用 Python 实现，单个服务进程，单个 SQLite 数据库文件。主机由用户另行选定。理由：规模小（数个读书员，每日写入估计在数千次以内，第一期需实测），单机最简单，且与 SQLite 的单写者模型一致。

所有时间内部存 UTC，页面与排班统一按 UTC+8 显示。禁读时段、排班时间与日报时间都以 UTC+8 为约定。

### 7.2 进程形态（已决定）

一个 Python 服务进程内含三部分：HTTP 接口（读书员 API 与后台页面）、定时调度器、job 执行线程池。定时任务不是独立进程，调度器在进程内触发 job，job 在线程池中执行，每个 job 设超时上限。

外部调用（AI 模型、浏览器检查结果处理、GitHub 导出）只在 job 线程中发生，不占用 HTTP 线程，不持有数据库写事务。所有写入经过同一个写入入口，进程内用写锁串行化。

拆分为独立 worker 进程的触发条件：(a) HTTP 接口 p95 响应时间超过 1 秒并持续一周，且原因是 job 占用资源；(b) 定时 job 因前一个 job 占用调度线程而延迟触发超过 5 分钟。拆分后仍使用同一 SQLite 文件，并遵守 7.3 的并发策略。

### 7.3 SQLite 并发策略（已决定）

连接建立时设置：WAL 模式、busy_timeout 5000 毫秒、外键约束开启、synchronous 为 FULL。理由：WAL 下读写互不阻塞；锁与审计写入优先于写入速度。

同一时刻只有一个写事务。写事务使用 `BEGIN IMMEDIATE`，开始即取得写锁，避免读后升级导致的繁忙错误。读请求使用独立的只读连接，不占用写锁。

一次状态转换（获取锁、回写结果、审核、下发任务、释放锁、AI 调用结果落库）为一个事务，包含：版本号条件检查、对象更新、锁表变更、审计日志、通知入队。全部提交或全部回滚，不允许只写一半。

不跨外部调用持有事务。流程为：读取，然后外部操作（无事务），然后写回结果（新事务）。这样 150 秒的模型调用或浏览器检查期间不会占着写锁。

锁与唯一性由数据库保证：获取锁为条件更新；同一书目唯一活动场次为部分唯一索引。

所有数据库操作设置 busy_timeout。仍返回“数据库忙”的写请求，返回“服务繁忙，请稍后重试”，不静默丢弃，并记录一次繁忙事件。

### 7.4 后台页面与鉴权

后台页面的范围、写操作与会话规则见 M01。鉴权方式如下：读书员使用各自独立的令牌，只能访问自己的任务、场次与产出，访问他人数据和越权请求一律拒绝并记录。令牌值不入库，数据库只存引用名与状态。后台用户与管理员通过用户名与口令登录，口令存于密钥存储。读书员令牌不能登录后台。后台二次验证默认开启，默认值见第 10 节“10.1 默认配置表”。

### 7.5 部署最小要求

运行环境为一台 Linux 云主机。Python 版本固定，使用虚拟环境安装依赖，依赖版本锁定。服务由 systemd 管理，开机自启，异常退出自动拉起（`Restart=on-failure`）。

HTTP 服务只监听本机地址，由反向代理提供 HTTPS。防火墙只开放 443 与 SSH，SSH 仅允许密钥登录。配置与密钥通过环境文件或密钥服务提供，文件权限仅服务账号可读，不入 Git，不进入导出包。

日志为结构化 JSON，每行一条，按日期或大小轮转，至少保留 30 天。日志不记录令牌、口令、完整 Cookie。导出前对日志做同样的脱敏扫描。

提供 `/healthz` 接口，返回：数据库可读写、调度器最近一次心跳时间（超过 2 分钟视为异常）、最近一次备份的时间与结果、磁盘占用。由独立于服务器的外部监控每 5 分钟探测一次，连续失败时通过 Cue 消息通知用户。磁盘占用超过 80% 时通知用户。

启动时检查数据库完整性；未提交的写事务由 SQLite 自动回滚。重启后场次状态以数据库为准，不因重启自动续读。

### 7.6 SQLite 的上限与迁移触发条件

本规模下 SQLite 够用。数据库不含书籍 PDF 与 EPUB（它们在私有存储中，见 M18）。写入量估计每日数千次以内，数据库文件预计远小于 1 GB（第一期实测）。真正的限制是写并发，而不是容量。

出现下列任一情况时，应迁移到服务型数据库，优先考虑 PostgreSQL：

1. 需要多台主机同时访问同一份数据（包括第三团队部署在其他机器上，见 M21）。SQLite 不适合放在网络文件系统上被多台机器并发访问。
2. 写锁等待超标：连续 7 天内，写事务 p95 耗时超过 200 毫秒，或出现“数据库忙”超时超过 10 次。
3. 恢复点目标收紧：要求数据丢失不超过 1 小时，或故障切换时间不超过 1 小时。当前每日快照的恢复点约为 24 小时。
4. 数据库文件超过约 10 GB，或每日快照耗时超过 30 分钟。
5. 引入多租户或数据库级的细粒度权限（第一期不做）。

第一期 SQL 使用参数化查询，避免依赖 SQLite 专有行为，便于替换数据库驱动。迁移方式为：导出为 JSON 中间格式，导入后做记录数与关键字段对账，在 13.4 规定的切换窗口内执行。

### 8.4 事务与并发规则

同一对象的并发修改通过版本号控制。回写时必须带上读取时的版本号，版本不一致则返回冲突，要求读书员重新读取后再提交。冲突不自动合并，避免覆盖他人结果。

所有写接口携带幂等键，重复提交返回首次结果，不产生第二次副作用。

时间字段统一存 UTC。跨日、跨周的规则（如 0 点催办、周一 todo 继承）以 UTC+8 为准换算。

系统无法强制外部浏览器的行为。未获开读许可的场次，其产出一律标记为“无许可产出”，不计入统计，不进入导出。

### 9.5 收尾与回写

| 步骤 | 执行方 | 动作 | 系统检查 | 是否需要人工 |
|---|---|---|---|---|
| 1 | 读书员 | 收尾，上报结束时间、结果摘要、续读点、产出引用、AI 调用引用、停止原因（如有） | 版本号与读取时一致；幂等键有效 | 否 |
| 2 | 系统 | 写回结果，更新书目续读点，生成待审核产出 | 状态转换合法；审计与通知入队在同一事务中完成 | 否 |
| 3 | 系统 | 释放资源锁 | 围栏令牌匹配 | 否 |
| 4 | 管理员 | 审核产出（M12） | 审核回避规则 | 是 |
| 5 | 系统 | 合入，进入导出（M13） | 脱敏扫描通过 | 否 |

回写冲突连续出现 3 次，通知用户。回写因网络失败时，读书员保留本地草稿，以相同幂等键重试。

### 9.6 超时裁定

系统在超时检查中发现场次超过最长时长后，场次转为“超时待裁定”，资源锁保持占用，并通知用户。用户只能做两种裁定：确认已停止（释放锁，记录原因）或确认仍在运行（延长，记录批准人与期限）。系统不得自动接管、补跑或续读旧运行。

### 9.7 审核与合入

审核人对产出做出通过、退回或有条件通过的结论。审核记录写入后不可修改，更正结论需新增一条记录或提交新版本。合入后的产出进入导出与知识库检索。

### 9.8 导出与发布

日报生成后执行一次导出；审核合入后延迟 10 分钟做增量导出。导出包由系统生成，经脱敏扫描后，由导出身份通过自动化 PR 合入 main。导出不需要人工确认，但脱敏扫描不通过时自动阻断。Pages 只从导出的公开产物生成。

### 9.9 日报与催办

23:50 系统自动生成日报并发送，内容见 M14。00:00 对未收尾、未回写的任务发出催办，并在日报中列出。次日 0 点前可补充更正，更正以新版本记录。

### 9.10 漏跑与补跑规则

场次结束时仍为待登记或已排班，标记为漏跑。过期场次不补跑。服务停机期间错过的场次，恢复后同样标记为漏跑。错过的日报与备份，允许在启动后补做一次，并标注“迟到”。

### 9.11 AI 问答链路

读书员从书内 AI 入口或 AI 调用代理发起问答（A1），系统记录调用与来源。问答按全貌、逐章、读后感的顺序进行。读后感草稿标为 AI 解读。读书员确认后，进入笔记草稿流程（A2 与 5.8），金句与事实经 A3 核验后才能收录。

### 9.12 仍需人工的步骤

用户手动登录共享浏览器（微信读书、轻游记）；审批排班；裁定超时场次；抽查审核结论；审核产出；核验金句与事实；确认已停止或仍在运行的裁定。

## 11. 外部集成

### 11.1 GitHub

GitHub 只做发布与审计归档，不做状态存储。系统导出的内容经脱敏扫描后，由导出身份通过自动化 PR 合入 main。读书员不直接写入 GitHub，不依赖任何会话的连接器是否启用。导出身份权限不足时阻断导出并通知，不改用读书员身份。

### 11.2 微信读书

通过浏览器操作。登录态由用户手动维护（M08）。系统不代为登录，不借用他人会话，不拼接 URL 绕过登录。微信读书官方接口凭据只以引用名登记在密钥存储中，系统库不存值。

### 11.3 Gemini 与其他第三方模型

统一通过 AI 调用代理调用（见 5.4）。系统维护模型顺序、额度记账与失败策略。密钥只以引用名保存。每次调用写调用记录，不含密钥。本地 PDF 可整本交给模型辅助；输出只作辅助，需人工核对后才能成为产出。

### 11.4 书内 AI 入口

书内 AI 入口由读书平台提供。读书员只能从已登录页面点击进入，不拼接 URL。系统记录入口类型与来源页面标记。

### 11.5 Pages 发布

Pages 只从系统导出的公开产物生成。发布前须通过脱敏扫描。

### 11.6 Webhook

至少配置一个 webhook 端点。用于群汇总（只承载汇总，不承载任务推进）与用户指定的监控端点。端点地址只保存在配置中，不写入文档、导出包或日志。

### 11.7 Cue 消息

个人主渠道，用于需要用户处理的事件与个人通知。送达以渠道回执为准。

## 12. 非功能要求

### 12.1 安全

令牌、口令与第三方密钥均以引用名存放在密钥存储中，系统库、导出包与日志中不出现值。所有写请求做防跨站请求伪造校验。鉴权失败与越权请求都写审计。服务器上不保存备份私钥。

### 12.2 隐私与数据分级

| 层级 | 内容 | 位置 | 访问 | 能否导出 Git |
|---|---|---|---|---|
| 公开 | 公开标题、已合入且标为公开的笔记、已核验的公开内容、日报中的公开部分、公开级别为“公开”的书籍（脱敏后） | 数据库与导出包 | 公开（Pages） | 能 |
| 内部 | 任务、场次、状态、产出草稿、核验记录、通知记录 | 数据库 | 按角色权限 | 不能（除非标为公开的聚合结果） |
| 私密 | 原始 AI 回复、标记为“私密”的书籍原件、凭据引用、私人路径、AI 修改前的原始草稿 | 私密存储区（加密）与本机 | 仅用户与管理员，每次打开记审计 | 不能 |

书籍的默认公开级别为“公开”，脱敏后可整本入公开仓库；用户可按书标记为“私密”，私密书不进 Git、不进公开页面。天涯神贴与甲骨文合集等已确认的书籍保持公开。公开内容需经脱敏扫描。

### 12.3 权限隔离

每个角色只能访问自己的数据，越权请求拒绝并记录。读书员默认只能看到本人的数据（见 4.3）。

### 12.4 审计

所有写入、状态转换、审核、核验、凭据操作、权限变更、原始 AI 回复的打开、配置修改都记录，只追加。审计日志包含操作者、动作、对象、前后版本与时间。

### 12.5 备份与恢复

每日一次加密快照（M19）。恢复点目标约为 24 小时。恢复时间目标在第一次恢复演练后记录，并在迁移触发条件中参照。

### 12.6 性能与可用性

写事务 p95 不超过 200 毫秒，HTTP 接口 p95 不超过 1 秒。第一期为单机，不承诺高可用。可用性目标为读书时段内服务可用，故障时通过通知及时告知用户。

### 12.7 可观测性

结构化日志；`/healthz` 探测；job 运行记录可在后台查看；繁忙事件、锁等待、job 延迟、AI 调用成功率、回退次数、通知送达率可在后台汇总。

### 12.8 可导出与可回滚

每个对象有版本号，可回到任一历史版本查看。导出为与旧格式一致的 JSON 与 Markdown，导出前做脱敏扫描。切换有回滚方案（13.4）。

### 12.9 语言与阅读体验

所有界面、通知与报表使用中文。通知内容简短，关键信息在首屏可见，不依赖网页才能理解。

### 12.10 AI 质量与安全

AI 输出可溯源（5.5）。AI 输出标签不漂移（P4）。书内文字视为数据不视为指令（P5）。模型顺序、额度与失败策略可配置（5.4）。金句与事实默认未核验（5.6）。

### 13.2 第二期：数据分析、异常识别与任务拆解

验收标准：指标与人工抽样统计的误差在 5% 以内（析）；每月自动生成月度目录（演）；A4 摘要中的数字与指标快照一致率为 100%（测）；A7 建议未经管理员采纳不能下发（测）。

### 13.3 第三期：AI 全量落库、核验与知识库

范围：A2 笔记草稿全流程与发布；A3 金句与事实核验全流程（含抽检）；全量落库与标签区分；知识库检索（只检索已合入的产出）；额度账本的完整分析；第三团队接入（M21）。

验收标准：所有 AI 调用都有记录（检）；金句默认未核验（测）；检索结果只包含已合入的产出（测）；第三团队试运行一本书，记录完整可回溯（演）。

### 13.4 迁移路径

**导入对照**

| 现有内容 | 导入目标 | 说明 |
|---|---|---|
| 书目状态与锁记录 | 书目、资源、场次 | 活动锁转为资源记录；续读点保留 |
| 成员花名册 | 成员与角色 | 只导入机器键与角色，不导入任何凭据 |
| 每日协作日志 | 运行记录（只读历史） | 历史日志只读，不参与新状态 |
| 个人记忆（memory） | 记忆条目（带版本） | 保留审核门槛 |
| 个人待办（todo） | 任务 | 未完成项转为待下发任务 |

**双写期**：2 周（建议值）。期间 Git 与系统都记录，每日生成一份差异报告。连续 10 个工作日差异为零或已全部解释后，才进入切换。

**切换**：切换窗口选在 02:00–06:00 禁读时段内，且当日无排班场次。切换后系统为真相源，Git 只接收导出，读书员不再直接写 Git。

**回滚**：切换前打一个 Git 快照标签作为回滚基准。回滚时先冻结系统写入，把系统状态导出为与旧格式一致的 JSON，恢复读书员对 Git 的读取。回滚时限为切换后 24 小时，超过后以系统为准。回滚后做一次对账，确认无丢失的场次和产出。

### 13.5 第一期量化指标

| 指标 | 定义 | 默认目标（见第 10 节“10.1 默认配置表”） |
|---|---|---|
| 任务耗时 | 从下发到开读的时间，取平均值 | 平均不超过 10 分钟 |
| 排班执行率 | 已登记或已开读的场次数除以排班场次数 | 不低于 90% |
| 漏跑率 | 漏跑场次数除以排班场次数 | 不超过 10% |
| 登录失效次数 | 每周登录态失效次数 | 每周不超过 1 次 |
| 人工介入次数 | 每场次需要人工处理的事件数（不含审批） | 每场次不超过 1 次 |
| AI 回退成功率 | 额度用尽或超时后，回退调用成功的比例 | 不低于 90%（默认值） |

## 14. 风险与约束

### 14.1 已发生事故与对应约束

| 事故 | 根因 | 系统中的约束（编号） |
|---|---|---|
| 某读书员未登记先读 | 开读靠自觉，没有许可机制 | 开读许可（M09）；未获许可的产出标记为无许可产出，不计入、不导出（AC-M09-1）；违规记录自动通知（M15） |
| 一次共享浏览器登录失效 | 登录态无人检查，失效后仍在开读 | 登录态检查与阻塞（M08）；超时未上报即视为未知并阻塞（AC-M08-2） |
| GitHub 连接器在子任务中未启用，提交停住 | 写入依赖会话连接器 | 读书员不写 Git，不依赖连接器（FR-ID-06）；导出由系统完成（M13） |
| 子任务直推 main 一次 | 子任务拥有直推权限 | 读书员无 Git 写权限；导出只经自动化 PR 合入（M13）；导出文件由系统生成，不允许手工修改 |
| 子任务把旧版草稿先合入 main（本次） | 合入以文件为准，不校验版本与审核 | 合入只接受当前版本号且已审核通过的对象（M12）；回写与审核均做版本校验（M09） |
| 排班空档由执行层没有可靠触发造成 | 触发依赖 Cue 定时任务与人工核对 | 系统自带调度器（M16）；排班核对 job（每小时）；心跳缺失检查；漏跑记录（M06）；空档由 A5 辅助识别 |

### 14.2 其他风险

| 风险 | 影响 | 应对 |
|---|---|---|
| SQLite 写并发与单机单点 | 写入等待、单机故障导致停机 | 单写者与条件更新；每日加密快照；迁移触发条件（7.6） |
| 书籍版权与隐私（整本内容发给外部模型） | 版权与隐私争议 | 书籍默认公开级别为“公开”（脱敏后可整本入公开仓库），可按书标记为“私密”；私密书不进 Git、不进公开页面；模型调用记录可审计；模型与提供方在配置中启用 |
| AI 幻觉与来源伪造 | 错误内容被当作事实 | 标签不漂移（P4）；金句与事实默认未核验；核验只能由人作出（5.6）；数字由系统计算（P2） |
| 提示词注入（书内文字含指令） | 模型输出试图触发系统动作 | 输入即数据（P5）；模型输出不能直接触发动作（5.4.6） |
| 模型版本变化或下线 | 调用失败或输出风格变化 | 模型顺序可配置；调用记录保存实际模型名；失败回退（5.4.5） |
| 额度与成本超支 | 额度用尽或费用超预期 | 额度记账与上限（每日默认 20 次，见第 10 节“10.1 默认配置表”）；额度用尽当日不再选用 |
| 凭据泄露 | 账号被滥用 | 只存引用；脱敏扫描；导出与日志不含凭据（AC-P1-10） |
| 浏览器页面改版 | 登录态检查与入口失效 | 检查失败即阻塞并通知人工；书内入口不可用时不替代为外部模型 |
| 迁移期数据不一致 | 历史与新系统记录不一致 | 双写期差异报告；切换窗口与回滚方案（13.4） |
| 团队沿用群聊习惯 | 系统未被实际使用 | 日报与通知作为入口；试运行一本书后才正式下发（M21） |

### 14.3 约束

技术约束：Python 实现；SQLite 单文件；单台云主机；读书员不依赖 GitHub 连接器。合规约束：书籍版权与隐私，私密内容不进入 Git。时间约束：禁读时段 02:00–06:00 不生成或登记场次，切换与备份均安排在该时段。角色约束：用户是唯一最终决策人；管理员不阅读书籍正文，不替代读书员阅读。

## 附录 A 术语表

| 术语 | 含义 |
|---|---|
| 场次 | 一个排班槽位在某时段的一次实际读书运行 |
| 槽位 | 排班模板中的一个时段定义，包含角色、资源、开始时间与时长 |
| 禁读时段 | 02:00–06:00（UTC+8），禁止登记与生成场次 |
| 开读许可 | 系统在登记检查全部通过后签发的许可，未获许可的场次不得开读 |
| 资源锁 | 对共享浏览器、本地 PDF 等资源的占用记录，获取须条件更新 |
| 围栏令牌 | 每次获取资源锁时发放的递增令牌，释放时必须携带 |
| 无许可产出 | 未获开读许可的场次所产生的内容，不计入统计，不进入导出 |
| 漏跑 | 场次结束时仍未进入执行，不补跑 |
| 超时待裁定 | 场次超过最长时长，锁保持占用，等待用户裁定 |
| 亲读 | 读书员实际阅读后形成的结论，由人亲自写入 |
| AI 问答 | 读书员提问、模型回答的内容 |
| AI 解读 | 模型基于原文或全书材料做的归纳、概括与读后感草稿 |
| 推断 | 基于上下文的推测，不直接来自原文 |
| 未核验 / 已核验 / 不收录 | 金句与事实的核验状态；默认为未核验；不收录的内容不进入公开层 |
| AI 调用代理 | 系统中代为调用第三方模型的组件，读书员不接触密钥值 |
| 提示词模板版本 | 系统中版本化的提示词，调用记录引用其编号与版本 |
| 私密层 | 原始 AI 回复、书籍原件等敏感材料的存储区，限权访问 |
| 公开产物 | 允许导出到 Git 与 Pages 的内容，经脱敏扫描且已合入 |
| 幂等键 | 写请求的唯一标识，重复提交不产生第二次副作用 |
| 版本号 | 可变对象的乐观锁版本，回写时必须携带 |
| 续读点 | 书目的当前阅读位置（章节或页码） |
| 机器键 | Agent 的稳定标识，不对外展示 |
| job | 系统后台定时或手动触发的任务单元 |
