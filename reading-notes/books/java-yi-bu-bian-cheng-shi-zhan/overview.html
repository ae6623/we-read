这本书在讲什么

本书涵盖了Java中常见的异步编程场景，包括单JVM内的异步编程、跨主机通过网络通信的远程过程调用的异步调用与异步处理，以及Web请求的异步处理等。本书在讲解Java中每种异步编程技术时都附有案例，以理论与实践相结合的方式，帮助读者更好地掌握相关内容。书中在讲解每种异步编程技术时多会对其实现原理进行讲解，让读者知其然也知其所以然。对于最近比较热门的反应式编程以及WebFlux的使用与原理解析，本书也有一定的深入探索。

高维追问 · LLM 补题（追加，原有问答保留）

一个接口 P99 突然从 50ms 涨到 800ms，但 CPU 只有 20%，怎么查？

先看线程状态分布：如果大量线程处于 WAITING/TIMED_WAITING 且堆栈停在网络调用上，就是下游变慢导致的线程耗尽；如果队列长度在涨而活跃线程数已到上限，就是池子不够或下游超时设置过长。CPU 低恰恰是「在等」的强信号，不要被它误导去优化计算。

异步代码最难测的是什么？怎么补？

最难测的是时序相关的问题：竞态、超时、取消、异常传播路径。补的办法不是写更多断言，而是把时间变成可控的依赖——注入调度器、用可控时钟、把超时参数外置。可测性差的根因往往是「时间被写死在代码里」，而不是「异步本身难测」。
