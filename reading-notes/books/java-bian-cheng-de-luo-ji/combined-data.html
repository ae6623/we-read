3.1 类的基本概念

  • static表示类方法，也叫静态方法，与类方法相对的是实例方法。实例方法没有static修饰符，必须通过实例或者对象调用，而类方法可以直接通过类名进行调用，不需要创建实例。
  • 类变量和实例变量都叫成员变量，也就是类的成员，类变量也叫静态变量或静态成员变量。类方法和实例方法都叫成员方法，也都是类的成员，类方法也叫静态方法。
  • 每个对象除了保存实例变量的值外，可以理解为还保存着对应类型即类的地址，这样，通过对象能知道它的类，访问到类的变量和方法代码。
  • 实例变量不能有static修饰符。
  • 实例方法可以理解为一个静态方法，只是多了一个参数this。通过对象调用方法，可以理解为就是调用这个静态方法，并将对象作为参数传给this。

4.3 继承实现的基本原理

  • 寻找要执行的实例方法的时候，是从对象的实际类型信息开始查找的，找不到的时候，再查找父类类型信息。
  • 对变量的访问是静态绑定的
  • 在Java中，类是动态加载的，当第一次使用这个类的时候才会加载，加载一个类时，会查看其父类是否已加载，如果没有，则会加载其父类。
  • 动态绑定，而动态绑定实现的机制就是根据对象的实际类型查找要执行的方法，子类型中找不到的时候再查找父类
  • 注意，类初始化代码，是先执行父类的，再执行子类的。不过，父类执行时，子类静态变量的值也是有的，是默认值。
  • 如果继承的层次比较深，要调用的方法位于比较上层的父类，则调用的效率是比较低的，因为每次调用都要进行很多次查找。大多数系统使用一种称为虚方法表的方法来优化调用的效率。
  • 栈存放函数的局部变量，而堆存放动态分配的对象，还有一个内存区，存放类的信息，这个区在Java中称为方法区。
  • 所谓虚方法表，就是在类加载的时候为每个类创建一个表，记录该类的对象所有动态绑定的方法（包括父类的方法）及其地址，但一个方法只有一条记录，子类重写了父类方法后只会保留子类的。

15.2 理解synchronized

  • 多个线程是可以同时执行同一个synchronized实例方法的，只要它们访问的对象是不同的即可
  • synchronized除了保证原子操作外，它还有一个重要的作用，就是保证内存可见性，在释放锁时，所有写入都会写回内存，而获得锁后，都会从内存中读最新数据。
  • synchronized保护的是对象而非代码，只要访问的是同一个对象的synchronized方法，即使是不同的代码，也会被同步顺序访问
  • 一般在保护变量时，需要在所有访问该变量的方法上加上synchronized。
  • 加了volatile之后，Java会在操作对应变量时插入特殊的指令，保证读写到内存最新值，而非缓存的值。
  • synchronized静态方法和synchronized实例方法保护的是不同的对象，不同的两个线程，可以一个执行synchronized静态方法，另一个执行synchronized实例方法。
  • synchronized有一个重要的特征，它是可重入的，也就是说，对同一个执行线程，它在获得了锁之后，在调用其他需要同样锁的代码时，可以直接调用。
  • synchronized实例方法实际保护的是同一个对象的方法调用，确保同时只能有一个线程执行
  • 应该尽量避免在持有一个锁的同时去申请另一个锁，如果确实需要多个锁，所有代码都应该按照相同的顺序去申请锁
  • 每个对象都有一个锁和一个等待队列，类对象也不例外。
  • 共享内存有两个重要问题，一个是竞态条件，另一个是内存可见性
  • 使用synchronized或者其他锁，要注意死锁。所谓死锁就是类似这种现象，比如，有a、b两个线程，a持有锁A，在等待锁B，而b持有锁B，在等待锁A, a和b陷入了互相等待，最后谁都执行不下去

核心追问（来自深读）

这本书的定位和写法有什么特别？

从提要看，作者写书动机很朴素：自己当年啃教程十几遍、上机调试才体会到数据结构的美妙，想把这份『清晰易懂』传给别人。所以它不是 API 手册，而是『从为什么到是什么』的思维书。开篇即用『世界万物由元素周期表基本元素组成，基本数据类型就像基本元素、对象就像万物』[576]这种比喻，把抽象的编程概念锚定到日常直觉，全程贯穿『用理解替代记忆』的初衷。

从划线看，作者对『变量与赋值』最想纠正什么误区？

他反复抠『名字』与『盒子』的区别。『变量就是给数据起名字，方便找不同数据，值可以变但含义不应变』[324]；进一步，『给数组变量赋值和给元素赋值是两回事——变量赋值让它指向别处，元素赋值改内容』[264]。这些被读者高频标记，正因为初学者常把『变量=容器』想死，结果在数组传递、引用赋值上栽跟头。作者要建立的，是一个稳定不变的『引用/值』心智模型。

为什么『函数调用原理』和『递归』被重点标记？

因为这两处是『程序如何跑起来』的命门。划线记了：『递归每调用一次就入栈，生成一份不同的参数、局部变量和返回地址』[240]，把黑盒式的『函数自己调自己』还原成栈帧的具象动作；而『数组作参数会在函数内改到调用者的数组』[255]则点出引用语义的隐蔽副作用。读者标它们，是因为一旦真懂了栈与引用，无数『为什么结果不对』的 bug 就豁然开朗——这正是本书『讲逻辑而非讲语法』的回报。

AI 问书

以下问答依据本书全书提要、章节结构与热门划线原文整理，不虚构页码；标「推断」处为整理者补注。

这本书到底在讲什么？

讲『编程背后的逻辑』，而不是某版 Java 的语法清单。它从二进制、数据类型、赋值、条件循环、函数，一路讲到类、继承、多态，但每一处都先回答『为什么这样设计』。比如用『元素—万物』比喻类型与对象[576]，用『时间片切换』解释进程并发[208]。它适合刚入门、背得下代码却说不清原理的人——把『会写』升级成『真懂』。

为什么作者花力气区分『==』和数组/对象比较？

因为这是对初学者最隐蔽的陷阱之一。书里点明：数组的 == 判断的是『两个变量指向是不是同一个数组』，而非『内容一不一样』[510]；同理『给数组变量赋值』是改指向、『给元素赋值』是改内容[264]。把这些讲透，是为了建立『引用语义』这个底层模型——很多 bug 与误解，根子都在以为变量存的是值、其实存的是地址。作者用最直白的对比拆掉这个地雷。

这本书对『自学编程』的人有什么特别价值？

价值在『替你踩过坑再讲给你听』。作者自己就是反复上机、调试、读教程十几遍才懂的，所以他把那些『教程不会明说、但一错就卡死』的点（短路求值[289]、重载按参数类型匹配[198]、父类转子类看动态类型[196]）一一拎出来。它像一位有耐心的学长，不在你面前堆术语，而是把你卡住的地方，用生活比喻和栈帧图慢慢捋顺。

用更高维度的知识看这本书

本书属于『概念驱动型』编程入门，与《Head First Java》的图解风、《Java 编程思想》的厚重体系并列中文自学者常走的三条路。它的特色是『用类比降低认知负荷』——元素周期表、时间片、名字与盒子，都是把计算机概念翻译回生活经验，契合认知负荷理论里『用熟悉 schema 锚定新知识』的原则。

局限在深度与时新：它重在夯实基础逻辑，对并发、JVM 内存模型、现代 Java（lambda、模块化）着墨有限，且比喻用多了偶尔会『漏细节』（如 == 对 Integer 缓存区的特殊行为）。作为入门与『原理补丁』极好，但要成为能打的工程司，仍需接《深入理解 Java 虚拟机》等进阶书。把它定位为『地基』而非『全部』最准。

阅读时要验证的问题

  • 书中比喻（如基本类型=元素、对象=万物）[576]为教学类比，意在降低门槛，引用作严谨定义时须补正式类型论表述，避免以喻代定义。
  • 『数字常量默认 int，加 L/l』[272]、『数组 == 比较引用』[510]等基于特定 Java 版本语义，跨语言或新版特性（如 Integer 缓存）有边界情形，引用宜加版本说明。
  • 划线样本集中在前几章（数据类型、赋值、函数），不能代表全书面向对象与继承部分，引用须注明章节。
  • 作者自述『反复读教程上机才懂』为个人学习经历，作普适学习方法建议时宜说明个体差异，不宜当唯一路径。

当年与今天 · 初步对照

本书写作于 Java 仍是企业主力、培训班泛滥的年代，彼时『背语法找工作』盛行；今天 AI 能秒写代码，『会不会写』的稀缺性下降，『懂不懂为什么』反而更值钱。这本书当年强调的『逻辑而非语法』，恰好是 AI 时代人类程序员最该守住的部分——你不必记得每个 API，但得判断 AI 给的代码为什么对、哪里会炸。

可迁移的启发是『建立心智模型胜过背结论』。作者用元素周期表、栈帧、时间片这些锚点，帮你把飘着的语法钉进脑子；今天面对任何新语言或框架，最该带走的正是这套学法：先问『它背后的模型是什么』，再动手。代码会过时，但『从原理到现象』的思考方式，是 AI 替不了你的硬资产。
