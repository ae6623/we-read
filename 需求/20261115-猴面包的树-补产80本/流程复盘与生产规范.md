## 2. 根因（5 条；前 4 条是事故①，第 5 条是事故②——两次同源）

1. **模板与真相源脱节**：真相源 `reader-js.json` 的 note 已写明升级链路（改 json + 引擎仓 `overview_gen/combine_page.py` 的 `READER_JS` 常量 + 跑 `scripts/upgrade_reader_js.py` 全量切换），但 `we-read` 仓 `tools/fill_combined_modules.py` 的 `READER_TPL` 是**另一套没人维护的模板**，不在升级链路里，11-06 后从未更新。
2. **本地生产/提交环节没有守卫**：云端有 `Verify reader JS version across all book shells`，本地没有。`produce_qingyouji.py` 自检只查 `data-key ≥9` + 文件存在；80/80 验收只查十模块、内容、兜底、死链、HTML 错配 —— **全程没有一道资源引用校验**，旧模板一路绿灯进 main。
3. **「与现有 N 本一致」验收口径缺项**：只比了模块结构与内容，没比 `<script src>` / `<link href>` / 头部标注，等于把「形态一致」偷换成了「模块一致」。
4. **旧工作副本未对齐**：本地副本是 11-05 基线，连真相源文件都没有；`push_snapshot.py` 只以服务端 tree 为基线覆盖清单文件，**不会把本地工具同步到最新**，所以「拉了 main 也没用」——问题在生成器本身，不在 pull 动作。
5. **【事故②·封面】形态基线整批漏项**：`/tmp/qingyouji_manifest.json` 里 **80/80 本都有官方 `cover` URL**（微信读书 `cdn.weread.qq.com/.../s_*.jpg`，换 `t9_` 即 428×616 高清，与原有 30 本同规格），仓库里也早有 `fetch_covers.py` / `refetch_covers.py` / `fix/covers.py` 现成下载脚本；但 `produce_qingyouji.py` **从未读 `cover` 字段、从未产出 `assets/covers/<slug>.jpg`**，推送清单 577 文件里也没有一张图。书卡 `home-card.js:165` 按 slug 找 `assets/covers/<slug>.jpg`，404 就静默退回渐变素封（`card-cover-title` + `WE READ`），详情页 `reader.js hasCover()` 同理降级。**不报错、不进任何验收项，所以 80/80 全绿却整批没封面。** 上一次 PROCESS-FIX 写的「形态基线」列了 script/link/十模块/导航/chips/标注，**唯独没列封面文件**，同一个坑没堵住就复发了。

> **两次事故的共同根**：把「与现有 N 本一致」当成口号，没有落成**逐文件可校验的形态清单**。第 5 节闸门现在把「封面文件存在且有效 JPEG」也列为硬失败项。

## 3. 系列书正确生产 SOP（逐条，禁止跳步）

### 3.0 开工前（强制，缺一不可）

```bash
cd <REPO>
# 1) 取权威 main（不要写死 commit，main 被多流水线高频推送）
git ls-remote origin refs/heads/main

# 2) 同步代码与数据：至少这三样必须与 main 一致
#    assets/data/reader-js.json、tools/、系列内 1 本已发布书页
#    缺 reader-js.json = 副本落后，禁止开工（生成器现在会直接报错）

# 3) 读真相源，记下 expected URL
python3 -c "import sys;sys.path.insert(0,'tools');import fill_combined_modules as F;print(F.reader_js_url())"
#    期望：https://cdn.js-dev.cn/assets/js/reader-20261118.js

# 4) 取样现有书页 + 现有封面，建立「形态基线」——必须逐文件比对，不能只看模块
#    <script src> 的 reader JS URL / <link rel=stylesheet> 版本
#    10 个 data-key / 导航锚点 / 头部 chips / AI 标注文字
#    assets/covers/<现有书slug>.jpg 存在、有效 JPEG、尺寸（本次 428×616）
#    单本目录文件集合（本次既有形态为 4 文件：combined-data/combined/outline.html/outline.json）
```

> **红线**：不许从本地旧模板、旧书页、记忆里的 HTML 片段复制壳页。壳页只能由生成器按真相源产出。
> **红线**：封面是形态基线的一等公民，不是可选项。拉书单时 `cover` 字段必须随 `bookId/title` 一起进 manifest；生产命令必须传 `--cover`（或 manifest 自带 `cover`）。

### 3.1 官方 AI 大纲

用微信读书网关 `fetch_outline_api.py` 拉 `/book/chapterinfo` + `/web/book/outline`，缓存到运行时目录；**没有官方大纲的书降级不编造**（本次 `3300238669` 即如此）。

### 3.2 精写 6 内容模块

`drafts/<slug>-llm.json`（aiask / coreask / higher / verify / thennow / quiz）。**禁止 `gen_auto_llm` 兜底套话**，禁止「Agent 兜底生成」标注，用中性标注「基于本书 AI 大纲自主整理 · 未亲读原书」。

### 3.3 组装 10 模块

`F.assemble(slug, struct=True, llm_data=ld, auto_llm=False)` → `combined-data.html`。

### 3.4 生成壳页（唯一允许的路径）

```bash
# produce_qingyouji.py 内部调用 F.gen_reader_page(slug) 生成壳页，
# 并按 --cover / manifest 的 cover 字段把官方封面落盘到 assets/covers/<slug>.jpg
python3 tools/produce_qingyouji.py --slug <slug> --book-id <bookId> --title "<书名>" \
  --llm drafts/<slug>-llm.json --cover "<官方cover URL>" --no-hero
```

`gen_reader_page()` 现在从 `reader_js_url()` 取 URL 填入 `READER_TPL.format(...)`。**任何新增能产 `combined.html` 的入口都必须调用同一函数并登记到第 5 节清单。**
封面下载复用 `check_covers.fetch_cover()`（`s_`→`t9_` 高清、失败降级、`>3KB` 且 `\xff\xd8` 校验）；仓库已有的 `fetch_covers.py` / `refetch_covers.py` 是同一思路，不重复造轮子。

### 3.5 单本自检（含硬闸门）

`produce_qingyouji.produce()` 已加两道硬断言：
- `reader_js_ok`：壳页必须包含 `src="<expected URL>"`，否则 `ok=False`
- `cover_ok`：`assets/covers/<slug>.jpg` 必须是有效 JPEG（`>3KB` + `\xff\xd8`），否则 `ok=False`

检查返回字典：`ok / n_keys / reader / reader_js_ok / reader_js_url / cover_ok / cover / llm` 全绿才算通过。

### 3.6 登记

`_data/books/<slug>.json`、`assets/data/hero.json`、首页 `index.html`、系列页 `reading-notes/series/<series>/index.html`。
首页/系列页的**计数与说明文案要一起改**（本次只改了徽标 103 册、漏了 intro「23 册」，已补 `d3b1ecbf`）。

### 3.7 提交前全站守卫（**两道都要退出码 0 才允许推 main**）

```bash
python3 tools/check_reader_js.py --files <推送清单>   # 资源引用；非 0 直接停
python3 tools/check_covers.py   --files <推送清单>   # 封面文件；非 0 直接停
# 资源引用不一致：python3 tools/check_reader_js.py --fix（按真相源换 key，不覆盖 CDN 同名文件）
# 缺封面：        python3 tools/check_covers.py --files <清单> --fix --manifest <书单>
# 推送清单必须同时含 assets/covers/<slug>.jpg，否则图不会进 commit（push_snapshot 只推清单文件）
```

> 封面 jpg 是二进制，`push_snapshot.py` 走 `git hash-object -w` 可直接入 tree；但**推送清单必须显式列出每一张图**，否则静默不进 main——本次 577 文件清单就是漏了这 80 行。

### 3.8 推送与发布验收

```bash
python3 tools/push_snapshot.py --files <推送清单> --message "..." --main --rounds 25
```

推送后由云端发布链路同步到 `reader.js-dev.cn`；发布后按第 7 节 6 条 curl 逐项验收，**全过才可回 DONE**。

## 5. 防再犯硬闸门（逐条可检查）

1. **单一真源**：任何生成器不得硬编码 reader JS URL / 相对路径 / `?v=`；只准 `reader_js_url()`。新增生成器必须登记进「能产 `combined.html` 的入口清单」，升级 JS 时逐一核。
2. **双闸门 × 双形态**：生成时单本硬断言（`reader_js_ok` **和** `cover_ok`）+ 提交前两道全站守卫（`check_reader_js.py` **和** `check_covers.py` 退出码均为 0）。**任一不通过禁止 `push_snapshot --main`**。
3. **验收口径固化**：「与现有 N 本一致」必须逐项比对 `<script src>`、`<link href>`、十模块 `data-key`、导航锚点、头部 chips、标注文字、**`assets/covers/<slug>.jpg` 存在且有效**、**单本目录文件集合**，并记录比对结果；禁止只比模块结构。
4. **旧副本硬失败**：本地缺 `assets/data/reader-js.json` 或版本落后时，生成器直接报错，逼迫开工前对齐最新 main，而不是静默用旧模板。
5. **双仓一致性**：引擎仓 `combine_page.py` 的 `READER_JS` 常量必须与 `reader-js.json` 的 `current` 一致；每次 JS 升级跑 `upgrade_reader_js.py` 全量切换，禁止只改一处。
6. **发布守卫前置**：GitHub Actions 的 `Verify reader JS version` 失败即阻断上线；发布后必须按第 7 节逐条 curl，不能只凭「部署成功」判定。
7. **封面清单显式化**：推送清单里每一本新书都要有一行 `assets/covers/<slug>.jpg`；`check_covers.py --files <清单>` 是唯一放行依据。**「不报错」不等于「有封面」**——封面 404 是静默降级，必须靠守卫显式查。
8. **需求文档必填字段**：`模板版本 / 资源引用基线 / 封面来源与规格 / 两道守卫通过结果 / 发布验收结果`，缺一项不算交付。

### 10.2 slug 命名（补 3.4）

`pypinyin` 本机有 PEP 668 / 解释器兼容问题，别卡在装包上。slug 按主题手工定，格式 `xh-<主题>-qingyouji`（如 `xh-ba-li-qingyouji`），保证唯一、可读、与封面文件名一致。

### 10.3 推送：SSH 不通走 Git Data API 单 commit（补 3.8）

`push_snapshot.py` 依赖 git SSH，云端 SSH 常不通。备用方案（辛恒批次 64 文件一次入库已验证）：

1. `GET /git/ref/heads/main` → `GET /git/commits/<head>` 取 base tree
2. jpg 用 base64 blob、其余用 utf-8 blob：`POST /git/blobs`
3. `POST /git/trees`（base_tree + entries）→ `POST /git/commits`（parents=[head]）
4. `PATCH /git/refs/heads/main`（force=false），409/422 则重取 head 重试（≤3 次）

> token 从 `.wr-auth/git-credentials` 提取，正则用 `https://[^:]+:([^@]+)@`——**别用 `https:` 宽匹配，会把协议头当用户名**。

### 10.4 Pages 并发 cancel（补 8）

3 分钟内连续 push 会触发 GitHub Actions 并发组 cancel 前一次部署，出现「明明推了却没上线」。**推完等 Actions run 到 completed 再按第 7 节验收**，不要连推。
