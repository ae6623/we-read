# 导图重做 · 执行卡（给执行 agent 的规则，勿改）

仓库 `/tmp/we-read`。任务：把分配到的书在 `data/mm-graph/<slug>.json` 里的旧导图数据，重写成**按本书论证维度归纳的知识骨架**。

## 输入

- 素材卡：`需求/20261105-导图全量重做-379本/批次-NN-1.md` 或 `-2.md`，每节形如 `## 3. slug ｜《书名》`，下面列出该书全部章节的「序号. 章名 | 要点」，节首标了**「素材 N 字 → 应做 X-Y 支（建议 M）」**。
- 需要更多上下文可看 `data/mindmap-material/<slug>.txt`，但素材卡已含全部要点，通常不用再开。
- 格式与语感参照：`data/mm-graph/1984.json`（文学）、`data/mm-graph/kubernetes-quan-wei-zhi-nan.json`（技术）、`data/mm-graph/spain-qingyouji.json`（薄素材游记）。

## 铁律：忠实素材

**只依据素材归纳，不引入书外知识、不补背景、不编造情节、不做现实引申**。素材没有的判断，宁可少写一个概念，也不要"想当然"补上。历史/政治类书只复述素材里的学术要点，不加评论。

## 硬规则（`tools/verify_mm_graph.py` 逐条检查，不合格要重写）

| 字段 | 规则 |
|---|---|
| `thesis` | 全书一条中心命题，≤40 字，完整句，以 `。！？；…` 结尾 |
| `branches` 数 | 按素材卡的「建议 M 支」写，不能少于区间下限 |
| `label` | ≤10 字，必须是**论证维度**（如「背压的三种策略」「制度如何抹去个体」）；严禁章节名（第X章/序言/前言/后记/引言/附录）和空话（核心观点/主要内容/全书概览） |
| `points` | 每支 3-5 个，每个 ≤12 字，写**论点/机制/结论**，不写人名、地名、物品名、角色名 |
| `note` | ≤45 字，说清这条线在论证什么 |
| `rel` | `因果/并列/递进/包含/对比` 之一，拿不准留空字符串 |
| `id` | A、B、C… 顺序 |
| `source` / `title` | 固定 `"llm"` / 书名 |

## 依据只写条目号（别抄原文）

```json
"evidence_ref": {
  "背压的三种策略": [4, 12],
  "Flux与Mono的分工": [9]
}
```

- key 必须和某个 `points` 的概念**一字不差**
- value 是 1-3 个**素材卡每行开头**的条目号（`3. 1.1 xxx` 取 `3`）
- **不要用行内的章节号**：短篇集/游记的章节号会 1、2、3 循环重复，引错会张冠李戴
- 每个概念都要有 ref；选要点最贴这个概念的那 1-3 行
- 素材确实没有可引用条目（如「共 0 章」的轻游记）时，才手写 `evidence`，每条 ≤40 字且必须是素材原文连续片段

`tools/expand_evidence.py` 会把条目号展开成原句（自动截 40 字内）并删除 `evidence_ref`。

## 自检（必须做，全部 0 问题才算完）

```bash
cd /tmp/we-read
python3 tools/expand_evidence.py --batch <本组4个slug，逗号分隔>
python3 tools/verify_mm_graph.py --batch <同上>
```

报错就改自己的 json 重跑。**不许改校验器、不许放宽标准、不许改别人的文件**。

## 边界

- 只写分配到的 `data/mm-graph/<slug>.json`
- 不渲染页面、不 git add/commit/push、不动其它书
- 回报：每本 slug、分支数、概念数、素材是否过薄

## 参考坑

- slug 以 `-` 开头（如 `-yao-yuan-...`）不能当位置参数，用 `--slug=-yao...`
- 一本 3-5 个概念/支是硬下限，别为了省事全写 3 个
- 分支 label 不许两本书用同一套词，每本必须来自本书素材的论证主线
