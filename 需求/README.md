# 需求记录

本目录存放每个需求的**过程记录**：为什么做、做什么、怎么做、验收标准、最终结果。
目的是让需求可交接——换一个 agent、隔一个月回来，只看这个目录就能接着干。

## 目录规范

```
需求/
└── YYYYMMDD-需求名/
    ├── README.md      # 必填：背景 / 目标 / 范围 / 流程 / 要求 / 验收 / 结果
    └── 待办清单.tsv    # 选填：批量任务的分项清单
```

- 需求名要精简到 12 字以内，能一眼看出做什么。
- 「结果」节不写计划，只写已发生的事实（完成数、提交号、遗留项）；每完成一批回填一次。
- 涉及批量生产的需求，必须把**验收命令**写进 README，不能只写"人工检查"。
