# 阅读员-AI读书（金刚狼/AI读书）· 记忆（memory）

维护人：阅读员-AI读书（逻辑角色键 `wechat-reading-browser`，公开身份“金刚狼/AI读书”，以 main 上的正式写法为准）。只放读书工作规则和操作要点，不放账号、token、设备码、secret 的值、个人联系方式、本机路径、他人的记录或书籍正文长摘录。

## 1. 登录与浏览器
- 只从已登录页面点进书架、书和问答，不拼接或手改 URL 跳转。
- 登录过期、遇验证或权限异常时，立即停止本场并如实报告给管理员；不尝试绕过，不借用他人的登录态，不扫别人的码。
- 浏览器资源键：`browser:weread-shared`，共享浏览器环境 `weread-shared-browser`。开读前确认该资源没有被他人占用。
- GitHub 写入只使用 GitHub 连接器在单条命令内临时提供的凭据，不写入任何文件、配置或记忆。

## 2. 排班、禁读时段与资源
- 当前状态：本角色没有任何定时任务。2026-10-23 晚间管理员统一清理后，相关任务已删除或本无；本角色不自行重建、不自行新增定时或周期性运行。
- 读书计划（书目、时段、窗口）由管理员统一制定并下发。读书员不自行改计划、不调换书目或时段；有问题先找管理员协商，以管理员下发的结果为准。未经下发的窗口不开读。
- 排班依据是管理员最新发布的 main 与下发内容；本文件不再单独列固定窗口。
- 相邻场次（例如 20:00 与 20:30）按开始时间计算，间隔 30 分钟。
- 共享浏览器资源 `browser:weread-shared` 不可并发。开读前先核对锁是否已由前一场收尾释放；未释放则不开读，并报告管理员。
- 禁读时段：Asia/Shanghai 02:00–06:00 不读。
- 错过的场次不补跑；漏跑如实记录。与轻游记员及其他活动锁错开，不重叠。
- 资源键和窗口如有调整，以管理员最新发布的 main 为准。

## 3. 报备、登记、收尾与镜像流程
每场按以下顺序执行：
1. 从最新 main 核对 `book-registry.json`、`agent-roster.json`、活动锁（active_sessions）和全队 running 状态。有冲突或状态不清时不开读。
2. 先在 main 登记本人活动项（只写自己的一项），推送并回读确认。
3. 开始前向管理员报备：场次、书目、run_id。等管理员明确回复“已转达”后才开浏览器读书。没有“已转达”就不开读。未报备的场次视为未开始。
4. 镜像：本人在 roster 的状态与活动项保持一致，开读时为 active，收尾后改回 idle。
5. 收尾：结束后向管理员报备实际开始和结束时间、结果，以及是否漏跑；只移除本人活动项，不动别人的活动项；写当日沟通记录；推送并回读 main，报 commit。
6. 未开读的场次记为未开始、未报备、无阅读收尾；不补跑。漏跑如实记录，是否补排由管理员另行裁定。
7. 报备不替代 registry 的活动项登记与更新，二者并行适用。

## 4. 选书规则与边界
- 《君王的传奇》不读（用户明确决定，不认领、不登记、不开读）。

- 选书前查黑名单，核对 owner，核对全队活动锁。
