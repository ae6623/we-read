# 阅读员-Windows读书 · 记忆（memory）

维护人：阅读员-Windows读书（local-pdf-reader）。只放读书规则与操作要点，不放账号、密钥、个人联系方式或本机路径。

## 边界与权限
- 只读本人云端副本（Sandbox 中的私密交接文件）。不读用户本机原件，不把本机路径或文件清单写进仓库。
- 用户要求：自己选书、自己排班、在云端推进；每场先登记再开读，不占浏览器，不与他人的书或共用资源冲突。
- 不改他人的 registry、roster、待办或记录。

## 选书规则
- 轮换顺序：第 3 类（社会与人生观察）→ 第 2 类（房地产、金融与投资）→ 第 5 类（案件、灵异、民俗、猎奇，后排）→ 第 6 类（小说、江湖与传统文化）。每轮各选一本，轮完回到第 3 类。
- 第 1、4 类暂不读。职业相关永久不读。
- 已跳过：#129（用户指定跳过）。已读完或已有他人认领的不重复选。
- 选书前查黑名单、核 owner、核全队活动锁。

## 登记与收尾
- 开始：从最新 main 读 registry、roster、当日记录；在 registry 的 active_sessions 加本人一项（reading_mode local_pdf，资源 local_pdf:xpdf-reader，environment_id sandbox-local-pdf-reader）；roster 改 active；推送并回读后才开读。
- 收尾：移除本人活动项（只移除自己的），roster 改 idle，填实际收尾时间，写当日记录，推送并回读，报 commit。
- 未完读不改 owner，不写完读；续读点写清亲读范围和未读范围。

## Gemini 辅助
- 先用 gemini-3.8-flash（请求超时至少 150 秒）；额度用完（429）或连续出错超过 3 次，换 gemini-3-flash-preview；两个都不可用就跳过，人工读。
- 整本或片段交给 Gemini 已在 main 9212ae9 允许。密钥只用已保存引用，不写入文件、不回显。
- Gemini 输出只作辅助，必须人工核对。它声称的“逐页检视”不采信。金句必须能在本人亲读页面逐字核对，否则不写。
- 笔记标注“自主整理（非AI问答）”和“Gemini 辅助”，不写通读、完读、AI 问答。

## 2026-10-24 交接：文字提取与工具试用
- 文字型 PDF 先用 pdftotext 抽取（约 0.1 秒/整本，只给内部处理用）。它只有纯文字，没有标题和结构。
- pymupdf4llm（PyPI 上 2.0 为空壳，代码在 pymupdf 2.x 内）：不需要 GPU 和 key，文字型 PDF 可用 use_ocr=False 出带结构的文本，约 0.3–1.2 秒/页；扫描件无文字层，需要 OCR，不可用。许可证为 AGPL 或商业双许可，正式公开使用前要先确认。
- pdf-craft：每种转换都要经过 OCR（远程服务要地址和 key，本地要 CUDA），本机无 GPU，暂不用。
- skill-focus 只借鉴笔记结构；它的流程要求嵌入原文引用，与不复制原文的规则冲突，不照搬。
- 目前推荐路线：文字型书用 pymupdf4llm 或 pdftotext 出内部文本，再分段交 Gemini 按精读提示词处理（提示词要求：复述论证链、列隐含假设、指出最薄弱环节、点明与主流观点冲突；引用只用短句并标位置），结果人工逐条核对。
